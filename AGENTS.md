# AGENTS.md — инструкция для ИИ-агентов (Codex, Claude Code и др.)

Этот файл — точка входа для любого агента, который продолжает работу над репозиторием. Прочитайте его целиком, затем `docs/dev/status.md` (текущее состояние и ближайшие задачи).

## 1. Что это за проект

**Patriarch** — одиночная стратегия-симулятор династии в России начала XVIII века (старт **1703**, юлианский календарь). Игрок ведёт род: браки и наследники, двор и должности, интриги, владения и экономика, вера и Церковь, армии, борьба за престол и гражданская война. Пётр I — ИИ-император. Роды реальные, люди вымышленные. Партия 30+ часов, карта — вся Россия (~400 провинций), **объёмный 3D-ландшафт в стиле Victoria 3**.

- Язык проекта: **C++20**, собственный движок, **Direct3D 11**, UI на **RmlUi**, окно на SDL3, Windows-first.
- Репозиторий **публичный**, лицензия «все права защищены» (`LICENSE`). Не коммитьте секреты, личные пути, локальные конфиги, `.claude/`.
- Работа ведётся **соло**, как хобби; документация и общение с владельцем — на **русском**, код, идентификаторы, комментарии и сообщения коммитов — на **английском**.

## 2. Как читать документацию (порядок)

1. `README.md` — карта документов.
2. `docs/dev/status.md` — **что готово, что дальше, известные проблемы** (обновляйте при каждой завершённой задаче).

4. `docs/adr/0001-stack.md`, `0002-performance.md`, `0003-3d-terrain-map.md` — архитектурные решения.
5. `docs/epics/README.md` и файлы `docs/epics/E0x-*.md` — задачи (ID `E{эпик}-T{номер}`), критерии приёмки, статусы.
6. `docs/gdd/01…08-*.md` — дизайн-документы систем (династия, престол/кризис, экономика, двор/интриги, религия, армия, дипломатия/ИИ, события/контент).

## 3. Структура репозитория

```
src/core/      общие утилиты без зависимостей от игры: Fixed32/64, PRNG, ID, SlotMap, SparseSet, Arena, лог, assert, Result, zstd
src/sim/       ядро симуляции (детерминированное, без графики/платформы): World, команды, цикл, сейвы, реплеи, календарь
tools/         simcli (headless-раннер), скрипты: format.ps1, check_assets.py, gen_tables.py
tests/         doctest (C++) + tests/tools (Python unittest)
assets/        ассеты + LICENSES.csv (реестр лицензий — обязателен)
docs/          вся документация
.github/       CI (GitHub Actions)
```
Будущие модули (пока не созданы): `data`, `rules`, `ai`, `engine`, `ui`, `game` — см. ADR-0001.

## 4. Сборка и проверки (Windows)

Нужны: MSVC (Visual Studio **2022** или Build Tools 2022), CMake ≥ 3.25, Git, Python 3, vcpkg.
**Важно:** на машине владельца Visual Studio 2026 стоит без C++-нагрузки, поэтому используется генератор `Visual Studio 17 2022` (Build Tools). Не переключайте на VS 2026 без причины.

```powershell
$env:VCPKG_ROOT = "C:\Users\<user>\vcpkg"            # клон https://github.com/microsoft/vcpkg
cmake --preset win-msvc                               # конфигурация + зависимости vcpkg
cmake --build --preset win-msvc-debug                 # или -release / -relwithdebinfo
ctest --preset win-msvc-debug                         # все тесты (включая simcli_determinism)
cmake --preset win-msvc-asan; cmake --build --preset win-msvc-asan-debug; ctest --preset win-msvc-asan-debug
powershell -File tools\format.ps1 -Check              # clang-format (в CI — версия 19.1.5)
python tools\check_assets.py                          # реестр лицензий ассетов
python tools\gen_tables.py --check                    # сгенерированные таблицы актуальны
.\out\win-msvc\tools\Debug\simcli.exe --verify-determinism --days 800 --seed 7
```

**Перед коммитом** должны быть зелёными: сборка без предупреждений (`/W4 /WX`), все тесты в Debug, Release (или RelWithDebInfo) и ASan, `format.ps1 -Check`. CI (`.github/workflows/ci.yml`) гоняет то же на `windows-2022` и Ubuntu.

## 5. Жёсткие правила (нарушение ломает проект)

1. **Детерминизм `sim`:** никакого `float/double` в состоянии и расчётах, влияющих на него; нет `unordered_*` в итерациях, нет `rand`/`random_device`, нет реального времени в логике, нет упорядочивания по адресам, нет потоков вне планировщика. Случайность — только `world.rng().stream("имя")`. Подробно: `docs/dev/code-style.md` §4.
2. **Граница слоёв:** `sim` не зависит от `engine`/`ui`/платформы. UI и ИИ читают **неизменяемый снапшот** и меняют мир **только командами** (`validate` → `apply` на границе тика).
3. **Состояние живёт в `World`.** Системы не хранят постоянное состояние вне мира (иначе сохранения и реплеи ломаются).
4. **Любое изменение логики симуляции/демо-сценария/форматов** меняет golden-значения в `tests/golden_test.cpp` — обновляйте их осознанно (инструкция в самом файле) и объясняйте в коммите. Незапланированное изменение хеша = баг.
5. **Форматы файлов версионированы** (`PCL1`, `PRP1`, `PSV1`, `World::kStateSchema`): меняя раскладку, поднимайте версию и добавляйте миграцию.
6. **Ассеты:** каждый файл в `assets/` обязан быть в `assets/LICENSES.csv` (проверяет CI). Запрещены лицензии NC/ND.
7. **Не вводите новые зависимости** без записи в ADR и `vcpkg.json` (с фиксацией версии через `builtin-baseline`).
8. Числа баланса в GDD помечены `[предл.]` — это предложения, не истина; исторические даты с `[проверить]` — сверять с источниками до использования в данных.

## 6. Стиль кода (кратко; полностью — `docs/dev/code-style.md`)

Типы `PascalCase`, функции и переменные `snake_case`, приватные поля `name_`, константы `kName`, макросы `PAT_UPPER`. Заголовки: `#include "pat/<модуль>/<файл>.hpp"`. Ошибки — `core::Result<T,E>` (исключения не используются для управления потоком), инварианты — `PAT_ASSERT` (только debug), проверки с побочным эффектом — `PAT_VERIFY`. Логи — `PAT_LOG_INFO("category", "text {}", x)`. Форматирование — `clang-format` (`.clang-format`), `tools\format.ps1`.

## 7. Подводные камни, уже встречавшиеся

- `windows-latest` и `windows-2025` в GitHub Actions теперь с **VS 2026** — наши пресеты требуют VS 2022, используем `windows-2022`.
- ASan на MSVC: рядом с каждым exe нужны runtime-DLL (`patriarch_copy_asan_runtime()` в CMake); без них exe падает с кодом `0xC0000135`.
- `/WX` + doctest: константные условия дают C4127 — используйте «непрозрачные» значения (см. `tests/assert_test.cpp`); для `std::string_view` в `CHECK` включён `DOCTEST_CONFIG_USE_STD_HEADERS`.
- `Simulation` перемещаемый, но **нельзя** перемещать, пока другой поток вызывает `submit()`.
- Месячный stagger — `id % 28` (дни 1–28), а не `% 30` (иначе двойная обработка в 31-дневных месяцах).
- Перед записью в `Write`/правками учитывайте, что `clang-format` переписывает файлы; после форматирования перечитывайте точный текст перед `Edit`.
- Git-репозиторий проекта — **эта папка** (`patriarch/`), а не домашняя директория пользователя. Коммиты делаются с адресом GitHub noreply (личная почта в публичной истории не публикуется): `git config user.email` уже настроен локально; не меняйте на личный.

## 8. Рабочий процесс

- Берите задачи из `docs/epics/` по порядку из `docs/epics/README.md` («сначала риск»). Каждая задача: код + тесты + обновление статуса в файле эпика + запись в `docs/dev/status.md`.
- Небольшие изменения — прямо в `main` после зелёной локальной проверки; крупные — отдельной веткой/PR. Сообщение коммита: `E1-T08: краткое описание` (английский), тело — что и почему; если это ИИ-агент, добавляйте строку соавторства по правилам своей среды.
- После push проверяйте CI (`gh run list`, `gh run watch <id>`); красный CI — первая задача.
- Если требование противоречит документам — **обновите документы** (ТЗ/ADR/эпики) в том же коммите и отметьте изменение в `docs/03-open-questions.md`. Так было с переходом на 3D-карту (ADR-0003).
- Решения владельца (например, «карта объёмная, как в Victoria 3») имеют приоритет над предложениями в документах.
