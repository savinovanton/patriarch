# ADR-0003: Объёмная 3D-карта-ландшафт (в стиле Victoria 3)

- Статус: **принято** для этапа P1 (подтверждено спайком E3, 2026-11-06; этапы P2–P6 — эпик E5)
- Дата: 2026-11-06
- Связано: ТЗ FR-MAP-1…9, FR-UI-1, NFR-GFX-1, NFR-PERF-1; ADR-0001 (D3D11, `IRenderer`), ADR-0002 (производительность); эпики E3, E5, E21, E26

## Контекст

Изначально карта планировалась 2D (политическая карта провинций, индексная текстура + палитра). **Владелец потребовал полноценный объёмный ландшафт в стиле Victoria 3.** Это означает рельеф с высотами, материалы поверхности, воду, растительность, освещение и свободную камеру с наклоном и зумом — при сохранении того, что игра остаётся стратегией с ~400 провинциями и тяжёлым UI.

Ключевые свойства карты Victoria 3, которые мы берём за ориентир:
- стилизованный (не фотореалистичный) рельеф, читаемый с дальнего расстояния; политическая раскраска провинций лежит поверх рельефа;
- режимы карты меняют раскраску без перестроения сцены;
- вблизи — леса, города, порты, армии как 3D-объекты; вдали — маркеры и подписи;
- камера «сверху с наклоном», плавный зум от обзора мира до уезда;
- вода (моря, реки, озёра), снег и сезоны, мягкое освещение и дымка.

## Решение

Рендер карты — **отдельная подсистема `engine/map`** за интерфейсом `IMapRenderer`; симуляция о ней ничего не знает (читает снапшоты, ADR-0001). Состоит из офлайн-конвейера данных и рантайм-рендера.

### 1. Данные (офлайн, `tools/mapgen`)

| Данные | Формат | Источник |
|---|---|---|
| Карта высот | 16-бит, например 8192×4096 (≈0.5–1 км/тексель) | Реальные DEM региона (SRTM / Copernicus / ETOPO — лицензии проверить), обработка и сглаживание в `mapgen` |
| Карта ID провинций | R16_UINT, то же разрешение | Рисуется/генерируется по границам провинций (E21); в спайке — процедурная |
| Карта материалов | индексы 8–12 классов (пашня, степь, лес, горы, тундра, болото, песок …) | Классификация по высоте/наклону/климату + ручная правка |
| Маска воды, глубины | R8/R16 | DEM + батиметрия + маска озёр |
| Реки | полилинии с порядком (шириной) | Natural Earth / HydroSHEDS (лицензии проверить) |
| Плотность растительности | R8 на тип | Из карты материалов + шум |
| Предрасчёт | нормали, затенение рельефа (ambient/horizon) | `mapgen` |

Проекция: равновеликая коническая (Albers/Lambert) вместо «плоской» широта/долгота, чтобы форма России не искажалась. Единицы мира — километры.

**Охват (решено): вся Россия до Тихого океана** — примерно от Прибалтики (~20° в. д.) до Камчатки и побережья Охотского моря (~165° в. д.), широты ~40°–73° с. ш. В проекции это порядка 7–8 тыс. км по ширине и ~3.5 тыс. км по высоте. Следствия: глобальная карта 8192×4096 даёт ≈ 1 км/тексель — достаточно для обзора и провинций (уезды европейской части — десятки километров), но для крупного плана нужны **детальные текстуры материалов и процедурная микро-детализация рельефа**, а при необходимости — дополнительные «тайлы» повышенной детализации для европейской части (решит спайк: 16384×8192 ≈ 256 МБ только на высоты). Слабоосвоенная Сибирь использует те же данные, но укрупнённые провинции (GDD 03).

### 2. Рантайм

1. **Геометрия рельефа:** квадродерево с плавным уровнем детализации (CDLOD или аналог): CPU выбирает видимые узлы (десятки–сотни), GPU сэмплирует высоту в вершинном шейдере; плавный переход между LOD (morphing), отсечение по пирамиде видимости; инстанс-рендеринг узлов.
2. **Материалы:** `Texture2DArray` (альбедо + нормаль + шероховатость, тайлинг в мировых координатах, triplanar на крутых склонах), смешение по карте материалов, макро-вариации цвета шумом, зима/лето — смешением наборов и маской снега.
3. **Политический слой:** индексная текстура провинций **накладывается на рельеф** в пиксельном шейдере (point sampling) → палитра (1×N, обновляется при смене режима карты). Сила раскраски зависит от зума (на дальнем плане сильнее).
4. **Границы:** шейдером по различию ID соседних текселей, толщина постоянна в пикселях экрана (через `fwidth`); уровни границ (провинция/регион/страна) через таблицы иерархии; подсветка выбранной/наведённой провинции.
5. **Вода:** море/озёра по маске и глубине (прозрачность, фреснель, анимированные нормали, пена у берега), реки — ленты-меши вдоль полилиний с анимацией течения.
6. **Растительность:** леса — инстансинг низкополигональных деревьев/импостеров в тайлах вокруг камеры по карте плотности; на дальнем плане — только цвет материала.
7. **Объекты:** города, крепости, порты, армии, торговые пути — инстансы моделей и маркеров, уровень детализации по зуму (вдали иконки и подписи).
8. **Освещение, время суток и погода (решено: сезоны + смена дня и ночи + погода):** динамическое солнце (направление и цвет по времени суток и сезону/широте), небесный купол с атмосферным рассеянием, ночное освещение (огни городов, лунный свет), мягкие **динамические тени** (каскадные карты теней, дальность по пресету) и предрасчитанное затенение рельефа; дымка по расстоянию; погода — облака (и их тени), дождь, снег, туман, метель как комбинация частиц и параметров шейдеров рельефа/воды. Сезоны: смена наборов материалов, маска снега по температуре/высоте, цвет растительности. Игровое время (1 тик = 1 день) задаёт сезон; **время суток течёт визуально**, независимо от тика (цикл суток в реальных секундах, настраиваемый, можно выключить).
9. **Камера:** орбитальная вокруг точки фокуса на рельефе; зум меняет и дистанцию, и наклон (вдали — почти сверху); ограничения по границам карты, инерция, управление мышью/клавиатурой/краем экрана.
10. **Выбор объекта:** луч камеры → пересечение с высотным полем на CPU (иерархия min/max по карте высот) → мировые XZ → ID провинции из CPU-копии индексной текстуры. Без считывания с GPU, детерминированно и дёшево.
11. **Режимы карты:** обновление палитры/наложенных текстур из значений в снапшоте симуляции (только при изменении).
12. **Пресеты качества:** Низкое / Среднее / Высокое: дальность и детальность рельефа, разрешение текстур, тени, вода, плотность растительности.

### 3. Бюджеты (черновик, уточняются спайком)

| Метрика | Цель |
|---|---|
| Кадр карты, GPU, 1080p, пресет «Среднее», минимальное железо | ≤ 12 мс |
| Видеопамять под карту (пресет «Среднее») | ≤ 2 ГБ; «Низкое» ≤ 1 ГБ |
| Оценка текстур | высоты 8192×4096×16 бит ≈ 64 МБ; ID 8192×4096×16 бит ≈ 64 МБ; материалы/маски со сжатием BC ≈ 100–200 МБ; материалы поверхности (array, BC) ≈ 100–300 МБ |
| Узлов рельефа за кадр | ≤ ~500 |
| Загрузка карты | ≤ 10 с |

| Этап | Результат | Эпик |

## Последствия

- **Объём работы по карте и рендеру значительно вырастает** (эпик E5: L → XL; E3 спайк: +~8 рабочих дней; арт E26 — больше). Это главный риск ТЗ после «свой движок».
- Появляется требование к видеокарте (NFR-PERF-1 уточнено): встроенная графика годится только для пресета «Низкое».
- Данные карты (DEM, реки, текстуры) нужно брать с совместимыми лицензиями и вести в реестре ассетов (`assets/LICENSES.csv`).
- Симуляция не затрагивается: граница `sim` / `engine` остаётся прежней, карта читает снапшоты.
- Упрощения на старте: детальные 3D-модели юнитов и зданий откладываются до M3 (маркеры и простые инстансы — решено).
- Выбор «сезоны + день/ночь + погода» делает динамическое освещение и тени обязательными, а не опциональными: бюджет кадра (NFR-GFX-1) нужно проверять с включёнными тенями и погодой; пресеты качества обязаны уметь их урезать.

## Риски и меры

| Риск | Мера |
|---|---|
| Рендер ландшафта «съедает» время, игра не появляется | Строго поэтапно (P1…P5); P1 в спайке; остальное — между вехами геймплея, а не вместо них |
| Нет арта уровня Victoria 3 | Процедурные материалы из DEM, CC0-текстуры (ambientCG / Poly Haven и др., лицензия CC0), стилизация шейдерами, а не ручной живописью |
| Производительность на слабых GPU | Пресеты, LOD, ограничение детальности, тесты на «слабом профиле» (E2-T08/E3-T10) |
| Лицензии на данные (DEM, реки) | Выбирать данные в общественном достоянии или с допустимой атрибуцией; всё в реестре |
| Рассинхрон с геймплеем (границы провинций ↔ рельеф) | Единый источник правды — карта ID провинций; `mapgen` строит граф соседства и проверяет согласованность |

## Отклонённые альтернативы

- **2D-карта с «псевдорельефом»** (затенённая картинка) — была планом до изменения требования; дешевле, но не соответствует требованию «полноценный объёмный ландшафт».
- **Предрендеренная изометрия** — нет свободной камеры.
- **Готовый движок для карты** (Unity/Godot) — противоречит решению о собственном движке (ADR-0001).
- **D3D12/Vulkan** — не нужны для такой нагрузки; пересмотреть только по результатам профилирования.

## Результаты спайка E3 (2026-11-06)

CDLOD с морфингом, палитры режимов, границы постоянной ширины, SDF-подписи и выбор лучом реализованы и измерены (`docs/dev/e3-spike-report.md`): кадр GPU ≤ 1.3 мс на RTX 3050 до 3840×2160, 8–87 узлов (бюджет ≤ 500), смена режима ≤ 0.12 мс CPU, видеопамять карты ≈ 245–290 МиБ. Бюджет кадра карты GPU на минимальном железе уточнён владельцем: **≤ 8 мс** на пресете «Среднее».

3. Нужны ли «тайлы повышенной детализации» для европейской части (16384×8192) или хватит глобальной 8192×4096 с процедурной микро-детализацией — решит спайк E3.
4. Скорость цикла суток по умолчанию и режимы (реальное время / ускоренный / выключен).

## Статус этапа P2 (2026-11-07, issue #120)

Сделано в `terrain.hlsl`: направленное солнце (`MapLighting`: азимут, высота), полусферический свет неба, **мягкие тени от рельефа трассировкой луча по текстуре высот** (24 шага на пиксель, без shadow map; 0 шагов выключает), вариации альбедо шумом (гаснут с расстоянием), скалы на крутых склонах, снег на высоте, дымка по расстоянию. Стоимость на RTX 3050 при 1080p, карта 8192×4096: GPU p50 1.02 → 2.16 мс с тенями (бюджет «не больше +2 мс»). Параметры в спайке: `--sun AZ,EL`, `--shadows N`, `--haze X`, `--mode N`. Осталось в P2: текстуры материалов вместо плоских цветов (нужны арт-ассеты), каскады/тени от объектов (с P4).

## Статус этапа P3 (2026-11-07, issue #123)

Часть a — **море**: анимированные нормали волн (длинная зыбь + мелкая рябь, затухают, когда пиксель покрывает больше пары текселей), Френель (цвет глубины ↔ небо), блик солнца по половинному вектору, пена в мелководье у берега. Стоимость ≈ 0 на RTX 3050 (GPU p50 1.00 мс на береговом виде без теней). Осталось в P3: реки и озёра — после реальных данных (E21, Geo-3…), отражения объектов и прибой — позже.
