# ADR-0008: Движок событий

- Статус: **принято** (E11-T01); открытые вопросы владельцу вынесены в отдельные issue (см. «Последствия»)
- Дата: 2026-11-14
- Связано: E11 (T01…T22, контент C01…C11), E4 (`.pd`, схемы, реестр, `loc`, `contentlint`), E7/E8/E9 (производители on-action), E13 (ADR-0011: сейвы), ADR-0001 (команды, слои), ADR-0002 (P5: индекс триггеров, бюджеты), ADR-0006 (D5 теги, D6 разделы, D7 хеш); FR-EVT-1…3, FR-DATA-1, FR-UI-3/4/5, FR-GOAL-3, NFR-DET-1, NFR-PERF-2, NFR-MOD-1; решения владельца #294 (`review`/`history`), #295 (параметры показа), #491 (исход захвата власти регентом другого рода выбирает движок событий). Все подробности, каталоги и таблицы — [docs/dev/event-engine.md](../dev/event-engine.md).

## Контекст

События — слой драмы поверх систем (GDD 08): правила пишутся данными, запускаются по действиям и пульсам, показываются игроку с последствиями до выбора, детерминированы, сохраняются и воспроизводятся. Факты, из которых надо исходить:

1. **Слои.** `sim` не зависит от `data`; `content` собирает правила из `data` + `sim` (как `build_economy_rules`); `ui` не знает `sim`, мост — `game`. Модуля `rules/` из схемы ADR-0001 нет, а «движок» не может жить ниже `sim`: ему нужны `World` и команды.
2. **Формат.** Ядро `.pd` (E4-T01) отвергает вызовы `имя(...)` и скобки (`PD012`), а схемы запрещают операторы сравнения в данных (`PD110`, «зарезервированы за E11»). GDD 08 §4.2 — псевдоформат с инфиксными выражениями.
3. **Команды и сейв.** Тег — `u16`/varint (ADR-0011), блок тегов E11 — 96…127, блок разделов — 48…63, `kMaxSections = 96`; E8 уже выпустил теги 64…83; один `kStateSchema` за W-задачу.
4. **Хеши.** `simcli_m1` закрепляет хеш мира (в него входит хеш контента `data/` за вычетом UI-вида `ui_honor_rank`). Одиннадцать пакетов контента (≈ 110 событий) иначе пересчитывали бы его по очереди.
5. **Производительность.** E2-T04: при плотном потоке и 5 000 персонажей индекс `[scope][on-action]` давал mean 3.26 мс / p99 5.20 мс против цели ≤ 1 / ≤ 3 мс (500 определений); бюджет не подтверждён. Производитель действий и стоимость fan-out не измерялись.
6. **Контракты производителей.** Шины триггеров нет: E7 отдаёт журнал применённых команд тика (`Die` и др.), E9 — `IncidentLog` с `seq` для курсора, здоровье — запись летописи `Note` 101/102 («хук для E11»).

## Варианты

**Исполнение правил**

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Интерпретация дерева AST на тике | проще написать | медленнее; два пути (дерево для тултипа, дерево для исполнения) расходятся |
| **B. Компиляция при загрузке в компактный байткод + стековая ВМ с режимами `Run`/`Trace`/`Preview` (выбрано)** | быстро; лимиты и откат тривиальны; один вычислитель для игры, причины недоступности и автотултипа | нужен компилятор и дизассемблер для отладки |
| C. Встроенный скриптовый язык (Lua/…) | гибко | новая зависимость (правило 7 AGENTS), недетерминизм по умолчанию (числа с плавающей точкой, хеш-итерация), песочница, ADR-0001 уже решил «свой DSL → байткод» |

**Синтаксис правил в `.pd`**

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Расширить грамматику `.pd` вызовами и инфиксом (`format_version = 2`) | близко к GDD 08 §4.2 | меняет парсер, схемы, `contentlint`, подсветку и позиции ошибок; приоритеты операторов; миграции всех файлов данных |
| B. Строки-выражения внутри значений (`ai_chance = "20 + opinion_of(emperor) / 5"`) | ядро не меняется | ошибки внутри строки теряют позицию; второй парсер; в строке не видно структуры для тултипа |
| **C. Блочный синтаксис на неизменённом ядре: триггеры, эффекты и «значения-аккумуляторы» — блоки записей `ключ оператор значение` (выбрано)** | парсер, `PD`-коды и позиции работают без правок; структура блока = дерево тултипа и `Breakdown`; один новый тип схемы `Type::rules()` («непрозрачный блок») | многословнее инфикса; арифметика — аккумулятором (`base`, `add`, `multiply`) |

**Хеш контента событий и закреплённые хеши**

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. События входят в хеш контента `data/` (черновик эпика) | один механизм | каждый пакет меняет `simcli_m1`; пакеты вынужденно сливаются по очереди; правка текста/`review` инвалидирует сохранения |
| **B. События исключены из хеша контента; у `EventSet` свой хеш по скомпилированному виду (выбрано)** | пакеты не трогают закреплённые значения и сливаются в любом порядке; текст и `review` на хеш не влияют; ADR-0011 получает отдельный ключ совместимости | нужен отдельный тест детерминизма живого контента (без закреплённого абсолютного хеша) |

## Решение

1. **Слои (D1).** Рантайм — `src/sim/events` (программа, ВМ, каталоги с числовыми кодами, `EventSet` как тип, состояние в `World`, системы `events.resolve` и `events.dispatch`); компилятор `.pd` → `EventSet` — `src/content/events`; мост UI — `src/game`; инструменты — `tools/`. Модуль `rules/` не создаётся.
2. **Формат (D2).** Вариант C: виды объектов `event`, `event_modifier` и `event_settings` на ядре `.pd`; правила — блоки на неизменённой грамматике; единственное расширение схем — тип `Type::rules()`; расширение файла одно (`.pd`, не `.pev`); инфиксный сахар — M2 как надстройка, компилируемая в то же дерево. `format_version` — один на файл, как у всех данных.
3. **ВМ (D3).** Вариант B: 8-байтные инструкции, только целочисленная арифметика и `Fixed64` с насыщением, жёсткие лимиты (стек, глубина областей, число инструкций, fan-out, команд на запуск), откат при превышении, три режима выполнения. Каталоги триггеров (≈ 40) и эффектов (≈ 40) — таблицы со стабильными кодами и ключами тултипов.
4. **Состояние (D4).** Всё в `World`: флаги, переменные, таймеры, кулдауны, цепочки, модификаторы, очередь игрока, кольцо истории, журнал уведомлений; события и опции ссылаются на 64-битный `EventKey` от строкового id. **Эффекты над чужим состоянием — команды** (актор — система, применение на границе тика); **эффекты над состоянием самих событий** (флаги, переменные, таймеры, модификаторы, очередь, журнал) — прямые операции системы-владельца (ADR-0006 D5: частые мелкие изменения не журналируются). Теги 96…109 выданы поимённо, 110…127 — резерв; разделы 48…57 выданы, 58…63 — резерв; части хеша `ExtPart` 24…29, 30…31 — резерв.
5. **Случайность (D5).** Только `world.rng().stream(...)`; **поток на событие** (`events.run`, `events.mtth`, `events.ai`, семейство по `EventKey`), чтобы добавление или удаление события не сдвигало броски других; MTTH → целые ppm без `double`.
6. **Индекс и пульсы (D6).** Списки `[scope][on-action]` в порядке `(priority ↓, EventKey ↑)`; дедуп кандидата `(событие, сущность)` за тик; полные пульсы по `id % 28`; ворота «кулдаун → окно дат → предфильтр → бросок MTTH → триггер»; не больше одного пульсового события на сущность за пульс; 10%-ной выборки нет. Источники действий: журнал применённых команд тика, `IncidentLog` по курсору, хвост летописи за сегодня (заметки здоровья), пульсы.
7. **Игрок (D7).** Очередь с классами `critical/important/info`, лимитом модальных окон в месяц (данные), понижением излишка до уведомлений, отсрочкой `DeferEvent`; запрос автопаузы выставляет сим (бегун ставит паузу сам на границе тика), решение о показе и звук — за хозяином UI. ИИ выбирает вариант по `ai_chance` из потока `events.ai`. Выбор — команда `ChooseEventOption`; эффекты применяются системой `events.resolve` ровно один раз (состояние `Pending → Chosen → Resolved` сохраняется).
8. **Хеш и golden (D8).** Живые события исключены из `content_hash` (обобщение `content_hash_excluding`); `EventSet::hash()` по скомпилированному виду идёт в ключ `events_hash` сводки ADR-0011 и в раздел 48; `simcli_m1` закреплён **без событий**; события покрываются `tests/golden_events_test.cpp` на эталонном наборе `tests/data/events/` (T21) и сквозным тестом «живой контент детерминирован» без абсолютного хеша. Пакеты контента не трогают закреплённых значений.
9. **Тексты (D9).** Ключи `evt.<id>.…`, `chronicle.<тип>`, `tooltip.effect.<имя>`, `tooltip.trigger.<имя>`; подстановки областей, падежи и пол — расширение синтаксиса `pat::loc` (`{actor.full:case(dat)}`, `{actor:sex(он|она)}`); формы имён — данные; текст в симуляции не участвует; `review = draft|reviewed`, `history = unchecked|checked` (решение #294).
10. **Проверки (D10).** Компилятор даёт ошибки `EV1xx` с позицией, `contentlint` — правила `EL2xx` (достижимость, циклы цепочек, варианты, `--release`, рамки контента 12+); `tools/simevents` — частота, «мёртвые» и «спам»-события.
11. **Версии (D11).** Байткод не сохраняется (компиляция при загрузке), поэтому миграции данных — через `MigrationRegistry` `.pd`; коды каталогов, `EventKey`, теги и разделы — навсегда; сейв хранит только ключи и числа; несовпадение набора событий — отказ по `events_hash`, кроме `--dev`.

## Последствия

- Каждая из W-задач (T02, T03, T21) получила конкретную раскладку и порядок; E11-T04 больше не зависит от T02 (ВМ работает через интерфейс хоста) и может идти параллельно очереди W-задач.
- Новые команды E11 (`PostEventMoney`, `AdjustSkill`, `AdjustHealth`, `AdjustStress`, `AdjustProvinceUnrest`, `AdjustProvinceControl`, `AdjustGroupMood`) правят горячие файлы `command.hpp/cpp`; коды ведомости для событий (`EventIncome`, `EventExpense`) выдаются после E8-T03 (стабильный хеш счетов).
- Долг: два вычислителя запрещены — режимы `Run`/`Trace`/`Preview` одной ВМ обязаны быть покрыты тестом «показанное = применённое»; модификаторы со статами для E7/E9 — M2 (в M1 только метки и числа для выражений событий).
- Проверить: замер E11-T05 (бюджет ≤ 1 мс mean / ≤ 3 мс p99 `[предл.]` при 110 и 550 событиях) до компилятора; поток на событие и `RngStreams` (создание потока при первом обращении, хеш по имени) — в T05; решение о мягкой совместимости сохранений при патче контента — E13-T07/M2.
- Вопросы владельцу (issue `type:decision` + `needs:owner`, рекомендации даны, до ответа в данных берутся предложения): рамки контента под рейтинг 12+ ([#495](https://github.com/savinovanton/patriarch/issues/495)); ожидание, отсрочка, область множителя частоты и излишек модальных окон ([#496](https://github.com/savinovanton/patriarch/issues/496)); видимость фоновых событий ИИ-родов, «слухи» ([#497](https://github.com/savinovanton/patriarch/issues/497)); события с четырьмя и более вариантами ([#498](https://github.com/savinovanton/patriarch/issues/498)).

## Отклонённые альтернативы

- **Шина/очередь сообщений в `sim`** для on-action — отклонено контрактом E7 (журнал команд) и стоимостью: производитель «дополнительных уведомлений на каждое изменение» не нужен, достаточно разобрать журнал тика, `IncidentLog` и хвост летописи.
- **Вероятность MTTH через `double`/`exp`** — недопустимо правилами детерминизма; используется целое `ppm = 10⁶ × интервал_пульса / MTTH` с зажимом.
- **Выборка 10% персонажей в пульс** (E2-T04) — меняет полноту (находит 18–50% подходящих пар за год) и калибровку MTTH; не вводится без отдельного решения.
- **Ручные тексты тултипов у вариантов** — теряют связь с применённым эффектом; заменены автотултипом из `Preview`.
- **События как команды целиком** (каждый флаг и таймер — запись журнала) — раздувает `CommandLog` на порядки (тысячи записей в год на персонажей); флаги и таймеры — состояние системы-владельца.
- **Один общий поток ГСЧ `events`** — любое добавление события сдвигает броски всех остальных, ломая сравнение прогонов и ревью пакетов.
