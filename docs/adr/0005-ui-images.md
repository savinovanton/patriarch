# ADR-0005: Изображения в UI — PNG через WIC, SVG через плагин RmlUi и lunasvg

- Статус: **принято** (технический выбор агента в рамках ADR-0001; расширение набора зависимостей)
- Дата: 2026-11-07
- Связано: ADR-0001 (стек, RmlUi), E3 (спайк UI), задача UI-1 (тема Olive Stone по макету Figma), `assets/LICENSES.csv`

## Контекст

Макет владельца (Figma, «Patriarch Sovereign — World UI · Olive Stone») состоит из золочёной рамы (PNG 1920×1080 с прозрачным центром) и векторных иконок (SVG: меню, ресурсы, сигналы). Интерфейс спайка до сих пор обходился цветами и текстом: `IRenderInterface::LoadTexture` был заглушкой. Нужно загружать PNG и растеризовать SVG, не вводя тяжёлых зависимостей и не нарушая границ слоёв (UI не зависит от `sim`).

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. PNG через **WIC** (Windows Imaging Component), SVG через **плагин SVG RmlUi + lunasvg** | WIC уже в системе, без новых библиотек для PNG/JPEG; SVG остаётся векторным и чётким при любом масштабе интерфейса; плагин RmlUi — готовое решение | WIC только Windows (рендерер D3D11 и так только Windows); новая зависимость lunasvg (маленькая, MIT) |
| B. `stb_image` для PNG, `lunasvg` для SVG | кроссплатформенно | ещё одна зависимость ради PNG; для D3D11-рендерера выгоды нет |
| C. Заранее растеризовать SVG в PNG | без lunasvg | размытие при масштабах интерфейса, множество вариантов размеров, лишний шаг сборки |
| D. `libpng` через vcpkg | стандарт | тяжелее `stb`, ради одного формата |

## Решение

Вариант **A**. `D3d11UiRenderer::LoadTexture` декодирует файл через WIC в премультиплицированный RGBA8 (формат, который ждёт шейдер UI); SVG рисует элемент `<svg src="...">` из состава RmlUi (включается функцией `svg` пакета `rmlui` в `vcpkg.json`, тянет `lunasvg` 3.5.0, лицензия MIT). Для Linux/CI без движка ничего не меняется: изображения нужны только слою `engine`/`ui`. Если появится не-Windows рендерер, декодер PNG заменяется на `stb_image` за тем же интерфейсом (изменение локально в `LoadTexture`).

## Последствия

- Рамы, кнопки, иконки подключаются обычными `<img>`/`<svg>`/декораторами RmlUi; ассеты регистрируются в `assets/LICENSES.csv`.
- Зависимость `lunasvg` (MIT) добавляется в `vcpkg.json` (версия фиксируется `builtin-baseline`).
- Для удобства дизайнера иконки лежат в `assets/ui/olive/icons/*.svg` как есть (цвета заданы внутри файла); перекраска состояний — отдельными файлами или маской позже (пока не нужна).
- Проверить: расход памяти текстур при 4K, время загрузки рамы (731 КБ PNG) — измерения в отчёте UI-1.

## Отклонённые альтернативы

B и D — лишние зависимости ради PNG без пользы для Windows-рендерера; C — потеря качества и рост числа ассетов.
