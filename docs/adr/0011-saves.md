# ADR-0011: Сохранения партии

- Статус: **принято**
- Дата: 2026-11-13
- Связано: E13 (T01…T15), E1-T10 (`PSV1`), ADR-0006 (D5 блоки тегов, D6 схема и разделы), ADR-0001 (снапшоты); FR-SAVE-1/2, NFR-PERF-5/6, NFR-DET-1; решения владельца #357 (каталог), #358 (автосохранения). Подробности и таблицы — [docs/dev/save-format.md](../dev/save-format.md).

## Контекст

Сохранение уже работает на уровне ядра (E1-T10, схемы мира 1…11, фикстуры), но у игры нет «сохранения партии» как продукта: нет сводки для экрана загрузки, каталога, автосохранений, политики совместимости. Раскладка форматов размазана по ADR-0006 и комментариям `world_io.cpp`. Эпики E8/E10/E11/E12/E30 одновременно добавляют состояние, и два лимита упрутся в план:

1. `kMaxSections = 32` в `world_io.cpp` при плане ≈ 76 разделов в худшем случае (E7 7, E9 9, E8 ≤ 16, E11 ≤ 16, E10 8, E12 12, E30 8).
2. `CommandType` — `uint8_t`: 255 тегов на все эпики; блоки E10/E12/E30 уже занимают 128…175, остальным остаются ≈ 80.

Факты: контейнер `PSV1` версии 1 (заголовок 32 байта, zstd, хеш нагрузки); команды кодируются одним общим `write_command` для `PSV1` (отложенные команды), `PRP1` и `PCL1`; `kExpectedReplayBytesHash` хеширует байты реплея демо, поэтому любое изменение кодирования команд — изменение golden.

## Варианты

**Ширина тега команды**

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. `u8`, компактные блоки | ничего не меняется | потолок 255 на всю игру; переносится на момент, когда файлов и реплеев больше |
| B. Плоский `u16` | просто | меняется кодирование во всех трёх форматах: `PRP2`, `PCL2`, версия контейнера, чтение обеих версий, пересчёт golden реплея; +1 байт на команду |
| **C. `u16` в памяти + varint (LEB128) на проводе** | теги 1…127 побайтно прежние — форматы и golden не меняются; потолок 16 383 | два байта на теги ≥ 128; один общий код (де)кодирования тега |

**Метаданные для экрана загрузки**

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Флаг в `flags` у `PSV1` | версия не меняется | старая сборка скажет «неподдерживаемые флаги» вместо «новее» |
| B. Новая магия `PSV2` | чёткое разделение | старая сборка скажет «не сохранение Patriarch» |
| **C. Магия `PSV1`, `format_version = 2`, сводка между заголовком и zstd-кадром** | старая сборка отказывает честно («создано более новой версией», код 22); нагрузка не меняется | заголовок v2 длиннее (44 байта) |
| D. Сводка в отдельном файле рядом | не трогает контейнер | рассинхрон файлов, лишний шаг атомарности |

**Лимит разделов:** 32 → 64 (недостаточно для плана) / **96 = первый нераспределённый id (выбрано)** / 255.

## Решение

1. **Тег команды — вариант C.** `CommandType` получает базовый тип `std::uint16_t`, на проводе — varint (1…127 — один байт, 128…16 383 — два байта; только каноническая форма). Для существующих тегов (1…39) и блоков E8/E11 (< 128) байты прежние, поэтому **`PRP1`, `PCL1` и нагрузка `PSV` не меняют версий, golden и фикстуры не двигаются**. Блоки тегов остаются как распределены (E1 1…5, E7 6…31, E9 32…63, E8 64…95, E11 96…127, E10 128…143, E12 144…167, E30 168…175, 176…255 — E14/E15/E16/E17/E20/E31/E33/E34, ≈ 10 на эпик); следующие блоки выдаются с 256, а не «уплотняются».
2. **Контейнер — вариант C.** Магия `PSV1`, `format_version = 2`: между заголовком и zstd-кадром несжатая сводка (`u16 key | u16 length | bytes`, неизвестные ключи пропускаются, свой `summary_hash`; ≤ 16 КиБ): версия игры, схема, сценарий, **хеш совместимости контента**, род игрока, имя главы, дата, казна, цель, время игры, вид (ручное/авто/быстрое/при выходе), имя, время сохранения, хеш мира, тик; ключи для ironman и скриншота зарезервированы. Версия 1 читается навсегда без сводки. Раскладка мира и `kStateSchema` не затронуты.
3. **Лимит разделов:** `kMaxSections = 96`; блоки разделов: E7 1…15, E8 16…31, E9 32…47, E11 48…63, E10 64…71, E12 72…83, E30 84…91, E13 92…95 (резерв), 96… — следующим эпикам. Задача T03 меняет только лимит (и тег), **не поднимая** `kStateSchema` (старая сборка получит «более новая версия» по слову схемы до проверки числа разделов). T03 выполняется **до E11-T03 и E10-T03** (в очереди W-задач — после E8-T03).
4. **Политика версий:** `kStateSchema` +1 за каждое изменение байтов (включая смену единицы); `load_state` читает все схемы от 1 навсегда (окно не сужается в M1); разделы читаются во всех своих версиях; `format_version` читается всеми версиями ≥ 1; вперёд не читаем, но отказываем понятно; реплеи и журналы гарантированы только на сборке-авторе. Любой PR, меняющий раскладку, обязан оставить фикстуру прежней схемы, запись в корпусе порчи и resume-сценарий (чек-лист §7.4 справочника; CI-проверка — E13-T12).
5. **Совместимость при загрузке:** отказ — формат новее, схема новее, другой набор контента (по хешу; режим `--dev` игнорирует), повреждение; игра не падает, причина — игроку, подробности — в журнал. Версия сборки на совместимость не влияет.
6. **Каталог (решение владельца #357):** `SDL_GetPrefPath("Patriarch", "Patriarch")` → `saves\*.psv`, `settings.pd`, `logs\`, `--user-dir` переопределяет. Имена: ручные `<имя>.psv` (кириллица как есть, запрещённые символы заменяются, путь ≤ 240), системные `_auto1…3`, `_autoexit`, `_quick` (вид определяет сводка). Запись: `.tmp` → проверка → прежний файл в `.bak` → переименование; автосохранения без `.bak` (копией служит ротация).
7. **Автосохранение (решение владельца #358):** реальное время, выкл./5/10/20 мин (по умолчанию 10), 3 ротируемых файла, отдельный файл при выходе, пропуск без изменений; F5/F9 — один слот; сохранение по игровой дате и ironman — не в M1.

## Последствия

- Старые сохранения и реплеи читаются без миграции; golden не меняются; сводка читается за миллисекунды без `zstd`.
- Номера разделов и тегов выдаются одной таблицей (`save-format.md` §5/§6) до первой строки кода эпика — два эпика не спорят за номера.
- Долг: `SectionInfo` пока знает «единственную версию» раздела — первый подъём версии существующего раздела расширяет запись до диапазона; фикстур схем 5…10 нет (закрывает E13-T12); реплеи и журналы с тегами ≥ 128 старые сборки не прочитают (допустимо: это инструменты разработки).
- Проверить: T02 (чтение v1 и v2, сводка без разжатия), T03 (границы тега 127/128/16 383, неизменность `kExpectedReplayBytesHash`/`kExpectedSaveBytesHash`), T12 (CI-проверка фикстур), T13 (NFR-PERF-6). Пересмотреть, если замеры T13 покажут, что копия мира для фоновой записи не укладывается в бюджеты.

## Отклонённые альтернативы

- **`PSV2` с новой магией** и **флаг в `flags`** — ухудшают сообщение старой сборки.
- **Плоский `u16` для тега (`PRP2`/`PCL2`)** — ломает golden реплея и требует двух читателей ради тех же 16 383 значений, которые даёт varint.
- **Дублирующий файл сводки (`.meta`)** — рассинхрон и лишняя атомарность.
- **Сохранение в `Saved Games` или рядом с `.exe`** — отклонено владельцем в пользу `SDL_GetPrefPath` (#357).
- **Сжатие сводки/хеширование сводки вместе с нагрузкой** — сводка должна читаться без разжатия и перезаписываться при переименовании без перепаковки нагрузки.
