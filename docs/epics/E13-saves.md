# E13 — Сохранения

> Веха: **M1**. Размер по дорожной карте: **M**; оценка по задачам — **≈ 42.5 дн. FTE** (задач: 15; ядро сохранений ≈ 28 дней, ещё ≈ 14 — каталог для меню, файл настроек и диалоги; критический путь ≈ 18 дней), т. е. выше M, но **основная работа уже сделана в E1** — см. §2 и §7. Статус: **разложен на задачи 2026-11-12** (задачи — в GitHub Issues, метка `epic:E13`; эпик — #46).
> Опирается на: ТЗ FR-SAVE-1 (сохранение/загрузка полной партии, версионирование, миграции), FR-SAVE-2 (автосохранения, быстрые), NFR-PERF-6 (загрузка ≤ 15 с, сохранение ≤ 5 с в фоне без фриза UI), NFR-DET-1, NFR-PERF-5; ADR-0001 (снапшоты, сейвы), ADR-0006 D6 (блок расширения, разделы, миграции); E1-T10 ✅ (`PSV1`, атомарная запись, фоновое сохранение), E7/E9 (схемы 2…10, фикстуры), UI-D12 ✅ (#284: экраны «Загрузка», «Восстановление сохранения», «Сохранение недоступно», «Настройки»).
> Оценки: **S** ≤ 1 дн., **M** 2–3 дн., **L** ~1 нед.
> Эпик **не переписывает сохранения с нуля**: он собирает из готовых частей **сохранение игры** — сводка без разжатия, каталог, сервис фоновой записи, автосейвы, загрузка с проверкой совместимости, настройки на диске, диалоги — и страхует форматы всех эпиков M1 (ёмкость, фаззинг, фикстуры, resume-тесты).

## 1. Цель

Игрок сохраняет партию вручную, быстро (F5/F9) и автоматически, видит список сохранений («Загрузка», «Продолжить»), загружает любое совместимое сохранение и продолжает **ровно с того места**; из более новой версии, с чужим набором данных или повреждённый файл не роняет игру, а даёт понятное сообщение и (для автосохранений) предыдущую копию. Сохранение идёт в фоне без фриза кадра, формат версионирован, прежние сейвы читаются навсегда, а каждый эпик M1 (E7…E12, E30), добавляющий состояние, **обязан** пройти одни и те же проверки совместимости и устойчивости.

## 2. Что уже есть и что делает эпик

**Есть (E1, E7, E9, UI-D12 — не дублируется):**
- Контейнер `PSV1`: zstd + хеш содержимого, проверка версии и флагов, точка миграций; полезная нагрузка — `World::save_state()` + невыполненные внутренние команды (`src/sim/save.*`).
- `World::kStateSchema` (сейчас 10) с пошаговой миграцией в `World::load_state`, блок расширения с **разделами** (`u16 id/version/length`, «пустое не пишется», ADR-0006 D6), фикстуры прежних схем в `tests/data/saves/` (E7/E9).
- Атомарная запись `write_file_atomic` (временный файл + переименование), `save_async` (неизменяемая копия мира + запись в потоке), `read_file`; `simcli --save/--load` и проверка хеша совместимости реестра при загрузке (E4-T10).
- Экраны меню: «Загрузка» (список, выбранное сохранение, пустое состояние), «Восстановление сохранения», «Сохранение готово/недоступно», «Настройки» — на **заглушках** (`make_placeholder_menu`, `SettingsModel` без файла), колбэки `MenuActions::load_save/continue_game/enter_game/apply_settings`.

**Делает E13:**
- единый справочник форматов, реестры тегов и разделов, политика совместимости (T01) и **две ёмкостные проблемы**: лимит `kMaxSections = 32` при плане ≈ 35–40 разделов и 8-битный тег команды (255 на все эпики) — T01/T03;
- метаданные сохранения для списка без разжатия (T02), каталог (T04), сервис записи и загрузки (T05, T07), автосохранения и быстрое сохранение (T06), мост меню вместо заглушки (T08), файл настроек (T09), диалоги (T10);
- устойчивость и совместимость: фаззинг (T11), CI-проверка фикстур и resume-матрица (T12), замеры NFR-PERF-6 (T13), приёмка (T14), итог (T15).

## 4. Пользовательские истории и критерии приёмки

**US-13.1 (SAVE-A1).** *Как игрок, я хочу сохраниться посреди чего угодно и продолжить ровно оттуда.*
- *Дано:* партия с ожиданием ответа на брак, таймером события, заговором, регентством. *Когда:* сохранение → загрузка → продолжение. *Тогда:* результат совпадает с непрерывным прогоном (хеши).

**US-13.2 (SAVE-A2).** *Как игрок, я хочу автосохранения без забот.*
- *Дано:* автосохранение каждые 10 минут. *Когда:* прошло 4 интервала. *Тогда:* 3 файла ротации, самый старый заменён; на паузе без изменений новые не пишутся; при выходе — отдельное автосохранение.

**US-13.3 (SAVE-A3).** *Как игрок, я не хочу потерять партию из-за сбоя записи.*
- *Дано:* последний автосейв повреждён. *Когда:* «Продолжить». *Тогда:* предложено предыдущее сохранение, игра не падает.

**US-13.4 (SAVE-A4).** *Как игрок, я хочу понятное сообщение о несовместимости.*
- *Дано:* сохранение из более новой версии или с другим набором данных. *Когда:* «Загрузить». *Тогда:* «Сохранение недоступно» с причиной; список остальных не страдает.

**US-13.5 (SAVE-A5).** *Как игрок, я хочу называть сохранения по-русски.*
- *Дано:* имя «Перед заговором 1708». *Когда:* сохранение и загрузка. *Тогда:* файл создан, имя в списке верное, перезапись требует подтверждения.

**US-13.6 (SAVE-A6).** *Как игрок, я хочу быстро сохраняться.*
- *Дано:* F5/F9. *Когда:* нажимаю. *Тогда:* тост «Быстрое сохранение», загрузка того же слота; клавиши переназначаются.

**US-13.7 (NFR-PERF-6).** *Как игрок, я не хочу фризов.*
- *Дано:* поздняя партия (стресс-состояние). *Когда:* сохранение. *Тогда:* ≤ 5 с в фоне, кадр не задерживается; загрузка ≤ 15 с.

**US-13.8 (разработчик, SAVE-A7).** *Как разработчик, я хочу, чтобы любой PR с новым состоянием проходил проверки.*
- *Дано:* PR поднимает `kStateSchema`. *Когда:* CI. *Тогда:* требует фикстуру прежней схемы, читает все фикстуры, гоняет resume-матрицу и корпус порчи; новый раздел без корпуса — красный тест.

**US-13.9 (настройки).** *Как игрок, я хочу, чтобы настройки помнились.*
- *Дано:* изменён масштаб интерфейса и клавиши. *Когда:* перезапуск. *Тогда:* значения те же; повреждённый файл не мешает запуску.

### 5.1 Порядок работы и параллелизм

- **Одновременно — только одна W-задача** во всём репозитории. **T03** (ёмкость форматов) нужно сделать **до** первой задачи E10/E12/E30, которая превысит 32 раздела (очередь: … → E8-T03 → **E13-T03** → E11-T02/T03 → E10-T02/T03 → E12-T02/T03 → E30-T02/T03). **T02** (контейнер) не трогает раскладку мира, но меняет формат файла — в очередь W-задач его ставят после E8-T03.
- **E13-T01** выполнена (ADR-0011). Теперь T02, T03, T04 можно брать параллельно разными агентами (T02 и T03 — W-задачи: по очереди, см. выше).
- **T07** (загрузка) делит сборку сессии с **E30-T10**; **T08** (мост) ждёт `GameSetup` (E30-T02); интерфейсная часть (T08–T10) идёт рядом с логикой, борды окон нарисованы (доски 14–23, 72, 78, `data/ui/layout/save_menu.pd`, UI-D11 #468); окна — после моста T08.
- «Горячие» файлы (`save.*`, `world_io.cpp`, `command.*`): не более двух задач одновременно, перед PR — `rebase`.

## 6. Тесты

### 6.1 Детерминизм и совместимость
- Round-trip и **resume** («сейв в точке N → продолжение = непрерывный прогон») по сценариям `demo`, `dynasty`, `m1` и новым; точки: дни 1, 30, 365, середина месяца (T12); `simcli --verify-save-resume`.
- Фикстуры **всех** схем читаются навсегда; CI требует фикстуру прежней схемы при подъёме `kStateSchema`; хеши после загрузки сверяются.

### 6.2 Политика golden (AGENTS.md §5.4)
- E13 **не меняет** golden мира и реплея: T02 меняет только контейнер; T03 — только лимит разделов (и тег, если решено: тогда `PRP`/`PCL` читают оба формата, golden реплея — осознанно с объяснением).
- Два PR, одновременно меняющие формат или golden, — стоп и согласование в issue.

### 6.3 Устойчивость (T11)
- Усечения на каждой границе, битовые порчи, перестановки/дубликаты `id` разделов, раздутые счётчики, ссылки за пределы таблиц, неизвестные перечисления, «бомба» zstd — ни падений, ни `PAT_ASSERT`, ни неограниченной памяти; ASan/UBSan.
