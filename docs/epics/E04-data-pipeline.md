# E4 — Данные и контент-пайплайн

> Веха: **M1**. Размер: **M (~12 рабочих дней FTE)**. Статус: **разложен на задачи 2026-11-06** (задачи — в GitHub Issues, метка `epic:E4`).
> Опирается на: GDD 08 §4 (язык правил, формат), ТЗ FR-DATA-1, FR-UI-5, NFR-MOD-1, ADR-0001 (слой данных свой, типизированный DSL), ADR-0002 (интернирование идентификаторов, без разбора текста на тике), ADR-0004 (геоданные и провенанс).
> Оценки: **S** ≤ 1 дн., **M** 2–3 дн., **L** ~1 нед.

## 1. Цель

Весь контент игры (провинции, династии, черты, навыки, события, сценарии, тексты) живёт в **файлах данных**, а не в коде; формат читаемый, типизированный и открытый для модов; ошибки находятся при загрузке с точным местом (файл:строка:столбец); тексты локализованы (RU, затем EN) с плюрализацией; файлы горячо перезагружаются в разработке. Эпик даёт **механизм** — сам объём контента (события и т. д.) пишет E22.

## 2. Объём

**Входит:** спецификация формата, лексер и парсер, схемы типов и валидация, реестр контента (загрузка нескольких корней: база + моды, переопределение, перекрёстные ссылки, хеш контента), первые определения для M1 (провинции, династии, черты, навыки), локализация (таблицы строк, именованные параметры, плюрализация RU/EN, запасные цепочки), горячая перезагрузка, утилита `contentlint`, документация формата для авторов.
**Не входит:** язык правил событий и их исполнение (триггеры, эффекты, компиляция в байткод — E11), сами события и тексты (E22), загрузка модов пользователем (после релиза; но загрузчик с нескольких корней — с первого дня), изображения и портреты (E26).

## 3. Решения и допущения эпика

| # | Вопрос | Решение (предложение агента; статус) |
|---|---|---|
| 1 | Формат | **Собственный типизированный DSL**, Paradox-подобный синтаксис (GDD 08 §4, подтверждено владельцем в GDD); расширение файлов `.pd` |
| 2 | Где лежит контент | Каталог **`data/`** в корне репозитория (оригинальный контент проекта; под общей лицензией «все права защищены»), **не** `assets/` — иначе каждый файл надо вносить в `LICENSES.csv`. Сторонние/производные данные (карты из DEM, шрифты, картинки) — по-прежнему `assets/` и реестр |
| 3 | Локализация | **Свой лёгкий формат** (`ключ = "текст"` в `.pd`, язык задаёт каталог `data/loc/<язык>/`) + именованные параметры + плюрализация RU (3 формы) и EN (2 формы); **без ICU** (тяжёлая зависимость). **Решено владельцем 2026-11-08 (#109)**; реализация — `src/loc`, [localization.md](../dev/localization.md) |
| 4 | Числа | Дробные числа в данных парсятся **в `Fixed`** без `double` (детерминизм); целые — `int64` |
| 5 | Идентификаторы | Интернируются в `StringId` при загрузке (`core::StringInterner`); на тике строк нет |
| 6 | Совместимость | `format_version` в каждом файле; хеш всего контента кладётся в сейв (контроль совпадения) |

## 4. Пользовательские истории и критерии приёмки

**US-4.1.** *Как автор контента, я хочу видеть точное место ошибки.*
- *Дано:* файл с опечаткой в имени поля, лишней скобкой и неверным типом значения. *Когда:* запуск `contentlint`. *Тогда:* сообщения вида `data/traits/core.pd:14:5: unknown field 'skils' (did you mean 'skills'?)`, все ошибки сразу (не только первая), ненулевой код выхода.

**US-4.2.** *Как автор, я хочу править файл и сразу видеть результат.*
- *Дано:* запущен спайк/игра в dev-режиме. *Когда:* сохраняю `.pd` с правкой. *Тогда:* контент перезагружается за < 1 с; при ошибке старое содержимое остаётся, ошибка показана и записана в лог.

**US-4.3.** *Как переводчик, я хочу правильные формы слов.*
- *Дано:* строка «{n} {n:plural(год|года|лет)}». *Когда:* n = 1, 2, 5, 11, 21, 22, 25, 111. *Тогда:* «1 год», «2 года», «5 лет», «11 лет», «21 год», «22 года», «25 лет», «111 лет»; отсутствующие ключи находятся `contentlint` (покрытие по языкам).

**US-4.4.** *Как моддер (после релиза), я хочу переопределять и добавлять данные.*
- *Дано:* два корня данных (база и мод). *Когда:* мод задаёт черту с тем же id и новую. *Тогда:* переопределённая заменяет базовую, новая добавляется, порядок загрузки детерминирован и записан в хеше контента.

**US-4.5.** *Как разработчик, я хочу, чтобы мир строился из данных.*
- *Дано:* файлы провинций и династий. *Когда:* запуск спайка/`simcli` со сценарием «M1». *Тогда:* мир создаётся из загруженного контента; связь провинций данных с идентификаторами карты (PMD) проверяется при загрузке.

## 6. Тесты

- Юнит-тесты лексера/парсера на корпусе (корректные и некорректные файлы), фаззинг (случайные байты, обрезанные файлы, глубокая вложенность — ограничение глубины).
- Тесты схем: по одному на тип и класс ошибки; `Fixed` без округления через `double`.
- Тесты реестра: порядок корней, переопределение, битые ссылки, хеш контента стабилен и меняется при правке.
- Тесты локализации: плюрализация RU/EN (таблица значений), параметры, запасные языки, отсутствующие ключи.
- `contentlint` в CI на `data/` и на корпусе ошибок (ожидаемый провал).

## 7. Риски и вопросы

| Риск | Митигация |
|---|---|
| Свой формат разрастается в «язык» | Парсер — только данные; правила событий — отдельно (E11) на готовом парсере; расширять синтаксис только с записью в `data-format.md` |
| Сообщения об ошибках неудобны | Критерий US-4.1 — тест на текст сообщений; «возможно, вы имели в виду…» |
| Горячая перезагрузка ломает состояние | Перезагружаем только определения, не состояние мира; подмена атомарна после валидации |
| Локализация RU: склонения шире плюрализации | Явные формы в строках (`plural`), падежи — отдельными ключами; расширение по мере надобности |
| Хеш контента мешает сейвам при правке текстов | В хеш входят только данные, влияющие на симуляцию; тексты — отдельно |

**Открытые вопросы владельцу:**
1. Локализация: свой лёгкий формат (рекомендация) или ICU MessageFormat (тяжёлая зависимость, больше возможностей)?
2. Нужен ли английский язык к M1 или только русский (EN — после M2)?
