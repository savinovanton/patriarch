# E9-T07: стоимость шага производства и потребления в `economy.provinces`

> Дата: 2026-11-09. Задача: [E9-T07](../epics/E09-holdings-economy.md) (#149). Бюджет — [economy-model §14](../dev/economy-model.md): экономика за день на 400 провинциях **≤ 3 мс p95**, закрытие месяца ≤ 5 мс; профиль ×3 — те же правила, жёсткого предела нет.

## Метод

Тот же, что в [E9-T06-population.md](E9-T06-population.md): `stressgen --profile year60|year60x3 --seed 7 --bench --bench-days 1500` на Release-сборке MSVC (`cmake --build --preset win-msvc-release --target stressgen`). Мир генерирует `stressgen --economy`, сохраняет, загружает и гонит 1500 дней (≈ 4,1 года) с каркасом систем E9-T05, в котором `economy.provinces` — **настоящая** система (шаги 2 и 3 из §7.3: рост населения T06 + производство и потребление T07, правила `EconomyRules::defaults()`, статические цены), `economy.settlement` и `economy.construction` — пустые заглушки. Метрики — телеметрия `system.economy.*` (окно 1024 тика) и таймер вокруг каждого `Simulation::tick()` с разбивкой по дню месяца. Второй прогон из того же мира даёт тот же хеш (`deterministic: true`), хеш загруженного мира равен хешу сгенерированного (`loaded_hash_equal: true`).

Генератор мира `stressgen --economy` теперь задаёт `capacity` хлеба по числу людей провинции (запас 20 % при стартовой рабочей силе и контроле), чтобы мир мирного времени не голодал; остальные товары и состояние — как раньше.

## Результаты (микросекунды на день)

| Профиль | Провинций | `system.economy.provinces` p50 / p95 / p99 / max | Тик в дни слотов 1…28, p50 / p95 | Тик в дни 29…31, p50 / p95 | Тик в 1-е число месяца, p50 / p95 / max |
|---|---:|---|---|---|---|
| year60 | 400 (14–15 слотов в день) | 64,2 / 77,0 / 102,0 / 242 | 64,9 / 83,4 | 0,3 / 0,4 | 68,1 / 81,9 / 114 |
| year60x3 | 1200 (42–43 слота в день) | 196,6 / 293,1 / 333,8 / 380 | 196,1 / 292,5 | 0,3 / 0,6 | 195,7 / 291,2 / 299 |

- **Бюджет 3 мс/день выполнен с запасом ≈ 40×** (p95 77 мкс на 400 провинциях; ×3 — 293 мкс).
- Стоимость слота провинции ≈ 4,5 мкс (рост T06 был ≈ 0,23 мкс): добавились сборка входа (6 групп, 10 слотов товаров, вызов `PriceSource` для каждого производимого товара), 6 выпусков по 5 множителей, потребность по 10 товарам, запас хлеба и достаток 6 групп. Всё целочисленное; рост линеен по числу провинций (×3 → ×3,0).
- «Месячного всплеска» нет по построению (stagger `id % 28`): 1-е число стоит как обычный день слотов, дни 29–31 почти пусты.
- Население за прогон: 50 695 000 → 50 815 385 (+0,24 % за 4,1 года на профиле `year60`: провинции генератора заполнены до предела тесноты, прирост замедлен) и 149 014 000 → 149 426 900 на ×3.

## Вывод

Превышений бюджета нет, issue `type:bug` `area:perf` не заводится. Следующие шаги `process_province` (налоги T08, настроения T11, рекруты T13) добавят стоимость; сводный замер — T23.
