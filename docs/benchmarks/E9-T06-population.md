# E9-T06: стоимость системы `economy.provinces` (рост населения)

> Дата: 2026-11-09. Задача: [E9-T06](../epics/E09-holdings-economy.md) (#148). Бюджет — [economy-model §14](../dev/economy-model.md): экономика за день на 400 провинциях **≤ 3 мс p95**, закрытие месяца ≤ 5 мс; профиль ×3 — те же правила, жёсткого предела нет.

## Метод

`stressgen --profile year60|year60x3 --seed 7 --bench --bench-days 1500` на Release-сборке MSVC (`cmake --build --preset win-msvc-release --target stressgen`). Мир сгенерирован `stressgen --economy`, сохранён, загружен (как в игре) и прогнан 1500 дней (≈ 4,1 года) с каркасом систем E9-T05: `economy.provinces` — **настоящая** система T06 (правила `EconomyRules::defaults()`), `economy.settlement` и `economy.construction` — пустые заглушки с теми же именами. Метрики — телеметрия `system.economy.*` (окно 1024 тика) и собственный таймер вокруг каждого `Simulation::tick()` с разбивкой по дню месяца (`skeleton.tick_us` в отчёте). Второй прогон из того же мира должен дать тот же хеш (`deterministic: true`); `check_invariants` после прогона пуст.

## Результаты (микросекунды на день)

| Профиль | Провинций | `system.economy.provinces` p50 / p95 / p99 / max | Тик в дни слотов 1…28, p50 / p95 | Тик в дни 29…31, p50 / p95 | Тик в 1-е число месяца, p50 / p95 / max |
|---|---:|---|---|---|---|
| year60 | 400 (14–15 слотов в день) | 3,3 / 5,4 / 6,7 / 82 | 3,7 / 6,1 | 0,3 / 0,5 | 3,9 / 6,8 / 29 |
| year60x3 | 1200 (42–43 слота в день) | 10,4 / 16,4 / 33,9 / 104 | 10,8 / 17,0 | 0,3 / 0,5 | 10,7 / 17,8 / 35 |

- **Бюджет 3 мс/день выполнен с запасом ≈ 500×** (p95 5,4 мкс на 400 провинциях; ×3 — 16,4 мкс). Максимумы (82 и 104 мкс) — разовые выбросы планировщика ОС, а не стоимость логики; тоже на два порядка ниже бюджета.
- «Месячного всплеска» нет по построению: работа размазана stagger-ом `id % 28`, дни 29–31 почти пусты (0,3 мкс), а 1-е число (слот 0 плюс будущий `economy.settlement`) стоит как обычный день слотов. Закрытие месяца (`economy.settlement`) пока заглушка: его бюджет проверит T09.
- Стоимость слота провинции ≈ 0,23 мкс (6 групп, только целые числа); рост линеен по числу провинций (×3 → ×3,1).
- Рост населения за прогон: 50 695 000 → 50 820 794 (+0,25 % за 4,1 года на профиле `year60`: большинство провинций генератора заполнено у предела тесноты, где прирост по формуле F1 замедляется до нуля) и 149 014 000 → 149 440 699 на ×3.

## Вывод

Превышений бюджета нет, issue `type:bug` `area:perf` не заводится. Реальные формулы T07–T13 добавят шаги в `process_province`; бюджет 3 мс будет перепроверен на T23.
