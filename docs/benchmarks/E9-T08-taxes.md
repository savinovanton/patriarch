# E9-T08: стоимость шага налогов в `economy.provinces`

> Дата: 2026-11-10. Задача: [E9-T08](../epics/E09-holdings-economy.md) (#150). Бюджет — [economy-model §14](../dev/economy-model.md): экономика за день на 400 провинциях **≤ 3 мс p95**, закрытие месяца ≤ 5 мс; профиль ×3 — те же правила, жёсткого предела нет.

## Метод

Тот же, что в [E9-T07-production.md](E9-T07-production.md): `stressgen --profile year60|year60x3 --seed 7 --bench --bench-days 1500` на Release-сборке MSVC (`cmake --build --preset win-msvc-release --target stressgen`). Мир генерирует `stressgen --economy`, сохраняет, загружает и гонит 1500 дней (≈ 4,1 года) с каркасом систем E9-T05, в котором `economy.provinces` — **настоящая** система: шаги 2, 3 и (новый) 4 из §7.3 — рост населения, производство и потребление, налоги и доход хозяйства с проводками через `post_money` (правила `EconomyRules::defaults()`, статические цены). `economy.settlement` и `economy.construction` — пустые заглушки. Метрики — телеметрия `system.economy.*` (окно 1024 тика) и таймер вокруг каждого `Simulation::tick()` с разбивкой по дню месяца. Второй прогон из того же мира даёт тот же хеш (`deterministic: true`), хеш загруженного мира равен хешу сгенерированного (`loaded_hash_equal: true`).

## Результаты (микросекунды на день)

| Профиль | Провинций | `system.economy.provinces` p50 / p95 / p99 / max | Тик в дни слотов 1…28, p50 / p95 | Тик в дни 29…31, p50 / p95 | Тик в 1-е число месяца, p50 / p95 / max |
|---|---:|---|---|---|---|
| year60 | 400 (14–15 слотов в день) | 111,3 / 138,4 / 173,2 / 302 | 114,3 / 173,3 | 0,4 / 0,6 | 119,5 / 177,8 / 180 |
| year60x3 | 1200 (42–43 слота в день) | 338,7 / 512,5 / 533,3 / 639 | 340,2 / 512,7 | 0,4 / 0,8 | 335,5 / 512,5 / 531 |

- **Бюджет 3 мс/день выполнен с запасом ≈ 20×** (p95 138 мкс на 400 провинциях; ×3 — 513 мкс).
- Слот провинции стоит ≈ 7,8 мкс (было ≈ 4,5 мкс после T07): шаг налогов добавил ≈ 3,3 мкс — сборка входа, шесть налогов по пяти множителям, до 14 проводок `post_money` (по `tax_<группа>`, `embezzlement`, доля короны, доход хозяйства; нулевые проводки возвращаются сразу). Рост линеен по числу провинций (×3 → ×3,0). Замеры сняты на другой загрузке машины, чем у T07 (там p50 64 мкс на день), поэтому абсолютные числа сравнивайте по стоимости слота, а не по строкам.
- Месячного всплеска нет по построению (stagger `id % 28`): 1-е число стоит как обычный день слотов, дни 29…31 почти пусты.
- Население за прогон не изменилось относительно T07: 50 695 000 → 50 815 385 и 149 014 000 → 149 426 900 (налоги на людей не влияют; обратная связь «налог → настроение» — T11).

## Вывод

Превышений бюджета нет, issue `type:bug` `area:perf` не заводится. Следующие шаги `process_province` (контроль T10, настроения T11, рекруты T13) добавят стоимость; сводный замер — T23.
