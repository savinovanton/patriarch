# E9-T16: стоимость системы `economy.construction` (очередь стройки) и содержание зданий

> Дата: 2026-11-12. Задача: [E9-T16](../epics/E09-holdings-economy.md) (#159). Бюджет — [economy-model §14](../dev/economy-model.md): экономика за день на 400 провинциях **≤ 3 мс p95**; стройка при пустой очереди O(1), **< 10 мкс**; профиль ×3 — те же правила, жёсткого предела нет.

## Метод

Тот же, что в [E9-T13-recruits.md](E9-T13-recruits.md): `stressgen --profile year60|year60x3 --seed 7 --bench --bench-days 1500` на Release-сборке MSVC (`cmake --build --preset win-msvc-release --target stressgen`). Мир генерирует `stressgen --economy`, сохраняет, загружает и гонит 1500 дней (≈ 4,1 года) с каркасом систем E9-T05. Заглушка `economy.construction` теперь запускает **настоящую** систему (`make_construction_system`: `World::finish_due_constructions`), так что метрика `system.economy.construction` — её стоимость. Сгенерированный мир несёт очередь стройки (на 400 провинциях ≈ 190 записей, на 1200 ≈ 580; `tables_used_bytes/construction` 5580 и 17400 байт) и здания в слотах, поэтому за прогон часть записей действительно завершается, а содержание зданий в `economy.settlement` считается по настоящей сетке слотов через `UpkeepTable`. Второй прогон из того же мира даёт тот же хеш (`deterministic: true`), хеш загруженного мира равен хешу сгенерированного (`loaded_hash_equal: true`).

## Результаты (на день)

| Профиль | Провинций | `system.economy.construction` p50 / p95 / p99 / max, нс | `system.economy.provinces` p50 / p95 / p99 / max, мкс | `system.economy.settlement` (месячный) p50 / p95 / max, мкс | Тик в дни слотов 1…28, p50 / p95, мкс | Тик в дни 29…31, p50 / p95, мкс |
|---|---:|---|---|---|---|---|
| year60 | 400 | 0 / 100 / 100 / 200 | 164,1 / 255,6 / 270,4 / 456,2 | 21,2 / 31,5 / 34,9 | 166,2 / 253,8 | 0,3 / 0,5 |
| year60x3 | 1200 | 0 / 200 / 200 / 400 | 507,5 / 786,5 / 842,2 / 1022,9 | 94,2 / 126,1 / 131,0 | 506,8 / 784,9 | 0,4 / 1,0 |

- **Система стройки укладывается в бюджет с запасом ≈ 10⁴×:** худший день — 0,2 мкс на 400 провинциях и 0,4 мкс на 1200 при бюджете 10 мкс на пустую очередь. Цена — одно сравнение `finish_date[0] > today` (очередь отсортирована по дате готовности, до первой неготовой записи не доходит); на заполненной очереди тот же ответ, пока ничего не готово, а в день завершения добавляется по одной записи колонок на здание (`set_slot_building`, `log_incident`) и один сдвиг колонок очереди.
- **Бюджет экономики за день выполнен** (≈ 12× запаса на 400 провинциях: p95 255,6 мкс при 3 мс). Шагов слота T16 не добавляет: время `economy.provinces` в пределах шума прогона относительно T13 (222 мкс p95 тогда, 256 мкс сейчас — разница прогонов, не кода: тот же код слота).
- **Содержание зданий** (`economy.settlement`) считается за тот же проход по сетке слотов, что и до T16 (`UpkeepTable` строится из правил — восемь типов вместо одного, 256 записей таблицы остались): 21 мкс p50 / 31,5 мкс p95 на 400 провинциях при бюджете 5 мс.
- **Команды** `StartConstruction` / `CancelConstruction` выполняются на границе тика, по единицам в день: проверка просматривает слоты провинции (≤ 6) и очередь целиком (O(длина очереди), десятки–сотни записей), применение вставляет одну запись в колонки очереди (O(длина) сдвига) и делает одну проводку. На бюджет дня не влияет.
- Население за прогон то же, что в T13 (50 695 000 → 50 813 348 и 149 014 000 → 149 420 349): здания пока не меняют выпуск (эффекты — T17).
