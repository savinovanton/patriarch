## 1. Что здесь решено и что нет

Документ фиксирует **форму состояния и контракты**, а не баланс:

1. какие таблицы и колонки добавляет E10 в `World`, их типы, единицы, диапазоны, кто пишет и кто читает (§4);
2. какие деньги и проводки нужны, как устроены оклады, содержание слуг и подарки (§5);
3. в каком порядке и когда работают системы, потоки ГСЧ (§6);
4. команды: теги блока 128…143, поля, кто выпускает, `validate`, коды причин отказа (§7);
5. формулы: допустимость назначения, полезность императора, вес челобитной, милость, слуги, эффекты должностей — таблицами со значениями `[предл.]` (§8) и их `Breakdown` (§9);
6. события для E11 и интерфейсы к E9/E12/E14/E17/E20/E30/E31/E33/E34 (§10);
7. данные (§11), инварианты (§12), сейв, хеш, миграция, golden (§13), бюджеты (§14);
8. контракты моста «снапшот → UI» для окон «Двор» и «Слуги» (§15);
9. соответствие историям (§16), открытые вопросы (§17), правки других документов (§18), поправки к задачам T02…T21 (§19).

## 3. Типы и единицы

| Величина | Тип | Единица / диапазон |
|---|---|---|
| Деньги | `int64` (`economy::Kopecks`) | копейки; суммы E10 ≥ 0 (знак задаёт статья) |
| Даты | `Date` (`kNoDate` = нет) | юлианский календарь, дни |
| Очки полезности, штрафы | `int32` | «очки», усечение к нулю; веса — промилле (`_permille`, 1000 = ×1,0) |
| Милость | `int32` | сотые доли очка, 0…10 000 (`favor_x100`); в UI — `favor_x100 / 100` усечением |
| Лояльность слуги | `uint8` | 0…100 |
| Навык слуги | `uint8` | 0…20 (как у людей) |
| Идентификаторы | `u32` | `OfficeId`, `VacancyId`, `PetitionId`, `ServantId`, `DecisionSeq` — монотонные счётчики, **не переиспользуются**; `OfficeTypeId` — `u8` (`slot` из данных, 1…63, стабилен навсегда) |
| `locus` | `u32` | общие должности: номер места `0…slots−1`; региональные: `ProvinceId` (сырое значение) |
| Роли слуг (`ServantRole`) | `u8` | 1 `Steward`, 2 `Spy`, 3 `Secretary`, 4 `Guard`; 5…15 резерв (M2: наставник, лекарь, духовник, повар) |
| Партии (`PartyId`) | `u8` | 0 — вне партий, 1 `OldNobility`, 2 `NewService`, 3 `Church`; 4…7 резерв |

Строка «Двор» не использует `float/double`; целочисленное деление **усекает к нулю** (тест на границах, как у экономики).

## 4. Таблицы

Все таблицы живут в `World::court()` (`pat/sim/court/tables.hpp`, пространство имён `pat::sim::court`); API мутаций — только методы `World` (границы, ссылки, производные индексы), правил в типах нет. Без экономики и режима династии таблицы пусты; все команды E10 требуют режим династии (иначе `InvalidState`).

| Константа | Значение | Что ограничивает |
|---|---:|---|
| `kMaxOffices` | 512 | держаний (GDD 04 §14: «≤ ~300» — запас на региональные места) |
| `kMaxVacancies` | 128 | открытых вакансий |
| `kMaxPetitions` | 256 | челобитных в мире |
| `kMaxPetitionsPerDynasty` | 3 (данные) | одновременных челобитных рода |
| `kMaxServants` | 10 000 | слуг в мире (GDD 04 §5.1) |
| `kMaxDisgraces` | 256 | записей об опале |
| `kDecisionRingSize` | 32 | кольцо итогов решений императора |
| `kDecisionContenders` | 4 | претендентов в записи итога |

### 4.1 `CourtMeta` — счётчики и рынок слуг

| Поле | Тип | Смысл |
|---|---|---|
| `next_office_id`, `next_vacancy_id`, `next_petition_id`, `next_servant_id`, `next_decision_seq` | `u32` | счётчики, начинаются с 1; сохраняются, чтобы идентификаторы не повторялись |
| `market_month` | `i32` | месяц текущего зерна рынка: `(год − 1600)·12 + (месяц − 1)`; `−1` — рынка ещё нет |
| `market_seed` | `u64` | зерно рынка кандидатов в слуги (§8.7) |

### 4.2 `OfficeTable` — занятые места (держания)

Строки по возрастанию `id`. `≤ kMaxOffices`.

| Колонка | Тип | Смысл |
|---|---|---|
| `id` | `u32` | `OfficeId` |
| `type` | `u8` | `OfficeTypeId` (слот типа из данных) |
| `locus` | `u32` | место внутри типа (см. таблицу §3) |
| `holder` | `CharacterId` | держатель; **не пуст** (место без держателя — вакансия, §4.4) |
| `appointer` | `DynastyId` | род, чьей волей назначен; невалиден — системное назначение (сценарий, событие) |
| `since` | `Date` | дата назначения |
| `patron` | `CharacterId` | кто выдвинул (глава рода-подавшего при назначении по челобитной); невалиден — нет. Заготовка клиентелы E20 |
| `flags` | `u8` | бит 0 — **«в исключительном порядке»** (держатель не удовлетворяет мягким требованиям), бит 1 — назначен сценарием/системой, бит 2 — `locus` есть `ProvinceId` (место региональной должности; ставит пишущий по правилу мест типа, нужен индексу `offices_by_province_` без правил; E10-T02) |

Уникальность: пара `(type, locus)` встречается не более одного раза; один человек держит не более `max_offices_per_person` мест (данные, 1 в M1).

Производные индексы (не сохраняются, пересобираются в `rebuild_derived_indexes()`): `office_by_holder_` (персонаж → `OfficeId`), `office_by_seat_` ((тип, locus) → `OfficeId`), `offices_by_province_`.

**Места (seats).** Множество мест вычисляется из данных и мира, а не хранится:

| Правило мест (`seats.rule` в данных) | Какие места существуют |
|---|---|
| `fixed` | `locus = 0 … slots−1`, постоянно (спальник, денщик, воспитатель, управитель двора, полковники, генералы, Посольский приказ, казначей, боярин Думы, фаворит) |
| `per_crown_province` | по одному на каждую провинцию с `OwnerKind::Crown`, подходящего вида (`kinds`), не более `max` (воевода — сельские и городские, комендант — города) |
| `listed` | перечисленные сценарием провинции (губернатор; список — `data/scenarios/<id>/court.pd`, E30-T06) |

Место «открыто», если выполнено окно дат (`from_date ≤ сегодня ≤ to_date`; пустая граница — без ограничения). Место исчезает, когда провинция перестаёт быть государевой или выходит из списка: держатель снимается (`ResignOffice{SeatClosed}`).

### 4.3 `DisgraceTable` — опала

Строки по возрастанию `character`, `≤ kMaxDisgraces`.

| Колонка | Тип | Смысл |
|---|---|---|
| `character` | `CharacterId` | человек в опале |
| `until` | `Date` | до какого дня (`≥ since`; бессрочной опалы в M1 нет — «нет вечных опал», US-10.4) |
| `reason` | `u8` | 1 воля государя, 2 по итогам расследования/заговора (E12/E14), 3 событие (E11) |

Опала — **состояние человека**, а не должности: пока `until > сегодня`, человек недоступен для любых должностей (причина `Disgraced`). Снимает `court.holders` командой `EndDisgrace` по сроку; пока опала действует, у человека черта `disgraced`.

### 4.4 `VacancyTable` — открытые вакансии

Строки по возрастанию `id`, `≤ kMaxVacancies`. Инвариант: для каждого **открытого** места либо есть держание, либо есть вакансия (допускается расхождение до следующего ежемесячного скана мест).

| Колонка | Тип | Смысл |
|---|---|---|
| `id` | `u32` | `VacancyId` |
| `type`, `locus` | `u8`, `u32` | место |
| `opened` | `Date` | когда открыта |
| `decide_by` | `Date` | когда государь решает (`opened + decision_delay_days`, 30…90 дней по должности) |
| `reason` | `u8` | 1 новое место, 2 держатель умер, 3 ушёл сам, 4 снят, 5 пострижен, 6 стал недопустимым, 7 реформа/сценарий |
| `previous_holder` | `CharacterId` | прежний держатель (может быть архивным) |
| `postponed` | `u8` | сколько раз решение отложено (§8.3) |

### 4.5 `DecisionRing` — итоги решений (кольцо 32)

Для тултипа «чего не хватило» и разбора «почему не мой кандидат» (US-10.1): по умолчанию состояние хранит результат, а не пересчитывает его (кандидаты и мнения за это время меняются).

| Колонка | Тип | Смысл |
|---|---|---|
| `seq` | `u32` | порядковый номер (`next_decision_seq`) |
| `vacancy` | `u32` | исторический `VacancyId` |
| `type`, `locus` | `u8`, `u32` | место |
| `decided` | `Date` | дата решения |
| `result` | `u8` | 1 назначен, 2 отложен, 3 некого назначать |
| `n` | `u8` | претендентов `0…4` (победитель — первым; далее — до трёх ближайших по полезности, **среди них — все челобитные игрока**, если их не больше места) |

## 5. Деньги

### 5.1 Новых кодов ведомости нет

| Поток | Кто платит → кому | Проводки | Условие |
|---|---|---|---|
| **Оклад должности** (ежемесячно, 1-го числа) | корона → род держателя | `transfer(Crown, holder_dynasty, salaries_out 104, salaries_in 12, salary_kop)` — **новая пара** в `kLedgerPairs` (T10) | держал место на 1-е число; казна короны может уйти в минус (государство в долг — состояние E9/E12, не причина не платить); держатель из рода-короны — без проводки |
| **Содержание слуг** | род → никому | строка `court_upkeep (103)` в `ExpenseSource` рода: `Σ wage_kop` слуг, нанятых **раньше** закрываемого месяца (месяц найма покрывает разовая плата) | при закрытии месяца (`economy.settlement`); долг разрешён (остаток может уйти в минус) |
| **Разовая плата при найме** | род → никому | `post_money(dynasty, court_upkeep, −fee_kop)`, `fee_kop = 2 × wage_kop` | `can_afford(fee)` в `validate` («Не хватает N ₽», доска 59) |
| **Подарок при челобитной** | род → корона | `post_money(dynasty, gifts_bribes 106, −gift)` затем `post_money(Crown, grants_in 13, +applied)` — `applied` равна фактически списанной сумме | `can_afford(gift)`; подарок **не возвращается** (кроме §5.2) |
| **Подарок императору** (`GiftToEmperor`) | род → корона | те же две проводки | `can_afford` |
| **Возврат** подарка при снятии челобитной системой (кандидат выбыл, место закрыто) | корона → род | `post_money(dynasty, gifts_bribes, +gift)`, `post_money(Crown, grants_in, −gift)` | 1000‰ `[предл.]`; при добровольном отзыве — 0‰ |

### 5.2 Правила и почему так

- **Пара `104 ↔ 12`.** Оклад — структурный повторяющийся поток между двумя счетами; пара гарантирует закон сохранения (E-M3: сумма двух линий по всем счетам равна нулю даже при насыщении — `transfer` двигает меньшую из сумм). После добавления пары `post_money(…, SalariesOut/SalariesIn, …)` вне `transfer` — ошибка (`PAT_ASSERT`); сегодня никто эти коды не проводит (в M1 источников нет), поэтому поведение прежнее. `kLedgerPairs` в хеш **не входит**.
- **`gifts_bribes` остаётся одиночным** кодом: E14 тратит его на взятки слугам и чиновникам, у которых нет счёта; потому подарок императору — две независимые проводки с одной суммой (дебет рода, кредит короны на **фактически списанную** величину). Тест E10: сумма подарков за 50 лет = Δ `grants_in` короны.
- **Режим одной казны (Q7 `EmperorDynasty`)**: `resolve_account(Crown)` возвращает счёт рода `crown_dynasty`; все проводки E10 остаются верными, при совпадении сторон (род-корона платит сам себе) проводка пропускается.
- **Без экономики** (`economy_present() == false`): оклады, плата за найм и подарки не проводятся, `can_afford = true`, числа хранятся как данные (образец E8).
- **Хеш:** ни одной новой строки ведомости → `kLegacyLedgerLines` и хвост «новых кодов» хеша счетов E8-T03 не нужны; golden экономики и `simcli_m1` не двигаются (F5, §13.3).

### 5.3 Прогноз и просрочка

- `court_monthly_forecast(world, rules, dynasty) → {salaries_in_kop, servant_wages_kop, breakdown}` — одна функция для моста (Breakdown 14600): прогноз «Казна» показывает «Содержание двора» (`court_upkeep` — уже через `ExpenseSource` и прогноз E9) и «Жалованье» (`salaries_in`) отдельной строкой моста.
- **Просрочка**: после закрытия месяца (`economy.settlement` 1-го числа) система `court.servants` смотрит остаток счёта рода: `treasury < 0` → у **каждого** слуги рода `arrears += 1`, лояльность падает (§8.7), милость рода — на `arrears_favor` (§8.5); остаток ≥ 0 → `arrears = 0`. Оклады должностей не бывают в просрочке (платит корона, §5.1).

## 6. Время: системы, порядок, очереди, случайность

### 6.1 Системы E10

Ставятся **двумя** функциями, потому что часть систем должна видеть уже закрытый месяц экономики:

- `install_court_systems(simulation, rules, emperor)` — после систем E7/E8 и **до** `economy.*`;
- `install_court_ledger_systems(simulation, rules)` — **после** `economy.settlement` (Monthly, 1-е число): работают над закрытыми книгами.

До E10-T20 в `dynasty.v1`/M1 не входят; каждая система — без собственного состояния (всё в `World`), эффекты — внутренние команды (применяются в начале следующего тика).

| № | Имя | `Cadence` | Когда | Что делает |
|---:|---|---|---|---|
| 1 | `court.holders` | Daily | до `economy.*` | обходит `OfficeTable`, `PetitionTable`, `DisgraceTable`, `ServantTable` (малые): держатель мёртв/пострижен/лишён прав/недопустим по типу (мужской пол, возраст) или место закрыто → `ResignOffice{Died/Tonsured/Ineligible/SeatClosed}`; челобитная с выбывшим кандидатом/закрытой вакансией → `WithdrawPetition{CandidateGone/VacancyClosed}`; `until ≤ today` → `EndDisgrace`; слуга вымершего рода → `FireServant{DynastyExtinct}`, слуга старше `retire_age` → `FireServant{Retired}` |
| 2 | `court.vacancy` | Daily | до `economy.*` | (a) **решение**: для вакансий с `decide_by ≤ today` в порядке `id` — собирает кандидатов (§8.2), считает полезность и выпускает `DecideAppointment`; (b) **ежемесячный скан мест** в день 2 месяца (после ежедневного прохода 1): для открытых мест без держателя и вакансии — `OpenVacancy{NewSeat}` |
| 3 | `court.ai` | Daily | до `economy.*` | ИИ-род по слоту `is_monthly_slot(dynasty.index, today)`: не более одной челобитной за слот (§8.9); для рода игрока ничего не делает (`player_dynasties`, E11 §10.3) |
| 4 | `court.market` | Monthly | до `economy.*` | **единственное** обращение к ГСЧ E10: одно извлечение `next_u64()` из потока `court.market`, команда `SetServantMarket{month, seed}` |
| 5 | `court.pay` | Monthly | до `economy.settlement` (1-е число) | оклады: для каждого рода с держаниями `transfer(Crown → род, 104, 12, Σ salary)`; в закрываемый месяц, потому что идёт до закрытия |
| 6 | `court.servants` | Monthly | **после** `economy.settlement` | просрочка, дрейф лояльности (§8.7), уход слуг после `quit_after_months` (`FireServant{Quit}`), ежемесячные `AdjustServantLoyalty` (только ненулевые дельты) |
| 7 | `court.favor` | Monthly | **после** `economy.settlement` | пересчёт милости каждого рода со строкой или с держаниями/слугами: `AdjustFavor` (только ненулевые дельты) с разложением 14200 |

Порядок «обход малых таблиц → решения → ИИ → рынок → оклады → (экономика) → слуги → милость» нужен, чтобы ИИ видел сегодняшние вакансии, оклады шли в закрываемый месяц, а просрочка и милость читали закрытые книги. Все обходы — по возрастанию ключа; параллельное исполнение не используется (`SerialExecutor`).

### 6.2 Очереди и даты

Очередей-индексов E10 **не заводит**: таблицы малы. Даты срабатывания — **значения в строках** (`decide_by`, `until`); «ровно в срок» = первый запуск системы с `дата ≥ срок`; повторно строка не обрабатывается, потому что команда-результат удаляет или двигает её (`DecideAppointment` удаляет вакансию или двигает `decide_by` при отсрочке). Ничья на один день — по возрастанию `id`.

Сейв **мира** между выпуском внутренней команды и её применением теряет её (ADR-0006 S4); продолжение восстановит её на следующий день: состояние в таблицах не изменилось. Сейв **симуляции** несёт `pending_internal`.

### 6.3 Реакции на смерть, пострижение, вымирание (D10)

| Событие | Кто и когда | Что |
|---|---|---|
| Умер/пострижен/лишён прав держатель | `court.holders`, не позже следующего дня | `ResignOffice{reason}` → держание удалено, вакансия открыта, `on_office_removed` |
| Умер/выбыл кандидат челобитной | `court.holders` | `WithdrawPetition{CandidateGone}`; подарок возвращается (1000‰) |
| Умер глава рода-подавшего | не реагирует: челобитная — акт рода, кандидат остаётся | — |
| Род вымер | `court.holders` | слуги: `FireServant{DynastyExtinct}`; строка милости/партии удалена; челобитные рода сняты |
| Провинция перестала быть государевой | `court.holders` (место закрыто) | `ResignOffice{SeatClosed}`; управитель провинции снимается методом `World` |
| Умер фаворит | как держатель | `RevokeTrait emperor_favorite` внутри `ResignOffice.apply`; хук «падение фаворита» (§10.3) |

`check_invariants` разрешает «умершего держателя» не дольше одних суток (как мнения в ADR-0006 D1 и регент в E8 M-5).

### 7.2 Общие правила `validate` / `apply`

1. Отказ — `Rejection` (`UnknownEntity`, `NotAuthorized`, `InvalidArgument`, `InvalidState`) + `detail` + `code` (`CommandError.code`, E8-T04): `code` — первая причина из `CourtDenial` (§7.3); **полный список** даёт чистая функция (`check_office_eligibility`, `check_petition`, `check_hire`), которую вызывает UI.
2. `apply` предполагает пройденную `validate` против того же состояния, ничего не решает случайно и не проверяет заново; все эффекты — детерминированная бухгалтерия: создаёт/удаляет строки, вызывает методы `World` (честь, мнения, черты, управитель провинции, проводки), пишет летопись.
3. Деньги: расход списывается ровно теми проводками §5.1; проверка средств — в `validate` (`can_afford`) по **тем же** функциям, что показывает UI.
4. Все команды E10 — только в режиме династии; без правил двора (`CourtRules` не установлены) — `InvalidState`.
5. Журнал: каждая принятая команда E10 попадает в журнал тика; E11 строит из журнала on-action (§10.1).

## 8. Формулы и правила (данные `[предл.]`)

### 8.1 Допустимость назначения `check_office_eligibility` (T05)

Чистая функция `(world, rules, type, locus, candidate, context) → DenialSet` (до 8 записей `{код, a, b}`, порядок — по возрастанию кода). `context` — кто спрашивает (император, род-подавший, система) и дата.

| Требование (поле данных) | Причина | Жёсткое / мягкое | Примечание |
|---|---|---|---|
| живой, не архивный | `NotAlive` | жёсткое | |
| `min_age` (лет) | `TooYoung` | **жёсткое** | возраст — по дате рождения и сегодня |
| `sex_allowed` (`male` в M1) | `SexNotAllowed` | жёсткое | предикат из данных (E8 §10.3, Q2 #360) |
| `min_honor` (честь рода) | `RankTooLow` | **мягкое** | «ранг» M1 = честь рода (GDD 04 §4.5); поле `rank_min` под Табель о рангах (E33) зарезервировано |
| `skills { skill = N }` (минимум по навыкам) | `SkillTooLow` | **мягкое** | по каждому навыку — отдельная запись (`a` — `Skill`, `b` — N) |
| `not_traits` | `ForbiddenTrait` | жёсткое | |
| пострижен / лишён прав (`PersonStatusTable`) | `Tonsured`, `Disowned` | жёсткое | |
| опала (`DisgraceTable`) | `Disgraced` | жёсткое | |
| вера (`faith`) | `FaithMismatch` | жёсткое | **заглушка** `FaithPolicy` E31: в M1 всегда проходит |
| не более `max_offices_per_person` | `AlreadyHoldsOffice` | жёсткое | фаворит не считается (тип `favourite` совмещаем с одной другой должностью) |
| малолетний глава рода (`age < 16` и `head`) | `ChildHead` | жёсткое | |
| окно дат типа | `DateWindowClosed` | жёсткое | проверяется на уровне места, не человека |

**«В исключительном порядке».** Назначение с флагом `exceptional` разрешает **только мягкие** причины, и не больше `exceptional_max_honor_gap` (200 `[предл.]`, одна ступень ранга) по чести и `exceptional_max_skill_gap` (3) по каждому навыку; в полезности тогда вычитается `exceptional_penalty` (§8.2). Такие держания помечаются битом 0 в `OfficeTable.flags` и показываются в UI. Сценарий и события могут назначать системой с флагом без этих пределов (E30-T06).

### 8.2 Решение императора: кандидаты и полезность (T07)

**Кандидаты на вакансию:**

1. Все **челобитные** на вакансию (кандидат — по челобитной).
2. Дополнительно — **собственный выбор** государя: из всех живых совершеннолетних персонажей, подходящих по §8.1 (в системе — один проход по `living()` по возрастанию id), отбираются **не более `candidate_prefilter` (16)** лучших по ключу `prefilter_key = Σ skill_weights[type][s]·skill_s + honor/10` (ничья — по id). Персонаж рода игрока, у которого милость ниже `self_nomination_min_favor` (40), собственным выбором **не назначается** (не втягиваем игрока в должности без его участия при плохой милости).
3. Если подходящих нет ни по челобитным, ни по собственному выбору — результат `3` (некого); после `relax_after_days` (180) вакансии допускаются **мягкие** отклонения по §8.1 в пределах «исключительного порядка» — «нет вечных вакансий» (US-10.4).

**Полезность** `U(c) = Σ_{i=1..8} T_i` — восемь слагаемых в очках (`Breakdown 14000`, индекс `terms[i−1]`):

| i | Слагаемое | Формула | Знак/диапазон `[предл.]` |
|---:|---|---|---|
| 1 | `ability` способности | `Σ_s w[type][s]·skill_s(c)` (навыки `0…20`; `w` — очки за уровень навыка, в данных должности) | 0…≈ 90 |
| 2 | `attitude` расположение | `favor_pt(c.dynasty)·favor_weight_permille/1000 − suspicion_pt(c.dynasty)·suspicion_weight_permille/1000`; `favor_pt = favor_x100/100`; `suspicion_pt` — E12 (до E12 — 0) | 0…30 |
| 3 | `opinion` личное мнение | `opinion(император → c)·opinion_weight_permille/1000` (−100…100 → −20…20) | −20…20 |
| 4 | `rank` честь и «исключительность» | `clamp(honor(c.dynasty)/honor_per_point, 0, rank_cap) − exceptional_penalty·[исключит.]` | −20…20 |
| 5 | `party_balance` баланс партий | `party_balance_points·(1000/3 − share_pm(party(c.dynasty)))/(1000/3)` (зажим ±`party_balance_points`); `share_pm` — доля держаний двора у партии в промилле; без партии — 0 | −15…15 |
| 6 | `gift` подарок | `min(gift_cap, gift_kop/gift_unit_kop)` (`gift_unit_kop = 5000`, `gift_cap = 25`) | 0…25 |
| 7 | `service` услуга | `service_points` (15) если флаг услуги | 0 / 15 |
| 8 | `patronage` поддержка | `party_support_points·cohesion_pm(party)/1000` при флаге партии + `favourite_points` (12), если род-подавший держит место фаворита | 0…22 |

Слагаемые 6–8 бывают только у кандидатов по челобитным; у собственного выбора они 0. Целочисленное деление **усекает к нулю**; все веса — в данных (`court_balance`, должность). **Ничья:** `(U ↓, honor рода ↓, CharacterId ↑)`.

**Решение (в `court.vacancy`, день `decide_by`):**

- победитель = максимум `U`;
- если `U_max < min_utility` (20) и `postponed < max_postponements` (2) — `result = 2` (отложено на `postpone_days` = 30);
- иначе `result = 1` (назначен), даже при низкой полезности («некого лучше» — вакансия не вечна).
- В кольцо попадают победитель и до трёх ближайших; **все челобитные игрока на эту вакансию** включаются всегда (если мест в записи не хватает — вытесняется ближайший не-игрок), чтобы тултип «чего не хватило» объяснял исход (US-10.1).

### 8.3 Задержка и последствия отказа

- `decision_delay_days` по типу — 30…90 (из данных; придворные дольше, региональные короче `[предл.]`).
- Последствия отвергнутым (§7.5): `AdjustOpinion(кандидат → император, −reject_opinion = −8, 301)` (если у кандидата есть место в таблице мнений ≤ 30 записей — как у E7), подарок не возвращается; победителю — `+grant_opinion = +5` (302), рода — `+favor_on_grant = +2,00` милости.
- Кулдаун: **челобитная того же рода на ту же вакансию** после отказа невозможна (вакансия удалена); на следующую вакансию — свободно.

### 8.4 Вес челобитной «до отправки» (T08, US-10.1)

Функция `petition_preview(world, rules, vacancy, candidate, gift_kop, flags) → {eligibility: DenialSet, utility: Breakdown 14000, rank_among: список (кандидат, U) по текущему состоянию, shortfall: подсказка}`. Применение (`DecideAppointment`) считает тем же кодом `utility` над теми же входами (**тест «показанное = применённое»**: при неизменном состоянии разложение в превью равно разложению в кольце). Подсказка «чего не хватило» — сравнение слагаемых кандидата игрока с **текущим лидером** по каждому слагаемому (разность терминов, отсортированная по убыванию отставания) и «стоимость недостающего»: сколько рублей подарка закрыли бы разрыв `(gap·gift_unit_kop)` (с зажимом `gift_cap`). Превью — прогноз: решение произойдёт в `decide_by` по состоянию на тот день; тултип говорит «на сегодня».

| Подкрепление M1 | Как работает | Лимит / цена |
|---|---|---|
| Подарок | слагаемое 6; деньги списываются при подаче | `gift_max_kop` (по умолчанию 100 000 коп = 1000 ₽); не возвращается |
| Услуга | слагаемое 7; тратит `services` | 1 на челобитную; максимум `services_max = 5` |
| Поддержка партии | слагаемое 8; запоминает `party_support_on` | не чаще раза в `party_support_cooldown_days` (365); нужна партия |
| Компромат | зарезервировано (`evidence`), в M1 не используется | E14 |

Источник «услуг» и UI подкреплений — вопрос [#509](https://github.com/savinovanton/patriarch/issues/509).

### 8.5 Милость `favor` (T14)

Помесячный пересчёт: система `court.favor` для каждого рода из `FavorTable` ∪ {род с держаниями ∪ род со слугами} выпускает `AdjustFavor` с суммой слагаемых (разложение — `Breakdown 14200`):

| Слагаемое | Формула `[предл.]` |
|---|---|
| 14201 `pull` — тяга к базе | `(base − favor_x100)·pull_permille/1000`, `base = favor_base_x100 + opinion(император → глава рода)·opinion_to_favor_x100` (средняя милость 50; симпатия императора ±25 очков при `opinion_to_favor_x100 = 25`), `pull = 100‰` |
| 14202 `service` — служба | `+service_per_office_x100` за каждое держание рода (300 = +3,00), но не больше `service_cap_x100` |
| 14203 `quota` — квоты E9 | `+quota_met_x100` (100), если прошлый месяц квота выполнена; `−quota_short_x100` (500), если `QuotaShort` (E9-T14; до E9-T14 — 0) |
| 14204 `favourite` | `+favourite_monthly_x100` (150) роду, чей член — фаворит |
| 14205 `arrears` — просрочка | `−arrears_favor_x100` (200) пока у рода есть слуги в просрочке |
| 14206 `disgrace` — опала | `−disgrace_favor_x100` (300) за каждого члена рода в опале |
| 14207 `suspicion` — подозрение | `−suspicion_pt·suspicion_to_favor_x100` (20); E12 (до E12 — 0) |

Итог за месяц зажимается `±favor_month_cap_x100` (600). Подарок и награды за назначение — **не** через `court.favor`, а своими командами (§8.6, §8.3). Порог «милость высокая/низкая» для `on_favor_threshold` — 8000/2000 (данные); `crossed` вычисляет **эмитирующая** система из состояния на момент выпуска.

Значение «милости рода» читают: слагаемое 2 полезности, E9 (порог займов, `World::court_favor_x100(dynasty)` — аксессор по умолчанию 5000), E12 («авторитет», защита при расследовании, `Denounce`).

### 8.6 Подарок императору (T14)

`gift_points_x100 = min(gift_per_100_rub_x100 · amount_kop / 10 000, gift_month_cap_x100 − gift_points_x100_this_month)` (`gift_per_100_rub_x100 = 25` — +0,25 очка милости за 100 ₽ `[предл.]`; `gift_month_cap_x100 = 1000` — потолок +10 очков в месяц); перерасход подарка сверх потолка **принимается**, но милости не даёт (`Breakdown 14100`: `gross`, `capped`, `result`). Мост показывает «милость +N» **до** отправки (одна функция `gift_preview`).

### 8.7 Слуги (T12, T13)

**Рынок кандидатов.** В начале каждого месяца `court.market` кладёт в мир зерно (`SetServantMarket`). Кандидат — **чистая функция** `market_candidate(seed, dynasty, role, index) → {name, sex, birth_year, skill, loyalty, wage_kop, fee_kop, portrait}` через целочисленный хеш `h = mix64(seed, dynasty, role, index)` (разные роды видят разных людей; повторных запросов в течение месяца одинаковый результат):

| Поле | Формула `[предл.]` |
|---|---|
| `skill` | `role.skill_min + h₁ mod (role.skill_max − role.skill_min + 1)` (6…15) |
| `loyalty` | `40 + h₂ mod 41` (40…80) |
| `birth_year` | `год − (20 + h₃ mod 30)` |
| `wage_kop` | `wage_base_kop + skill·wage_per_skill_kop` (500 + 100·навык: навык 13 → 18 ₽) |
| `fee_kop` | `fee_months · wage_kop` (2 месяца: 36 ₽ при окладе 18 ₽) |
| `name`, `sex`, `portrait` | пул имён E7-T09 по `h₄…h₆`; роль «шпион» и «секретарь» — любой пол по данным (M1 — мужской) |

Макеты 58/59 показывают трёх кандидатов («Хозяйство 13 · Лояльность 62 · 18 ₽ / мес.») — `index = 0…2`; значения на досках — примеры, не контракт.

**Найм.** `HireServant{role, index}` создаёт слугу; число слуг роли ≤ `slots(role)` (в M1 — 1, D17); эффект роли и плата — из данных роли.

**Роли и эффекты M1.**

| Роль | Навык | Эффект M1 | Задел |
|---|---|---|---|
| `Steward` (управляющий) | Хозяйство | `+steward_control_per_skill_x100·(skill − 10)` пунктов контроля и `−steward_corruption_per_skill_permille·(skill − 10)` ‰ коррупции во **всех** провинциях рода **без** назначенного управителя и `+половина` в провинциях с управителем (T13: узкая правка E9 — вход «модификаторы персонала» рядом с модификаторами зданий; нулевой, пока нет управляющих) | — |
| `Spy` (шпион) | Интриги | нет | исполнитель схем E14 |
| `Secretary` (секретарь) | Учёность | нет | бумаги, ускорение схем E14 |
| `Guard` (телохранитель) | Воинское дело | нет | защита от убийств E14 |

**Лояльность** (помесячно, `court.servants`; `Breakdown 14400`):

| Слагаемое | Формула `[предл.]` |
|---|---|
| 14401 `pull` | `(loyalty_base − loyalty)·loyalty_pull_permille/1000`, база 60, 100‰ |
| 14402 `paid` | `+paid_bonus` (1) за месяц без просрочки |
| 14403 `arrears` | `−arrears_loss` (8) за месяц просрочки |
| 14404 `events` | дельты E11 (`adjust_servant_loyalty`), не месячные |

«Ненадёжен» — `loyalty < unreliable_below` (35). После `quit_after_months` (3) просрочки слуга уходит (`FireServant{Quit}`). Слуга старше `retire_age` (65) уходит на покой.

**Вероятность предательства** (задел E14; чистая функция, потребителя в M1 нет): `betrayal_permille(loyalty, bribe_kop, secrecy) = clamp(betrayal_base + loyalty_gap·betrayal_per_gap + bribe_kop/betrayal_bribe_unit_kop·betrayal_per_unit − secrecy·betrayal_per_secrecy, 0, 1000)`, `loyalty_gap = max(0, 50 − loyalty)`; **монотонна** по росту суммы подкупа и убыванию лояльности и убывающая по скрытности (тест монотонности).

### 8.9 ИИ-челобитные `court.ai` (T16)

Род ИИ по слоту `is_monthly_slot(dynasty.index, today)`: из **открытых** вакансий (отсортированных по `id`) берётся первая, для которой в роде есть кандидат с `U ≥ ai_min_utility` (25); из членов рода кандидат — максимум `U` (ничья — id); подарок `gift = min(ai_gift_permille · treasury/1000, ai_gift_cap_kop)` (50‰, 30 000 коп) если разрыв с лидером положителен и род не в долгу; услуга и партия используются, если разрешены и закрывают разрыв. Один шаг за слот, без ГСЧ; число решений ИИ ≤ 1 мс/кадр (бюджет эпика §6.5). Утилити-ИИ E17 заменит систему на тех же командах.

### 8.10 Партии `party_standing` (T15)

- `party_weight(dynasty) = party_base_weight + clamp(honor, 0, party_honor_cap)/party_honor_div` (100 + честь/10 `[предл.]`);
- `party_strength(p) = Σ party_weight(d)` по родам-членам; **доля** `share_pm(p) = party_strength·1000/Σ_all` (доли округляются для UI методом наибольшего остатка, сумма — 100%);
- `cohesion_pm(p) = clamp(500 + mean_{a≠b ∈ члены}(opinion(head_a → head_b))·5, 0, 1000)` (родов ≤ 100; пары ограничены `cohesion_pair_cap` = 200);
- «повестка» — только текст `court.party.<id>.agenda` (на доске: «против реформ», «за службу и реформы», «права Церкви»); членство задаёт сценарий (`AssignParty`); в M1 вступления/выхода нет.

### 8.11 Опала и снятие (T11)

`DismissOffice{reason = 2, disgrace_days > 0}`: запись в `DisgraceTable` (`until = today + disgrace_days`, ≤ `disgrace_max_days` = 730 `[предл.]`), `GrantTrait disgraced`, `AdjustHonorWithReason(302)` дому, мнение держателя к императору, `favor −disgrace_one_off_x100` (500). Ссылка, конфискация, пострижение — **не** E10: хуки (§10.3) для команд E12/E14/E8. Падение фаворита: после `ResignOffice`/`DismissOffice` типа `favourite` журнал даёт `on_office_removed` (причина → E11); цепной чистки клиентов нет (E20).

### 13.2 Хеш и версия схемы

- **Части хеша** (`ExtPart`, блок 32…39, F4): 32 `CourtMeta` (раздел 64: счётчики и зерно рынка), 33 `CourtOffice` (65), 34 `CourtVacancy` (66, вместе с кольцом), 35 `CourtPetition` (67), 36 `CourtServant` (68), 37 `CourtFavor` (69), **39 `CourtPortfolio` (разделы 70 и 71 вместе)** (E10-T22; 38 занят E7-T25 `Feud` — house-relations-model.md; блок исчерпан). Часть **0 и вне `total`**, пока её данные по умолчанию; FNV по строкам в порядке хранения. Мир без данных E10 имеет прежний `total`.
- **`kStateSchema`:** один подъём в T03 — **следующий свободный номер на момент слияния** (сейчас 12; E11-T03 в очереди раньше E10-T03, возможно 13): единая схема для всех таблиц E10. Контейнер `PSV1` v2 не меняется; последующие изменения байтов — отдельным подъёмом по ADR-0011 §7.
- **Ключ сводки:** `22 court_hash` (u64, необязательный) — `CourtRules::hash()`, пишется только если системы двора установлены (T20); отсутствует — партия без двора.
- **Миграция «N−1 → N»:** пустые таблицы E10, `next_* = 1`, `market_month = −1`; ledger-раздел старого файла читается как есть (новых кодов нет). Шаг — типизированный, над загруженным миром.
- **Фикстуры:** `dynasty_vN-1_court.psv` (создаётся **кодом `main` до изменения формата**, генератор и хеши рядом, как `dynasty_v11_e8_economy.psv`) и `dynasty_vN_court.psv` (непустые таблицы: держания, опала, вакансия с кольцом, челобитная с подарком, слуги, милость и партия). Старые байты неизменны; повторный round-trip текущей схемы стабилен побайтно.
- Корпус порчи (E13-T11): усечения, битые перечисления, раздутые счётчики для **каждого** из разделов 64…69.
- **Сделано (E10-T03, схема 14):** `src/sim/world_court_io.cpp` — разделы 64…71 и 10 (влияние), части хеша 32…37, 39, 40; читатель проверяет форму, границы и строгий порядок ключей, остальное (перечисления, ссылки, счётчики, `market_month ≥ −1`, режим династии) — `check_invariants()` после загрузки (C-1…C-16, I-1…I-3). ### 15.3 Контракты и риски моста

1. **Команда в паузе** — как у E8: решение владельца Q8.7 [#489](https://github.com/savinovanton/patriarch/issues/489) (рекомендация: один тик, `Runner::step(1)`); до решения мост показывает `Submitting` до следующего снапшота.
2. **Превью = применение.** `petition_preview`, `hire_preview`, `gift_preview` — те же функции, что `validate`/`apply`; тесты «показанное = применённое».
3. **Дата в макете** (1 января 1708 при старте 1703) — иллюстрация; мост всегда берёт дату снапшота.
4. **Имена:** имя слуги — `StringId` из пулов; склонения «Семён Андреев» — E7-T09.
5. **Ширина:** `holders[]` ограничивается 3 в строке, полный список — в детали (воеводы по десяткам провинций не вытесняют таблицу).

### 20.3 Типы и единицы

| Величина | Тип | Единица / диапазон |
|---|---|---|
| `PortfolioId` (тип портфеля) | `u8` | совпадает со слотом типа должности (`OfficeTypeId`); портфель — необязательное свойство типа |
| `course` | `u8` | `0…7`; 0 — умолчание типа (по данным может быть другой индекс, `default_course`) |
| `order` | `u8` | `0…3` (`kMaxOrdersPerPortfolio = 4`) |
| `state` | `u8` | 1 `Active` (держатель есть), 2 `Inertia` (место пусто, курс действует), 3 `Rollback` (курс шагает к умолчанию) |
| Давление | `i32` | очки ×100 (`pressure_x100`); полосы 0…3 (`PressureBand`) |
| Шум | `i16` | сотые доли очка давления; затухает за `heat_days` |
| Сила, исполнение | `i16`/`u16` | промилле |
| Домен портфеля (`domain`) | `u8` | 1 `Treasury` (E9), 2 `Education` (E7), 3 `Province` (E9/E10), 4 `Inquiry` (E12/E14, **M2**: тайная канцелярия, #517), 5 `Army` (E15, M2), 6 `Diplomacy` (E18, M2), 7 `Church` (E31, M2), 8 `Navy` (E16, M2) |
| Вид цели (`target_kind`) | `u8` | 0 нет, 1 род, 2 провинция, 3 персонаж |
| Вид цены | битовая маска | бит 0 деньги (коп.), бит 1 милость (сотые), бит 2 услуги (после #509) |

Целочисленное деление усекает к нулю; дельты зажимаются границами получателя (не отказ), если не сказано иное.

### 20.4 Таблицы

Живут в `World::court()` рядом с таблицами §4 (`pat/sim/court/portfolio.hpp`); мутации — методы `World`. Без правил портфелей (`PortfolioRules` не установлены) таблицы пусты и команды дают `NoCourtRules`.

| Константа | Значение | Что ограничивает |
|---|---:|---|
| `kMaxPortfolios` | 32 | строк `PortfolioTable` (M1: ≤ 8; губернаторские места по списку сценария ≤ 8, плюс 3 ведомства) |
| `kMaxOrdersPerPortfolio` | 4 | приказов на тип |
| `kOrderRingSize` | 64 | кольцо приказов (мир целиком) |

**`PortfolioTable`** — строки по возрастанию `(type, locus)`, ≤ 32:

| Колонка | Тип | Смысл |
|---|---|---|
| `type`, `locus` | `u8`, `u32` | место (как §4.2) |
| `course` | `u8` | выбранный курс |
| `course_since` | `Date` | когда выбран (для `course_change_cooldown_days`) |
| `controller` | `DynastyId` | род **текущего или последнего** держателя (в `Inertia`/`Rollback` — последнего); определяет, кто может ставить курс и приказы |
| `set_by` | `DynastyId` | род, выбравший текущий курс (для события «курс сменился другим родом») |
| `target` | `u32` | `DynastyId` целевого рода для курса «с целью»; «нет» — невалидный `DynastyId` (не 0: род 0 существует; E10-T02) |
| `state` | `u8` | см. §20.3 |
| `next_step` | `Date` | конец инерции (`Inertia`) или дата следующего шага отката (`Rollback`); `kNoDate` в `Active` |
| `order_ready[4]` | `Date[4]` | дата, с которой приказ снова доступен (`kNoDate` — готов) |
| `flags` | `u8` | бит 0 — «враждебный»: `controller` ≠ род, начавший курс, и курс с целью против рода игрока/любого рода (производное, хранится для хеша событий); бит 1 — курс задан системой/событием |

Размер строки 44 байта (≤ 1,4 КБ таблица). Уникальность `(type, locus)`; `controller` — существующий род; `target` — существующий род или 0.

**`PortfolioOrderRing`** — кольцо 64 записи (старейшая вытесняется), хранит историю приказов для окна и шума давления:

| Колонка | Тип | Смысл |
|---|---|---|
| `seq` | `u32` | из `CourtMeta.next_order_seq` |
| `type`, `locus`, `order` | `u8`, `u32`, `u8` | что и где |
| `issuer`, `holder` | `DynastyId`, `CharacterId` | кто отдал и кто исполнял |
| `date` | `Date` | дата |
| `target` | `u32` | цель (род/провинция/персонаж по `target_kind`) |
| `cost_kop`, `cost_favor_x100` | `i64`, `i32` | фактически списанная цена |
| `power_permille`, `execution_permille`, `noise_x100` | `i16`, `i16`, `i16` | итоговая сила, исполнение, шум приказа |

45 байт × 64 ≈ 2,9 КБ. Затухание шума — по `date`, без записи.

**Изменения таблиц §4.1/§4.8** (T02/T03 ещё не начаты, поэтому правим сразу): `CourtMeta` получает `next_order_seq` (раздел 64); `FavorTable` получает колонку `pressure_band` (`u8`, 0 по умолчанию; раздел 69 `+1` байт) — для события пересечения порога давления (§20.7, on-action 109).

**Производные (не сохраняются, `rebuild_derived_indexes()`):** индекс `portfolio_by_seat_`; кэши ведомственных модификаторов E9 (`province_dept_[p]`: сдвиг налогового уровня, бонус контроля, поправка коррупции; `loan_terms_[dynasty]`; `quota_permille_[dynasty]`; `crown_tax_shift`) с dirty-битами; кэш давления `pressure_cache_[dynasty]` (пересчёт ежемесячно и при команде). Кэши пусты после загрузки и пересчитываются лениво (как §17.10 E9).

**`validate`:**

| Команда | Проверки (порядок) |
|---|---|
| `SetPortfolioCourse` | режим династии → правила → тип имеет портфель (`NoPortfolio`) → портфель `Active` и актор — род-держатель (`PortfolioClosed`, `NotPortfolioOwner`; системный актор пропускает) → курс существует и отличается от текущего (`CourseUnknown`, `CourseSame`) → `course_change_cooldown_days` (`CourseCooldown`, a = дней; не для первой настройки и не для системы) → цель: нужна для курса «с целью» (`TargetRequired`), существует, не сам род-держатель и не Корона (`TargetInvalid`) → домен, подсистема которого ещё не включена (`Inquiry` в M1 нет), даёт `SystemNotReady` |
| `IssuePortfolioOrder` | как выше до `Active` → приказ существует (`OrderUnknown`) → перезарядка (`OrderCooldown`, a = дней) → условие приказа (`OrderConditionUnmet`, например смута ≥ 40) → цель (`TargetRequired`/`TargetInvalid`; провинция — государева/«своя» по `target_kind`) → **исполнение**: `execution ≥ refuse_below` иначе `HolderRefuses` → цена: деньги `can_afford` (`CannotAfford`), милость `favor ≥ cost` (`FavorTooLow`) → тот же `SystemNotReady` |
| `AdvancePortfolio` | внутренняя (`InternalOnly`, актор невалиден); строка существует (кроме `Adopt` для первой строки и `PressureCrossed`); шаг допустим для состояния |

**`apply` (что меняется):**

| Команда | Эффекты |
|---|---|
| `SetPortfolioCourse` | создаёт строку при первой настройке; пишет `course`, `course_since = сегодня`, `set_by`, `target`, `controller`; помечает dirty-биты затронутых кэшей; пересчитывает флаг «враждебный»; летопись `Note` 11; журнал для on-action 106 |
| `IssuePortfolioOrder` | считает `power`, `cost`, `cooldown`, `noise` теми же функциями, что превью; списывает цену (§20.5); применяет эффект методами `World` (контроль, смута, настроение, стресс, мнение 311/312, милость, образование, срок квоты, коррупция, заём); пишет `order_ready[order] = сегодня + cooldown`; запись в кольцо; летопись `Note` 12; журнал для on-action 107 |
| `AdvancePortfolio` | `Adopt`: создаёт/обновляет строку, `controller = dynasty`, `state = Active`, `next_step = kNoDate`, пересчитывает «враждебный»; `BeginInertia`: `state = Inertia`, `next_step = сегодня + inertia_months·30`; `Rollback`: курс → `rollback_to`, `state = Rollback`, `next_step += 30`; `Close`: строка удаляется, dirty-биты кэшей; `PressureCrossed`: пишет `pressure_band` в `FavorTable`, летопись; журнал для on-action 108/109 |

| Код | Имя | Где | `a` |

### 20.8 Формулы

Все — таблицы данных, целочисленные; «показанное = применённое»: `course_preview`, `order_preview`, `portfolio_pressure` — те же функции, что `validate`/`apply`/системы.

**20.8.1 Исполнение и сила** (код `portfolio_power`; `Breakdown` 14700): `skill` — навык держателя области (`Хозяйство`, `Учёность`, `Интриги`…); `loyalty_pt` — мнение держателя к главе его рода; `integrity` — из `administrator_profile` (E10-T09); `skill_power = clamp(1000 + 40·(skill − 10), 600, 1400)`; `loyalty_term = 500 + 5·loyalty_pt`; `integrity_term = 10·integrity`; `execution = (600·loyalty_term + 400·integrity_term)/1000`; `exec_eff = min(1000, execution·1000/700)`; `power = skill_power·exec_eff/1000`; `leak = max(0, 40 − integrity)·10`‰ для денежных эффектов. Отказ при `execution < 300`.

**20.8.2 Цена и перезарядка** (14750): `cost = base·clamp(1000 − 30·(skill − 10), 700, 1300)/1000`; `cooldown = base_days·clamp(1000 − 25·(skill − 10), 750, 1250)/1000`.

**20.8.3 Числовые эффекты:** сила умножает **изменение**, а не базу: `delta' = delta·power/1000` (усечение к нулю), множители курсов — `1000 + (mult − 1000)·power/1000`. Курсы действуют с `power` держателя на момент пересчёта кэша (смена навыка или мнения помечает кэш грязным ежемесячно); в `Inertia` — с последним сохранённым значением (в строке не хранится: берётся `power_inertia_permille = 800` — курс без держателя работает «как привык»).

**20.8.4 Инерция и откат:** `inertia_months` типа (6/4/12/6); `Rollback`: шаг в 30 дней по `rollback_to` (цепочка ≤ 3 шагов, курсы с целью — сразу к умолчанию); строка удаляется при курсе = умолчание.

**20.8.5 Давление и зависть** (`Breakdown` 14800): `pressure_x100 = (Σ w·k(state) ·convex + Σ noise_course + Σ noise_orders·decay − favor_relief)`, где `convex = (1000 + 250·max(0, n − 1))/1000`, `decay = max(0, 1 − возраст/heat_days)`, `heat_days = 180`, `favor_relief = favor_x100/10`; полосы 20/40/60. Вклад в подозрение (E12): `max(0, pressure − 20)·60/1000` очка в месяц, ≤ 5. Зависть: для каждого из `envy_max_rivals = 12` родов по возрастанию `(−честь, id)`, кроме Короны и рода-держателя: `delta = −min(2, (pressure − 15)/10)`, вдвое меньше при собственном портфеле или общей партии → `AdjustOpinion` (19, причина **310**, глава рода → глава рода-держателя); только ненулевые.

**20.8.6 Милость:** к `Breakdown` 14200 добавляется слагаемое **14208 `portfolio`**: суммы `favor_per_month` выбранных курсов (щадящий −0,4, жёсткий +0,6, сбор податей +0,5 и т. п.) для рода-держателя; зажим месячной дельты прежний (±6).

**20.8.7 ИИ-держатель** (`court.ai`): для каждого курса — `ai_score = Σ ai_weight[курс]·контекст` (данные: казна Короны, смута, милость, мнение к кандидату в цель); цель выбирается как род с минимальным мнением главы к главе держателя **при условии** `opinion ≤ hostile_opinion (−15)` или противоборствующих партиях (§8.10); иначе — курс без цели; максимум, ничья по индексу. **Враждебный преемник** — это тот же выбор: он начинается в первый месячный слот после `Adopt` (≤ 30 дней).

**Семейства `Breakdown`** (стабильные `u16`, продолжение §9): **14700** сила исполнения (14701 `skill`, 14702 `loyalty`, 14703 `integrity`, 14704 `inertia`, 14705 `leak`); **14750** цена приказа (14751 `base`, 14752 `skill_discount`, 14753 `favor_part`, 14754 `fee`); **14760** перезарядка (14761 `base`, 14762 `skill`); **14800** давление (14801 `offices`, 14802 `convexity`, 14803 `courses`, 14804 `orders`, 14805 `favor_relief`, 14806 `suspicion_hint`); **14810** зависть (14811 `base`, 14812 `own_portfolio`, 14813 `same_party`). Текст — `court.term.t<код>`.

### 20.19 Поправки E7-T38: влияние как цена и подкрепление

> Решение владельца [#527](https://github.com/savinovanton/patriarch/issues/527) (2026-11-15) и спецификация [influence-model.md](influence-model.md). Не меняет D1…D26; уточняет цены приказов и челобитную. Выбор вариантов — [#577](https://github.com/savinovanton/patriarch/issues/577) (хлопоты вместо «услуги»), [#578](https://github.com/savinovanton/patriarch/issues/578) (цена приказов); до ответа действуют рекомендации (вариант A), все значения — данные.

- **Таблицы.** `InfluenceTable` (строка 8 Б) и кольцо `InfluenceLog` (64) объявляются в **E10-T02** (+0,5 дн.), сохраняются в **E10-T03** (+0,5 дн.): раздел **10** из резерва E7, часть хеша **40**, тот же подъём схемы; очередь W не меняется.
- **Вектор цены приказа.** В `portfolios.pd` у приказа три части цены `{money_kop, influence_x100, favor_x100}` (любая может быть 0); скидка по навыку (`Breakdown` 14752) применяется ко всем частям; новый узел **14755 `influence_part`**; по умолчанию большинство приказов — деньги и влияние, милость списывают только приказы «вопреки государю». Влияние списывается `World::add_influence(…, reason 302 PortfolioOrder)` в `apply`.
- **Отказы.** `CourtDenial` **115 `InfluenceTooLow`** (`b` — не хватает, сотые очка), **116 `InfluenceAmountInvalid`** (сумма хлопот вне 0…30 очков); соответствие `Rejection` — `InvalidState` и `InvalidArgument`.
- **«Хлопоты» при челобитной.** `PetitionForOffice` получает поле `influence_x100 (u16, 0…3000)`; слагаемое 7 `service` = `min(15, influence_x100/200)` очков полезности (1 очко за 2,0 очка влияния; `service_points` и флаг услуги остаются как данные для M2); счётчик `FavorTable.services` в M1 не заводится (вариант A [#577](https://github.com/savinovanton/patriarch/issues/577), закрывает [#509](https://github.com/savinovanton/patriarch/issues/509)); списание — при подаче, причина 301 `PetitionPush`; возврат при снятии челобитной системой — 0 ‰ (как у подарка при добровольном отзыве; влияние не возвращается).
- **ИИ.** `court.ai` добавляет «Хлопоты», когда до лидера не хватает ≤ 15 очков полезности и баланс ≥ `2·need + ai_reserve` (§12 модели влияния); приказы — по `ai_orders` с проверкой всех частей цены.
- **Мост.** `OrderView.cost` получает `influence_x100`; `OrderPreview`/`CourseChangePreview` показывают три части и «не хватает» по каждой.
- **Деньги.** Без изменений: влияние вне ведомости ([influence-model.md](influence-model.md) §10); в §5.1 ничего не добавляется.
