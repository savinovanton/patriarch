# Геоданные: как получить исходные данные и проверить их (Geo-2)

> Статус: каркас (Geo-2, #78). Контекст — [ADR-0004](../adr/0004-geodata-pipeline.md), вердикты по лицензиям — [geodata-sources.md](geodata-sources.md). Здесь — манифест источников и безопасная воспроизводимая загрузка; стадия 1 (GDAL/PROJ → промежуточные файлы, Geo-4) и стадия 2 (`mapgen --import` → PMD2, Geo-3) — [geodata-pipeline.md](geodata-pipeline.md); полный прогон и замеры — §7.

## 1. Главное правило

**Сырые сторонние данные (DEM, векторы, сканы карт) в репозиторий не коммитятся — никогда.** В репозитории лежат только манифест (`data-sources/geodata.manifest.json`) и скрипты (`tools/geo/`). Данные живут в локальном кэше **вне** репозитория. Валидатор считает ошибкой лишние файлы рядом с манифестом, а `fetch.py` отказывается работать с кэшем внутри репозитория. В Git попадают только производные файлы (`.pmd` и т. п.) — по правилам `assets/LICENSES.csv` и с источниками в `notes`.

## 2. Что есть

| Файл | Назначение |
|---|---|
| `data-sources/geodata.manifest.json` | манифест источников (формат — `data-sources/README.md`) |
| `tools/geo/geo_manifest.py` | валидатор манифеста (схема, лицензии, уникальные id, хеши, статусы); запускается в CI |
| `tools/geo/fetch.py` | загрузка в кэш с проверкой SHA-256 и размера; **в CI не запускается** |
| `tests/tools/test_geo_manifest.py`, `test_geo_fetch.py` | тесты (только локальные фикстуры, без интернета) |

Нужен только Python 3 (стандартная библиотека, зависимостей нет).

## 3. Где лежит кэш

Порядок выбора каталога: аргумент `--cache DIR` → переменная окружения `PATRIARCH_GEO_CACHE` → `~/.patriarch/geodata-cache` (`C:\Users\<user>\.patriarch\geodata-cache`). Раскладка: `<кэш>/<id источника>/<путь файла>`. Каталог внутри репозитория запрещён (скрипт завершится с кодом 2).

```powershell
$env:PATRIARCH_GEO_CACHE = "D:\geodata-cache"    # по желанию; диск с запасом места (наборы — десятки ГБ)
```

## 4. Проверка манифеста (быстро, без сети)

```powershell
python tools\geo\geo_manifest.py                 # код 0 — манифест согласован; каждая проблема — одна строка ERROR
python -m unittest discover -s tests/tools -v    # включая тесты манифеста и загрузчика
```

Валидатор проверяет: версию формата, обязательные поля (неизвестное — явный `null`), уникальность `id`, словарь лицензий (`assets/README.md` + собственные `LicenseRef-<имя>`; `NC`/`ND` запрещены), хеши (64 hex или `null`), безопасные пути и `https`-ссылки, правило «`unverified` не может быть `ready`», наличие `decision_issue` у `blocked-on-owner`, запрет `may_commit_raw: true` и посторонних файлов рядом с манифестом.

## 5. Как владельцу получить данные

Сейчас в манифесте записаны **кандидаты без URL и без хешей** (статус `unverified`), потому что файлы ещё ни разу не скачивались; выдумывать хеши и ссылки нельзя. Порядок работы:

1. Прочитайте вердикт по набору в [geodata-sources.md](geodata-sources.md) и откройте страницу набора (адреса доступа перечислены в `notes` записи).
2. Добавьте в запись `files[]` — `path` (имя внутри `<кэш>/<id>/`) и `url` (ссылка на конкретный файл с официальной страницы), оставив `sha256` и `size` равными `null`; заполните `version`/`version_date`, `source_page`, `license_url`.
3. Пробный прогон без загрузки: `python tools\geo\fetch.py --only <id> --dry-run`.
4. Первая загрузка с вычислением хеша:
   ```powershell
   python tools\geo\fetch.py --only <id> --allow-unverified
   ```
   Скрипт скачает файл, и в конце напечатает `"sha256": "…", "size": …` — **запишите эти значения в манифест** после того как убедились, что скачан именно тот файл, что нужно.
5. Когда у всех файлов набора есть `url`, `sha256`, `size`, а лицензия, её страница, дата проверки и решение по атрибуции заполнены, поменяйте `status` на `ready`; валидатор не даст пометить `ready` набор с `null`-хешами.
6. Дальше `python tools\geo\fetch.py` скачивает всё недостающее; повторный запуск ничего не качает — файлы с верным хешем пропускаются. Прерванная загрузка лежит как `*.part` и докачивается (HTTP Range); файл с неверным хешем или размером удаляется и в кэш не попадает.

Наборы со статусом `blocked-on-owner` (HydroSHEDS/HydroRIVERS — #96, сканы РНБ — #97) и `rejected` скрипт **никогда не скачивает**, пока вы не примете решение и не поменяете статус. Ключи: `--only ID` (можно несколько раз), `--dry-run`, `--allow-unverified`, `--timeout`.

## 6. Как данные используются дальше

Стадия 1 (внешние офлайн-инструменты GDAL/PROJ, `tools/geo/stage1.py`; реализована, Geo-4 — установка, запуск и формат в [geodata-pipeline.md](geodata-pipeline.md)) читает файлы из кэша, перепроецирует и ресемплирует их и выдаёт простые промежуточные файлы; стадия 2 — детерминированный `mapgen --import` (C++, Geo-3) — собирает из них пару PMD2 `physical.pmd` + `provinces.pmd` (процедурный `mapgen --out` по-прежнему пишет `PMD1`). Идентификаторы наборов и версии из манифеста попадут в провенанс карты, а тексты атрибуции (`attribution.text`) — в экран «Об игре». CI собирает игру из подготовленных данных и **не** скачивает сырьё: он только запускает валидатор манифеста.

## 7. Полный прогон реальной карты и замеры (Geo-3, Geo-17; 2026-11-26)

Порядок (всё вне репозитория; манифест с полным списком тайлов — временный, `~\.patriarch\manifest-geo3\`):

```powershell
curl -o tileList.txt https://copernicus-dem-90m.s3.amazonaws.com/tileList.txt
python tools\geo\stage1.py tiles --tile-list tileList.txt > tiles.json        # 6468 тайлов
#   вставить tiles.json в files записи copernicus-dem-glo90 копии манифеста
python tools\geo\fetch.py --manifest <копия> --only copernicus-dem-glo90 --allow-unverified
python tools\geo\stage1.py run --projection lcc --manifest <копия> --allow-unverified
mapgen --import %USERPROFILE%\.patriarch\geodata-work\lcc <каталог карты> --preview карта.png
patriarch_spike --map <каталог карты>\physical.pmd [--season winter|summer] [--shot снимок.png]
```

Повторный `fetch.py` докачивает пропущенное (при первой загрузке 3 тайла из 6468 не скачались без явной ошибки — проверяйте число файлов в кэше).

| Показатель (8192×4096, `lcc`, Release, 12 логических ядер) | Значение |
|---|---|
| Загрузка GLO-90 | 6468 тайлов, **19,25 ГиБ** (оценка ADR — ≈ 10 ГБ); в кэше 18 ГиБ на диске C: |
| Стадия 1 (`stage1.py run`, одна проекция) | ≈ 6,6 мин; суша 19,28 млн пикселей (57,5 %), море 14,10 млн, озёра 0,17 млн, суша без DEM — 24 пикселя |
| Стадия 2 (`mapgen --import`) | чтение 0,2 с, построение слоёв ≈ 6 с, запись ≈ 1,6 с |
| Водоёмы и провинции-заглушки | 383 моря, 862 озера; 400 провинций разбиения + 1475 островных |
| `physical.pmd` (zstd 3) | **27 359 740 Б (26,1 МиБ)**; оценка ADR-0007 §7.1 — 12-30 МБ |
| `provinces.pmd` | **735 675 Б (0,70 МиБ)**; оценка ≈ 0,5 МБ (больше из-за 1475 островных провинций) |
| `load_map`, 1 поток | **2,4-2,8 с** |
| `load_map`, 8 потоков | **1,6-1,9 с** |
| из них распаковка физики (1 / 8 потоков) | ≈ 0,9 с / ≈ 0,35 с |
| из них `validate_physical` | ≈ 0,43 с (однопоточно) |
| из них проверка провинций (`validate_provinces`) | ≈ 0,6-0,75 с (однопоточно) |
| спайк: загрузка `--map physical.pmd` | 1,8-1,9 с (все ядра) |

Оговорка: все замеры сделаны при 100 % загрузке процессора параллельными сборками других агентов, поэтому указаны лучшие значения серий; на свободной машине они будут меньше. Вывод: бюджет ADR-0003 (**≤ 10 с**) выполнен с запасом в 4-5 раз; оценка ADR-0007 (**≤ 0,5 с на 8 потоках**) **не** выполнена: она учитывала только распаковку, а при загрузке ещё идут однопоточные семантические проверки обоих слоёв (≈ 1,1-1,2 с) и сборка `MapData`. Ускорение (параллельные проверки, один расчёт `coast_key` вместо трёх, проверка в CI вместо каждой загрузки) — отдельная задача (#790).

Снимки реальной карты в спайке (общий план и вблизи — Кавказ, Байкал, Камчатка; зима и лето) приложены к PR Geo-3. Ограничения отображения — [geodata-pipeline.md](geodata-pipeline.md) §11.
