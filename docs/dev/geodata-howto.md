# Геоданные: как получить исходные данные и проверить их (Geo-2)

> Статус: каркас (Geo-2, #78). Контекст — [ADR-0004](../adr/0004-geodata-pipeline.md), вердикты по лицензиям — [geodata-sources.md](geodata-sources.md). Импорт в карту (`mapgen import`, Geo-3) **ещё не реализован**; здесь описано только то, что уже есть: манифест источников и безопасная воспроизводимая загрузка.

## 1. Главное правило

**Сырые сторонние данные (DEM, векторы, сканы карт) в репозиторий не коммитятся — никогда.** В репозитории лежат только манифест (`data-sources/geodata.manifest.json`) и скрипты (`tools/geo/`). Данные живут в локальном кэше **вне** репозитория. Валидатор считает ошибкой лишние файлы рядом с манифестом, а `fetch.py` отказывается работать с кэшем внутри репозитория. В Git попадают только производные файлы (`.pmd` и т. п.) — по правилам `assets/LICENSES.csv` и с источниками в `notes`.

## 2. Что есть

| Файл | Назначение |
|---|---|
| `data-sources/geodata.manifest.json` | манифест источников (формат — `data-sources/README.md`) |
| `tools/geo/geo_manifest.py` | валидатор манифеста (схема, лицензии, уникальные id, хеши, статусы); запускается в CI |
| `tools/geo/fetch.py` | загрузка в кэш с проверкой SHA-256 и размера; **в CI не запускается** |
| `tests/tools/test_geo_manifest.py`, `test_geo_fetch.py` | тесты (только локальные фикстуры, без интернета) |

Нужен только Python 3 (стандартная библиотека, зависимостей нет).

## 3. Где лежит кэш

Порядок выбора каталога: аргумент `--cache DIR` → переменная окружения `PATRIARCH_GEO_CACHE` → `~/.patriarch/geodata-cache` (`C:\Users\<user>\.patriarch\geodata-cache`). Раскладка: `<кэш>/<id источника>/<путь файла>`. Каталог внутри репозитория запрещён (скрипт завершится с кодом 2).

```powershell
$env:PATRIARCH_GEO_CACHE = "D:\geodata-cache"    # по желанию; диск с запасом места (наборы — десятки ГБ)
```

## 4. Проверка манифеста (быстро, без сети)

```powershell
python tools\geo\geo_manifest.py                 # код 0 — манифест согласован; каждая проблема — одна строка ERROR
python -m unittest discover -s tests/tools -v    # включая тесты манифеста и загрузчика
```

Валидатор проверяет: версию формата, обязательные поля (неизвестное — явный `null`), уникальность `id`, словарь лицензий (`assets/README.md` + собственные `LicenseRef-<имя>`; `NC`/`ND` запрещены), хеши (64 hex или `null`), безопасные пути и `https`-ссылки, правило «`unverified` не может быть `ready`», наличие `decision_issue` у `blocked-on-owner`, запрет `may_commit_raw: true` и посторонних файлов рядом с манифестом.

## 5. Как владельцу получить данные

Сейчас в манифесте записаны **кандидаты без URL и без хешей** (статус `unverified`), потому что файлы ещё ни разу не скачивались; выдумывать хеши и ссылки нельзя. Порядок работы:

1. Прочитайте вердикт по набору в [geodata-sources.md](geodata-sources.md) и откройте страницу набора (адреса доступа перечислены в `notes` записи).
2. Добавьте в запись `files[]` — `path` (имя внутри `<кэш>/<id>/`) и `url` (ссылка на конкретный файл с официальной страницы), оставив `sha256` и `size` равными `null`; заполните `version`/`version_date`, `source_page`, `license_url`.
3. Пробный прогон без загрузки: `python tools\geo\fetch.py --only <id> --dry-run`.
4. Первая загрузка с вычислением хеша:
   ```powershell
   python tools\geo\fetch.py --only <id> --allow-unverified
   ```
   Скрипт скачает файл, и в конце напечатает `"sha256": "…", "size": …` — **запишите эти значения в манифест** после того как убедились, что скачан именно тот файл, что нужно.
5. Когда у всех файлов набора есть `url`, `sha256`, `size`, а лицензия, её страница, дата проверки и решение по атрибуции заполнены, поменяйте `status` на `ready`; валидатор не даст пометить `ready` набор с `null`-хешами.
6. Дальше `python tools\geo\fetch.py` скачивает всё недостающее; повторный запуск ничего не качает — файлы с верным хешем пропускаются. Прерванная загрузка лежит как `*.part` и докачивается (HTTP Range); файл с неверным хешем или размером удаляется и в кэш не попадает.

Наборы со статусом `blocked-on-owner` (HydroSHEDS/HydroRIVERS — #96, сканы РНБ — #97) и `rejected` скрипт **никогда не скачивает**, пока вы не примете решение и не поменяете статус. Ключи: `--only ID` (можно несколько раз), `--dry-run`, `--allow-unverified`, `--timeout`.

## 6. Как данные будут использоваться дальше (план, не реализовано)

Стадия 1 (внешние офлайн-инструменты GDAL/PROJ/QGIS, скрипты в `tools/geo/`) читает файлы из кэша, перепроецирует и ресемплирует их и выдаёт простые промежуточные файлы; стадия 2 — детерминированный `mapgen import` (C++, Geo-3) — собирает из них `PMD1`. Идентификаторы наборов и версии из манифеста попадут в провенанс карты, а тексты атрибуции (`attribution.text`) — в экран «Об игре». CI собирает игру из подготовленных данных и **не** скачивает сырьё: он только запускает валидатор манифеста.
