# Итоговый отчёт спайка E3 (D3D11 + RmlUi + объёмная карта)

> Дата: 2026-11-06. Задачи E3-T10 (замеры) и E3-T11 (решение). Источник цифр: `patriarch_spike --bench` (Release, MSVC 19.44), воспроизводится командами из раздела 2.

## 2. Замеры (T10)

**Стенд («машина разработки»):** i5-12400F, 32 ГБ, **RTX 3050** (драйвер 32.0.16.1664), Windows 11. «Слабого профиля» (встроенной графики или старой карты) под рукой нет — см. оценку в разделе 3.

**Сцена:** процедурная карта 8192×4096 / 400 провинций, 420 подписей (400 + 20 регионов), окно «персонаж» на вкладке «Отношения» (список 1000 строк непрерывно прокручивается), панель времени, **симуляция в параллельном потоке на скорости 5**, 10 смен режима карты, сценарий камеры «зум от обзора до крупного плана с вращением и панорамой» (1200 кадров). Рендер в офлайн-цель на видеокарте, без vsync; GPU-время — по timestamp-запросам.

| Разрешение | CPU кадр p50 / p95 (мс) | **GPU p50 / p95 / max (мс)** | Видеопамять (+карта) | Подписей на экране (макс.) |
|---|---|---|---|---|
| 1920×1080 | 0.66 / 1.28 | **0.32 / 0.88 / 1.16** | 250 МиБ (+243) | 121 |
| 2560×1440 | 0.72 / 1.41 | **0.45 / 0.99 / 1.30** | 263 МиБ (+256) | 170 |
| 3840×2160 | 0.78 / 1.62 | **0.79 / 1.06 / 1.26** | 297 МиБ (+290) | 231 |
| 3840×2160, только карта (без UI/подписей/симуляции) | 0.78 / 0.98 | 0.76 / 0.86 / 1.01 | 294 МиБ | — |
| 1280×720, окно, vsync выкл. | 0.62 / 1.20 | 0.23 / 0.69 / 1.09 | — | 78 |

- **Оперативная память процесса:** ≈ 295–320 МиБ (рабочий набор) при карте 8192×4096.
- **Смена режима карты:** ≤ 0.12 мс CPU (бюджет ≤ 2 мс), геометрия не перестраивается.
- **Терейн:** 8–87 узлов за кадр (бюджет ≤ 500).
- **Симуляция на скорости 5 и на «без ограничений»** (136 тыс. игровых дней за прогон): кадр p95 1.2 / 1.4 мс — UI читает снапшоты без ожидания тика (US-3.5).
- **Окно с 1000 строк:** в документе ≈ 20 строк; кадр со скроллом списка p95 ≈ 1.0 мс.

**Наблюдение (не блокирует):** в сценариях с окном-списком ≈ 1% кадров имеют пик CPU ≈ 10–12 мс (максимум 12.4 мс < 16.6) при очень быстрой прокрутке — источник в RmlUi (генерация текста новых строк), без UI пиков нет (p99 ≈ 1 мс). Заведено как задача оптимизации UI (см. issues).

**Воспроизведение:**
```
patriarch_spike.exe --bench 1200 --offscreen 3840x2160
patriarch_spike.exe --bench 1200 --offscreen 3840x2160 --no-ui --no-labels --no-sim
```

## 3. Оценка для «слабого профиля»

Решение владельца: минимум **GTX 1050 Ti / RX 560**, бюджет кадра карты **≤ 8 мс GPU** на пресете «Среднее» (в ADR-0003 был черновик 12 мс), «Низкое» — для встроенной графики (Intel Iris Xe).

- GTX 1050 Ti по публичным обзорам в 4–5 раз медленнее RTX 3050 `[проверить на реальных бенчмарках]`; кадр GPU 1080p p95 0.88 мс → **≈ 4–5 мс**, 4K p95 1.06 мс → ≈ 5–6 мс — **в бюджете с запасом**; пока на сцене нет теней, воды, растительности и сезонов (этапы P2–P5, E5), которые добавят нагрузку.
- Видеопамять карты ≈ 245–290 МиБ — в пределах бюджета «Низкое» (≤ 1 ГБ) с большим запасом.
- **Не измерено** на реальной слабой видеокарте и на встроенной графике: нужна машина (вопрос к владельцу остаётся открытым, закрывается перед E5/E24).

## 4. Ограничения RmlUi, найденные в спайке (T11)

1. Нет встроенных (user-agent) стилей: блочность элементов и полосы прокрутки задаются в RCSS — нужен общий «базовый» стиль в теме.
2. `data-if` и шаблон `data-for` не удаляют элементы, а скрывают (`display: none`): код и тесты считают только видимые.
3. Большие списки — только через виртуализацию (сделана в окне «персонаж»: фиксированная высота строки + распорки).
4. Документы из памяти не принимают URL вида `C:/...` — стили тултипов встраиваются как `<style>`.
5. Прокрутка колесом плавная и идёт по реальному времени (в тестах нужны кадры со сном).
6. Нет загрузки изображений «из коробки» — нужен свой загрузчик (E26); `LoadTexture` в нашем render interface пока заглушка.
7. В нашем render interface **не реализованы** clip masks (скруглённый `overflow`, нужен stencil) и слои/фильтры/opacity-группы (offscreen-цели) — добавляются по необходимости в E6.
8. Нет сложного шейпинга текста (для кириллицы и латиницы не нужен); кернинг и лигатуры ограничены.
9. В выражениях data model неудобны смешанные типы (число + строка): строки готовим в модели (`"65%"`, `"480dp"`).
10. Единичные пики ≈ 10 мс при быстрой прокрутке с генерацией нового текста (см. раздел 2).

Ни одно из ограничений не критично: критерии провала из эпика (клип-маски, производительность списков, тултипы) **не сработали** — списки и тултипы работают, клип-маски нужны только для скруглённого обрезания и реализуются отдельно.

## 6. Решения по итогам спайка

| Вопрос | Решение |
|---|---|
| ADR-0001 (стек: C++20, D3D11, SDL3, RmlUi) | **Принято** (без «предварительно»): запасной план (ImGui + свой слой) не нужен |
| ADR-0003 (объёмная карта, этап P1) | **Принято**: CDLOD, палитры, SDF-подписи, выбор лучом подтверждены; P2–P6 — в E5 |
| Минимальная видеокарта | GTX 1050 Ti / RX 560 (владелец, 2026-11-06) |
| Шрифты игры | Пока системные (для спайка); окончательный выбор — вместе с темой (M1), решение #27 остаётся открытым |
| Тайлы повышенной детализации, скорость цикла суток | Откладываются: тайлы — до спайка проекции/разрешения (Geo-5), цикл суток — до E5 (решение #25) |
| Тема «старинная карта и гравюра» (T09) | Перенесена в M1 |
