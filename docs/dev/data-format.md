# Формат данных `.pd` (Patriarch Data)

> Версия формата: **1** (`format_version = 1`). Статус: спецификация E4-T01 (2026-11-06). Парсер — `src/data` (E4-T02, готов), схемы — E4-T03 (готово, см. [data-schemas.md](data-schemas.md)), реестр и загрузчик — E4-T04 (готово, см. [data-loader.md](data-loader.md)).
> Источники требований: GDD 08 §4, ТЗ FR-DATA-1, NFR-MOD-1, ADR-0001, ADR-0002.

## 1. Назначение и границы

`.pd` — текстовый формат **данных** игры: определения провинций, династий, черт, навыков, сценариев, таблиц локализации. Он читаем человеком, подходит для модов и даёт точные сообщения об ошибках.

В формат **не входит** язык правил (триггеры, эффекты, выражения вида `20 + (opinion / 5)`, вызовы `has_favor(emperor)`, `+ 20 if trait(greedy)`, `any_in_scope(...) { ... }`). Его определяет E11 ([event-engine.md](event-engine.md), ADR-0008) **поверх этого ядра без изменения грамматики**: триггеры, эффекты и числовые «аккумуляторы» — блоки записей `ключ оператор значение`; операторы в таких блоках разрешает новый тип схемы `Type::rules()` (`PD110` остаётся для обычных данных), а вызовы `имя(...)` и круглые скобки по-прежнему дают `PD012` (инфиксный сахар — возможное расширение M2 с подъёмом `format_version`). Примеры в GDD 08 §4.2 и §8.1 показывают псевдоформат; вложенный `format_version` внутри объекта заменён **файловым** (см. §6).

Парсер ядра ничего не знает о смысле данных: он строит нетипизированное дерево с позициями. Типы, обязательные поля и ссылки проверяют схемы (E4-T03) и реестр (E4-T04).

## 2. Файлы и кодировка

- Расширение `.pd`, кодировка **UTF-8** (необязательная метка BOM допускается и пропускается), переводы строк `LF` или `CRLF`.
- Недопустимая последовательность UTF-8 — ошибка `PD007` (позиция — первый плохой байт).
- Максимальный размер файла — 16 МиБ (`PD023`).
- Контент проекта лежит в каталоге `data/` (оригинальные данные, не `assets/`); один файл — любое число объектов.
- Позиции в сообщениях: **строка** и **столбец** с 1; столбец считается в кодовых точках Unicode (табуляция — один столбец), строки заканчиваются на `LF`.

## 3. Лексика

| Элемент | Правило | Пример |
|---|---|---|
| Пробелы | пробел, табуляция, переводы строк; значимых отступов нет | |
| Комментарий | `#` до конца строки (вне строкового литерала) | `# заметка` |
| Разделитель | запятая `,` — необязательный разделитель записей и элементов списка; лексер трактует запятые как пробелы (лишние допустимы) | `a = 1, b = 2,` |
| Целое | `-?[0-9]+`, не более 18 цифр, без `_` и ведущего `+` | `42`, `-5`, `007` |
| Десятичное | `-?[0-9]+\.[0-9]{1,9}` | `1.5`, `-0.025` |
| Дата | `Г.ММ.ДД`: `[0-9]{1,4}\.[0-9]{2}\.[0-9]{2}`; лексически месяц 01–12, день 01–31; реальное существование дня по **юлианскому** календарю проверяет схема | `1703.01.01` |
| Логическое | ключевые слова `yes`, `no` (не `true`/`false`) | `yes` |
| Строка | `"…"` в одну строку; экранирование ниже | `"Москва"` |
| Блочная строка | `"""…"""`, многострочная, без экранирования (§3.1) | |
| Идентификатор | сегменты `[A-Za-z_][A-Za-z0-9_]*`, соединённые точками; до 256 символов; только ASCII | `court.embezzling_governor` |
| Ссылка | `префикс:имя` без пробелов, оба — идентификаторы | `scope:governor` |
| Операторы | `=`, `!=`, `<`, `<=`, `>`, `>=` | `corruption > 30` |
| Скобки | `{ }` блок, `[ ]` список | |

Русский текст допустим **только** в комментариях и строках. Идентификаторы и ключи — латиница.

### 3.1 Строки

Обычная строка не содержит необработанных переводов строки (`PD002`). Экранирование: `\\`, `\"`, `\n`, `\t`, `\r`, `\u{X…X}` (1–6 шестнадцатеричных цифр, кодовая точка Unicode, не суррогат); иное — `PD003`.

Блочная строка начинается и заканчивается тремя кавычками; один перевод строки сразу после открывающих кавычек отбрасывается; внутри всё сохраняется как есть (без экранирования, переводы строки нормализуются в `LF`); незакрытая — `PD024`. Нужна для длинных текстов летописи и событий.

### 3.2 Числа

- Целые хранятся как `int64`.
- Десятичные разбираются **точно, как рациональное число** (`цифры / 10^k`) и преобразуются в `Fixed` через `Fixed::from_ratio` — **без `double`** (правило детерминизма). Тип `Fixed32` (Q16.16) или `Fixed64` (Q32.32) выбирает схема. Выход за диапазон — ошибка схемы.
- Число с более чем 18 цифрами или более чем 9 знаками после точки — `PD006`.
- Запись вида `1.`, `.5`, `1e5`, `0x10` — `PD004`; три группы цифр через точки (`1.2.3`, `1703.1.1`, `1703.13.01`, `1703.02.32`), не образующие допустимой даты, — `PD005`.
- Позиция лексической ошибки — начало токена (для `PD003` — символ `\`, для `PD024` — открывающие `"""`).

## 4. Грамматика

```
файл      = { запись [ "," ] } ;
запись    = ключ [ метка ] ( оператор значение | блок ) ;
ключ      = идентификатор | целое | дата ;
метка     = строка | идентификатор ;            (* только перед блоком *)
оператор  = "=" | "!=" | "<" | "<=" | ">" | ">=" ;
значение  = скаляр | блок | список ;
скаляр    = целое | десятичное | логическое | дата | строка
          | блочная_строка | идентификатор | ссылка ;
блок      = "{" { запись [ "," ] } "}" ;
список    = "[" { значение [ "," ] } "]" ;
```

Правила разбора записи (по токену после ключа):

1. Оператор → запись «ключ оператор значение».
2. `{` → запись-блок; `key { … }` **равносильно** `key = { … }`.
3. Строка или идентификатор, за которыми идёт `{` → блок **с меткой**: `event "court.fire" { … }`, `province moscow { … }`; метка нормализуется в строку (`province "moscow"` и `province moscow` дают одно дерево).
4. Иначе — `PD010`.

Ключи в блоке могут повторяться; порядок записей сохраняется (это мультикарта: схема решает, допустим ли повтор). Голые значения в блоке (`{ "a" }`, `{ yes }`) запрещены — для последовательностей есть списки; запись, начинающаяся не с ключа, — `PD016`, а `{ a b c }` читается как ключ `a` с неверным продолжением — `PD010`.

Круглые скобки `(` и `)` — зарезервированные токены (для вызовов в E11): в версии 1 любое их появление вне строки — `PD012` на идентификаторе, за которым идёт `(`, иначе на самой скобке. Элементы списка — любые значения, включая вложенные блоки и списки; блок в списке не имеет ключа и метки.

Лимит вложенности — 64 уровня (`PD015`); длина строки — до 1 МиБ.

## 5. Дерево разбора (контракт для E4-T02)

Узел значения: `Int`, `Decimal` (текст + точная дробь), `Bool`, `Date` (год, месяц, день), `String`, `Ident`, `Ref` (префикс, имя), `Block`, `List`. Запись содержит ключ, необязательную метку, оператор и значение, а также **позиции** начала ключа и значения. Файл — заголовок (`format_version`) и список записей верхнего уровня.

**Каноническая текстовая запись дерева** (для корпуса и отладки) — по строке на запись, отступ 2 пробела на уровень:

```
КЛЮЧ [МЕТКА] ОПЕРАТОР ЗНАЧЕНИЕ        для скаляра
КЛЮЧ [МЕТКА] ОПЕРАТОР {               для блока; далее вложенные записи; закрывающая } с тем же отступом
КЛЮЧ [МЕТКА] ОПЕРАТОР [               для списка; элементы — строки «- ЗНАЧЕНИЕ», «- {» … «}», «- [» … «]»
```

- Метка — всегда строка в кавычках. Оператор печатается как записан (`key {` печатается как `key = {`).
- Значения: `int:5` (нормализованное число: `007` печатается как `int:7`), `dec:1.50` (текст как в файле), `bool:yes`, `str:"текст"`, `date:1703.01.01`, `ident:a.b`, `ref:scope:governor`.
- Экранирование в `str:` каноническое: `\\`, `\"`, `\n`, `\t`, `\r`, прочие управляющие — `\u{X}`; остальное (включая кириллицу) — как есть.

## 6. Версия формата и заголовок

Первая запись файла обязана быть `format_version = <целое>` (иначе `PD020`). Версия **файла**, а не объекта. Загрузчик (E4-T04, [data-loader.md](data-loader.md) §3) поддерживает текущую версию и цепочку миграций «старая → новая»; неизвестная более новая версия — `PD021`. Изменение грамматики или смысла существующих конструкций поднимает версию и требует миграции; добавление новых необязательных полей схем версию **не** меняет.

## 7. Объекты и локализация (соглашения)

- Объект определения: `<вид> "<id>" { … }` на верхнем уровне, например `trait "greedy" { … }`. Вид и поля задаёт схема.
- Идентификатор объекта уникален в пределах вида; переопределение модом заменяет объект целиком (E4-T04).
- Таблица локализации — обычный файл `data/loc/<язык>/…/*.pd`: после `format_version` записи `ключ = "текст"` на верхнем уровне (ключи — идентификаторы с точками); **язык задаёт каталог** (`data/loc/ru/ui.pd`), записи `language = …` в заголовке нет. Загрузчик контента такие файлы пропускает (E4-T06, [localization.md](localization.md)).
- Внутри строк локализации (`{name}`, `{n:plural(год|года|лет)}`) разбирает не `.pd`, а модуль локализации `pat::loc` ([localization.md](localization.md)).

## 8. Коды ошибок

Сообщение: `файл:строка:столбец: error[КОД]: текст`. Коды стабильны — тесты сверяют **код и позицию**, не формулировку.  Коды `PD101…PD110` (проверка по схемам, E4-T03) описаны в [data-schemas.md](data-schemas.md); `PD111…PD114` (загрузчик, E4-T04) — в [data-loader.md](data-loader.md).

| Код | Смысл |
|---|---|
| `PD001` | недопустимый символ |
| `PD002` | незакрытая строка (необработанный конец строки или файла) |
| `PD003` | недопустимая escape-последовательность |
| `PD004` | некорректное число |
| `PD005` | некорректная дата |
| `PD006` | значение вне допустимых пределов (цифры числа, знаки после точки, длина идентификатора — 256, длина строки — 1 МиБ) |
| `PD007` | некорректный UTF-8 (фатальная) |
| `PD010` | после ключа ожидается оператор или `{` |
| `PD011` | ожидается значение |
| `PD012` | зарезервированная конструкция (вызов `имя(…)`, круглые скобки) |
| `PD013` | лишняя закрывающая скобка |
| `PD014` | незакрытая скобка к концу файла (позиция — открывающая скобка) |
| `PD015` | слишком глубокая вложенность (фатальная) |
| `PD016` | ожидается ключ (запись начинается не с ключа) |
| `PD018` | `true`/`false`: используйте `yes`/`no` |
| `PD019` | `==`: используйте `=` |
| `PD020` | нет `format_version` первой записью |
| `PD021` | неподдерживаемая версия формата |
| `PD022` | слишком много ошибок (разбор остановлен после 100; фатальная) |
| `PD023` | файл слишком большой (фатальная) |
| `PD024` | незакрытая блочная строка |

### Восстановление после ошибки

Парсер не останавливается на первой ошибке. Запись с ошибкой **отбрасывается целиком**: токены пропускаются до ближайшего из — закрывающая скобка текущего контейнера (она не считается ошибкой и закрывает контейнер), либо идентификатор/целое/дата, стоящий **первым на строке**; на пропущенных токенах новые ошибки не сообщаются, кроме лексических в том же проходе по строке. Для каждого файла сообщается до 100 ошибок, затем `PD022`.

**Фатальные** ошибки (`PD007`, `PD015`, `PD022`, `PD023`) прекращают разбор файла сразу: последующие ошибки (например, `PD014` от незакрытых скобок) не сообщаются. Ошибки заголовка `PD020` не мешают разбору остальной части файла. Конец файла внутри записи: `PD011` для оператора без значения (позиция — конец файла), `PD014` для незакрытой скобки.

## 9. Тестовый корпус

Каталог `tests/data/pd/`:

- `valid/<имя>.pd` + `<имя>.tree` — файл и ожидаемая каноническая запись дерева (§5);
- `invalid/<имя>.pd` + `<имя>.expect` — файл и ожидаемые ошибки по строке на ошибку: `строка:столбец КОД`, в порядке следования.

Корпус общий для лексера/парсера (E4-T02) и фаззинга; `tests/tools/test_pd_corpus.py` проверяет, что у каждого файла есть парный и формат пары корректен. Правка грамматики обязана сопровождаться правкой корпуса и поднимать `format_version` по правилам §6.

## 10. Принятые решения (E4-T01)

| Вопрос | Решение |
|---|---|
| Расширение | `.pd` |
| Где контент | `data/` в корне репозитория, не `assets/` (не нужен реестр лицензий) |
| Версия | в файле, первой записью |
| Дробные числа | точная дробь → `Fixed`, без `double` |
| Языки идентификаторов | ASCII; русский — только в строках и комментариях |
| Блочные строки | есть (`"""`) для длинных текстов |
| Выражения и вызовы | вне формата; расширение E11 |
| Локализация (формат строк, ICU или свой) | **свой** лёгкий формат, без ICU (решение владельца 2026-11-08, #109); [localization.md](localization.md) |

## 11. Заметки по реализации парсера (E4-T02)

- Код: `src/data` (`pat::data`, зависит только от `core`); точка входа `parse_pd(source)` возвращает дерево `ParsedFile` и отсортированный список `Diagnostic`.
- Проверка UTF-8 (`PD007`) и размера (`PD023`) выполняется до разбора; лексические ошибки сообщаются всегда, даже в пропущенных при восстановлении местах; после фатальной ошибки сообщения, лежащие позже неё по позиции, отбрасываются.
- Тесты: `tests/pd_parser_test.cpp` — весь корпус (`valid` → каноническая запись дерева, `invalid` → точные коды и позиции), пределы, `PD022`, `PD023`, вложенность 64/65, фаззинг (случайный мусор, мутации корпуса, все префиксы файлов).
- Решения при реализации: ключ-идентификатор не может содержать сегмент, начинающийся с цифры (`chronicle.1703` — это `chronicle` и ошибка числа `.1703`); `PD014` сообщается для каждой незакрытой скобки в позиции её открытия.
