# Локализация: таблицы строк, параметры, плюрализация

> Статус: E4-T06 готово; окна UI читают таблицу (#233, §9). Код — `src/loc` (`pat::loc`, `pat/loc/plural.hpp`, `message.hpp`, `localizer.hpp`), тесты — `tests/localization_test.cpp`, пример таблицы — `data/loc/ru/ui.pd`.
> Решение владельца (2026-11-08, #109): **свой лёгкий формат, без ICU и новых зависимостей**; в M1 только русский, но механизм рассчитан на любые языки.
> Формат файлов `.pd` — [data-format.md](data-format.md) (§7), загрузка корней и модов — [data-loader.md](data-loader.md).

## 1. Где что лежит

Таблица строк — обычный файл `.pd`, а **язык задаёт каталог**:

```
data/loc/ru/ui.pd            # русские строки интерфейса
data/loc/ru/events/court.pd  # подкаталоги любой глубины
data/loc/en/ui.pd            # английский (появится позже)
mods/my_mod/loc/ru/mod.pd    # мод: свой корень, тот же путь loc/<язык>/…
```

- Файл читается как таблица языка `<язык>`, если его путь `loc/<язык>/…/*.pd` (расширение строго `.pd`). Код языка — `[a-z][a-z0-9_]*`, до 16 символов (`ru`, `en`, `pt_br`). Выбран каталог, а не запись `language = ru` в заголовке: язык виден по пути, его нельзя забыть или указать неверно, а мод добавляет язык простым созданием каталога.
- Файл прямо в `loc/` (без каталога языка) — ошибка `LC001`; каталог с неизвестным языком — `LC002` (один раз на каталог).
- Каталог `loc/` в корне контента **не читается загрузчиком контента** (`load_content` пропускает все файлы под `loc/`), поэтому таблицы не мешают схемам и не входят в хеш контента (хеш текстов — отдельная задача, если понадобится для сохранений).
- Содержимое файла: первой записью `format_version = 1` (как у любого `.pd`, [data-format.md](data-format.md) §6), дальше записи `ключ = "текст"`:

```
format_version = 1

ui.age.years = "{n} {n:plural(год|года|лет)}"
ui.menu.chronicle = "Летопись"
event.court.fire.text = """
Пожар в Кремле. Сгорело {n} {n:plural(двор|двора|дворов)}.
"""
```

- **Ключ** — идентификатор с точками (`ui.hud.tab.cities`): сегменты `[A-Za-z_][A-Za-z0-9_]*`, только латиница. Рекомендуемое соглашение: `ui.<окно>.<смысл>`, `event.<id>.<часть>`, `trait.<id>.name`.
- **Текст** — обычная строка `"…"` (экранирование `.pd`: `\"`, `\\`, `\n`, `\u{…}`) или блочная `"""…"""` для длинных абзацев.
- Любая другая запись (число, блок, оператор не `=`, метка, ключ-число) — `LC004`.

### Несколько корней (моды)

`load_localization(roots)` принимает **упорядоченный список корней**, как `load_content`. Мод **заменяет отдельные ключи** (не таблицу целиком): ключ из позднего корня побеждает ключ того же языка из раннего; ключи, которых нет в моде, остаются от базы; мод может добавить новый ключ и целый новый язык. Один и тот же ключ дважды в одном корне и одном языке — ошибка `LC003` с местом второго и указанием первого (остаётся первый по порядку «путь файла, позиция»). Один ключ в разных языках — норма. Порядок файлов в корне — по байтовому порядку путей (результат не зависит от того, в каком порядке источник их перечислил).

## 2. Синтаксис сообщений

| Запись | Смысл |
|---|---|
| обычный текст | выводится как есть (любой Unicode) |
| `{{` и `}}` | литеральные `{` и `}` |
| `{имя}` | параметр: целое — десятичной записью без локали (`12480`, `-7`); строка — как есть |
| `{имя:group}` | целое с группами по три цифры, разделитель **U+00A0** (неразрывный пробел, UTF-8 `C2 A0`): `12480` → `12 480`, `1234567` → `1 234 567`, `-12480` → `-12 480`; группируется с четырёх цифр |
| `{имя:plural(ф1\|ф2\|ф3)}` | форма слова по целому числу `имя` согласно правилу плюрализации языка (§3) |

Имя параметра — `[A-Za-z_][A-Za-z0-9_]*`. Формы `plural` — обычный текст; в форме нельзя `{`, `}`, `|`, `)`; допускается пустая форма (`книг{n:plural(а||)}`). Пробелов внутри `{…}` быть не должно. Позиционных параметров (`{0}`) нет.

Типичное использование: `"{n} {n:plural(год|года|лет)}"` — число и слово пишутся двумя полями с одним параметром. Параметры сообщения неупорядочены: один и тот же именованный аргумент можно использовать сколько угодно раз и в любом порядке (удобно переводчику).

## 3. Правила плюрализации

Правило задаёт язык (`pat::loc::PluralRule`: число форм, функция выбора, форма для дробных). Выбор — **только целочисленная арифметика**; знак числа игнорируется (`-1` читается как `1`), включая `INT64_MIN`.

**Русский (`ru`), 3 формы: `один | несколько | много`** (`год | года | лет`):

| Условие | Форма | Примеры |
|---|---|---|
| `n % 10 == 1` и `n % 100 != 11` | 1-я | 1, 21, 101, 121 → «год» |
| `n % 10` в 2..4 и `n % 100` не в 12..14 | 2-я | 2, 3, 4, 22, 102 → «года» |
| остальное | 3-я | 0, 5–20, 25, 100, 111, 112 → «лет» |

Проверенная таблица (US-4.3): 0 лет, 1 год, 2 года, 3 года, 4 года, 5 лет, 11 лет, 12 лет, 13 лет, 14 лет, 21 год, 22 года, 25 лет, 101 год, 111 лет, 112 лет.

**Английский (`en`), 2 формы: `one | other`** (`year | years`): 1-я только при `n == 1`, иначе 2-я (`0 years`, `1 year`, `2 years`, `21 years`).

**Дробные числа.** Аргументы сейчас только целые, поэтому правило для них зарезервировано: `PluralRule::fraction_form` — форма, в которую попадает любое нецелое число. Для `ru` это **2-я форма** («1,5 года»: в CLDR категория `other` русского совпадает с родительным падежом единственного числа), для `en` — 2-я («1.5 years»). Если появятся дробные аргументы (например, `Fixed`), они будут использовать это поле.

**Как задать число форм другого языка.** Число форм — `PluralRule::form_count` языка; загрузчик проверяет, что каждый `plural(...)` в таблице этого языка содержит ровно столько форм (иначе `LC015` с позицией), так что «русская» строка с тремя формами в английской таблице — ошибка при загрузке, а не опечатка в игре. Правило встроено для `ru` и `en`; другие языки регистрируются в коде: `LoadOptions::languages.push_back({"de", PluralRule{2, 1, &my_select}})`. Для языка без формы-различителя (китайский, японский) годится `PluralRule{1, 0, …}`.

## 4. API

```cpp
#include "pat/loc/localizer.hpp"
using pat::loc::Arg;

DirectorySource base("data");
DirectorySource mod("mods/my_mod");
const ContentSource* roots[] = {&base, &mod};
pat::loc::LocLoadResult r = pat::loc::load_localization(roots);   // LoadOptions: языки, цепочка
for (const pat::loc::LocError& e : r.errors) log(e.format());     // ВСЕ ошибки, отсортированы
pat::loc::Localizer& loc = r.localizer;

std::string s = loc.format("ui.age.years", {Arg("n", 21)});       // "21 год"

// Горячий путь: без аллокаций
std::string line;  line.reserve(256);                              // буфер переиспользуется
line.clear();
const std::array<Arg, 2> args = {Arg("label", "Казна"), Arg("n", 12480)};
loc.format_to(line, "ui.res.tooltip", args);                       // добавляет в конец строки
char fixed[64];
pat::loc::FormatResult res = loc.format_to(std::span<char>(fixed), "ui.menu.world");  // res.size, res.truncated
```

- **Аргумент** `Arg(имя, значение)`: любое целое (хранится как `int64`) или строка (`string_view`; должна жить до конца вызова). Лишние аргументы игнорируются; при повторе имени побеждает первый.
- **Без аллокаций.** Сообщения компилируются один раз при загрузке (`CompiledMessage`: сегменты текста, параметров и форм). `format_to(std::string&, …)` только дописывает в строку: пока ёмкости хватает, куча не трогается. `format_to(std::span<char>, …)` не аллоцирует никогда; при нехватке места обрезает по границе кодовой точки UTF-8 (`truncated == true`), текст не завершается нулём. Поиск ключа — двоичный по отсортированному вектору, без хеширования и без создания строк. Тест `formatting does not allocate…` проверяет это подменой глобального `operator new` на считающий (счётчик на поток; работает в любой конфигурации, в т. ч. ASan) и эталонным контролем, что без запаса ёмкости счётчик срабатывает. Аллокации есть только на холодных путях: загрузка, сообщение об отсутствующем ключе, запросы `keys()`/`coverage()` и т. п.
- **Потоки.** Форматирование и запросы — `const` и потокобезопасны (учёт отсутствующих ключей защищён мьютексом); `set_chain` вызывайте, когда никто не форматирует.
- `FormatResult`: `size` (записано/добавлено байт), `truncated`, `missing_key`, `bad_argument`; `ok()` — ничего из перечисленного.

## 5. Запасная цепочка языков

`LoadOptions::chain` (по умолчанию `["ru", "en"]`) и `Localizer::set_chain(...)` задают порядок поиска: берётся первый язык цепочки, где есть ключ. Языки без таблицы пропускаются молча (цепочка `ru, en` работает, пока английской таблицы нет). `default_language` (по умолчанию `ru`) — язык, на котором пишут тексты; это эталон для отчётов о покрытии.

## 6. Отсутствующие ключи и ошибки аргументов

- Ключ не найден ни в одном языке цепочки → в вывод попадает **видимый заполнитель `[[ключ]]`** (в UI сразу видна пропажа; ASCII выбран намеренно: шрифт игры может не содержать редких скобок), `FormatResult::missing_key = true`, и в лог идёт строка `WARN loc: missing localisation key 'ключ' (language chain: ru, en)` — **один раз на ключ** (повторы подавляются; `reset_missing_log()` сбрасывает учёт). Ключи, запрошенные во время работы и не найденные, накапливаются: `requested_missing_keys()`.
- Параметр не передан или у него не тот тип (строка в `{n:group}`/`{n:plural(…)}`) → вместо него выводится `{!имя}`, `bad_argument = true`, предупреждение в лог один раз на ключ.

### Данные для `contentlint` (E4-T08, [contentlint.md](contentlint.md))

| Функция | Что даёт |
|---|---|
| `missing_keys(язык, эталон)` | ключи эталона, которых нет в языке (отсортированы) |
| `coverage()` | для каждого языка кроме `default_language`: `total`, `missing`, `extra` (`LanguageCoverage`) |
| `absent_keys(язык, использованные)` | ключи, на которые ссылается код/данные (`name_key = "…"`, вызовы `format`), но которых нет в таблице |
| `unused_keys(язык, использованные)` | ключи таблицы, на которые никто не ссылается |
| `keys(язык)`, `languages()`, `origin(язык, ключ)` | перечисление и место определения (корень, файл, позиция) |
| `parameters(язык, ключ)` | имена параметров сообщения (для сверки переводов: у одного ключа параметры должны совпадать) |

## 7. Проверка при загрузке и коды ошибок

Каждое сообщение компилируется при загрузке; ошибка указывает на **позицию внутри файла `.pd`** — на тот символ строки, где нашлась проблема (колонки в кодовых точках; экранирование `\"`, `\u{…}` и блочные строки учитываются). Сообщение содержит ключ, поэтому видно, какая запись неверна. Остальные записи файла загружаются, ошибки собираются все.

Формат: `[root 0 'data'] loc/ru/ui.pd:12:30: error[LC010]: message 'ui.x': unmatched '}' (write '}}' for a literal brace)`.

| Код | Смысл | Позиция |
|---|---|---|
| `LC001` | файл таблицы лежит не в каталоге языка (`loc/x.pd`) | — |
| `LC002` | неизвестный язык (каталог не из `LoadOptions::languages`) | — |
| `LC003` | ключ повторён внутри одного корня и языка | ключ второго определения |
| `LC004` | запись не вида `ключ = "текст"` | ключ или значение |
| `LC010` | одиночная `}` (для литерала пишите `}}`) | эта скобка |
| `LC011` | `{` без закрывающей `}` | эта `{` |
| `LC012` | пустое/некорректное имя параметра, лишние символы в поле (`{}`, `{1x}`, `{n x}`, `{n:group(3)}`) | символ ошибки |
| `LC013` | неизвестный модификатор (кроме `group`, `plural`) | начало модификатора |
| `LC014` | неверный `plural(...)`: нет форм, нет `)`, скобки внутри форм, лишнее после `)` | место ошибки |
| `LC015` | число форм `plural` не равно числу форм языка | начало модификатора |
| `LC016` | сообщение слишком длинное для внутреннего представления | — |
| `PD0xx` | синтаксические ошибки `.pd` (`PD020` — нет `format_version`, `PD021` — неподдерживаемая версия, `PD113` — не читается файл/корень) | как в [data-format.md](data-format.md) |

Файл с синтаксической ошибкой `.pd` не загружается целиком (чтобы не плодить ложные «отсутствующие ключи» по частичному дереву).

## 8. Как добавить язык

1. Создайте каталог `data/loc/<код>/` и скопируйте таблицы русского (`ui.pd` и др.), переведите значения. **Ключи и имена параметров не меняются**; формы `plural` пишите по правилам языка (число форм проверит загрузчик).
2. Если язык не `ru`/`en`, зарегистрируйте его правило плюрализации в `LoadOptions::languages` (место — код запуска игры; для мода-перевода — вместе с механизмом настройки языка, когда он появится).
3. Включите язык в цепочку: `["de", "ru"]` — недостающие строки покажутся по-русски, а не как `[[ключ]]`.
4. Проверьте покрытие: `contentlint --lang ru --fallback en` ([contentlint.md](contentlint.md)) перечислит ключи, которых не хватает (`CL001`), лишние (`CL002`) и расхождения параметров (`CL003`); то же даёт `Localizer::coverage()`.

## 9. Как строки попадают в UI (#233)

Окна (`HudWindow`, `TimeBar`, `CharacterWindow`) получают `const loc::Localizer&` при создании (объект должен пережить окно) и не содержат русских литералов. Правила:

- **Подписи окна** (вкладки, заголовки блоков, кнопки, названия навыков и пунктов меню, «Пауза») окно форматирует само: `loc.format("ui.hud.tab.cities")`. Документ RML не пишет текст, а читает привязанные переменные: `{{ t.tab_cities }}`, `{{ pause_text }}`. Ключ вида `ui.menu.<имя>` и `ui.res.<имя>` строится из ключа записи (`"ui.menu." + key`), `contentlint` считает такой префикс использованием всех ключей группы.
- **Числа и множественные формы** — параметрами: `ui.fmt.number` (`{n:group}`, неразрывные пробелы), `ui.fmt.thousands`, `ui.age.years`/`{age:plural(…)}`, `{n:plural(вопрос|вопроса|вопросов)}`; общие помощники — `pat/ui/text.hpp` (`format_number`, `format_thousands`, `format_delta`). Знак «+» у прироста пишет код, остальное — таблица.
- **Снимки** (`HudSnapshot`, `CharacterSnapshot`) не хранят готовых фраз интерфейса: числа — числа, фразы — **ключ таблицы + `count`** (`HudAffair::title_key/detail_key`, `HudChronicleLine::key`), роль и здоровье персонажа — ключи (`ui.character.role.*`, `ui.health.*`). Обычным текстом остаются только **имена из контента** (держава, провинция, город, армия, династия, имя персонажа, черта) — их даёт данные/мир, а не таблица интерфейса. Строки семьи, связей и разложений навыков (`ui.explain.*`) собирает построитель снимка (`game::character_snapshot(loc, …)`, `ui::make_test_character(loc, …)`) на языке момента сборки.
- **Смена языка:** `Localizer::set_chain(…)`, затем `relocalize()` у каждого окна (подписи и тексты, собранные из ключей снимка, обновятся сразу) и пересборка снимка персонажа; дату `TimeBar` задаёт вызывающий (`game::format_date(loc, date)`, ключи `ui.date.long`, `ui.month.*`). В `--dev` спайк перезагружает таблицы вместе с контентом.
- **Нет ключа** — на экране `[[ключ]]`, одно предупреждение в лог, окно не падает (тесты `HUD: a missing key…`).
- Не переведено сознательно: отладочная панель `apps/spike/ui/demo.rml` (тест шрифтов, F2), строка fps в `main.cpp`, названия клавиш (`Esc`), цифры скоростей, а также временные имена-заглушки (`kGivenNames`, кланы в `world_view.cpp`, города в `make_test_hud`) — они заменятся данными (`names.pd`, карта).

Окно «Титры» (UI-213, [credits.md](credits.md)) читает свои подписи так же (`ui.credits.*`), а записи списка берёт из данных: ключи записей форматирует мост `game::credits_snapshot`, юридические тексты источников остаются как в манифесте.

Тесты: `tests/hud_test.cpp`, `time_bar_test.cpp`, `character_window_test.cpp`, `game_bridge_test.cpp` (общий помощник — `tests/ui_loc_fixture.hpp`: настоящие таблицы, таблица с английским «модом», пустая таблица).
