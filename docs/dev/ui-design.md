## 1. Идея

«Карта — основное рабочее пространство; подробности — в контекстной панели; риски отмечены текстом и цветом; последствия показаны до принятия решения» (принципы варианта с доски «00 / Основа варианта и компоненты»). Тёмная «чернильная» рама вокруг карты (верхняя полоса, левая навигация, нижняя полоса) и светлые «пергаментные» окна поверх карты; золото (латунь) — только для линий, фокуса и акцентов; зелёный — единственный цвет главного действия; красный — только внимание и причина недоступности. Переходы сценария: карта → род → событие → карта.

Стилистика плоская: **нет теней и градиентов**, скругление 2 px, линии 1 / 1.5 / 2 px.

## 10. Масштаб под референс 1080p

- Макет рисовался при **1920×1080**; все значения этого документа — в «референсных» пикселях и равны `dp` при масштабе 1.
- Правило (решение владельца, #255 п. 5; реализовано в `pat::engine::design_ui_scale`, `src/engine/include/pat/engine/dpi.hpp`): `s = min(w/1920, h/1080)`, `dp`-коэффициент RmlUi = `s` × пользовательский масштаб, округление до 1/8; пользовательский масштаб — одна настройка `user_ui_scale` в диапазоне **80–150 %** (`clamp_user_ui_scale`; в спайке `--ui-scale`, ползунок в окне настроек — отдельная задача, когда окно появится); общий предел коэффициента остался прежним, 0.5–4 (`kMinUiScale`, `kMaxUiScale`: окно ниже 1366×768 не поддерживается, жёсткая отсечка 0.75 из первоначального предложения сломала бы спайк в окне 1280×720). Остальное из прежней формулировки: панели привязаны к краям (верх, лево, низ, право), модальные окна центруются по области карты (§2); значения с ограничением по минимуму (шрифт ≥ 11 dp, кнопка ≥ 32 dp по высоте).
- Размеры панелей **не растягиваются**, пока окно не станет шире: на 21:9 дополнительное пространство отдаётся карте; на 4:3 нижняя область — карте.
- Нижняя граница поддержки — 1366×768 (s ≈ 0.71, шрифт 12 px → 8.5 px): ниже порога включать режим «крупный интерфейс» (минимум 11 dp).
- Целые координаты: слои на целых x/y — рамки не размываются; при дробном масштабе линии 1 px округляются до целого устройства.

## 11. Локализация

- Все надписи — только через `Localizer` и таблицы `data/loc/<язык>/ui.pd`; правила и API — [localization.md](localization.md) §9. Макет на русском, но тексты слоёв **не** переносятся в код: слои дают ключи (`ui.hud.res.treasury`, `ui.province.tab.overview`, …).
- Числа и валюта: `{n:group}` с неразрывным пробелом («1 248 ₽»), «₽» — часть формата `ui.fmt.rouble` (отдельный ключ); минус — U+2212; прирост со знаком «+» пишет код (`format_delta`); множественные формы — `{n:plural(…)}` («3 доступные партии», «22 года», «21 год»).
- Даты: «1 января 1703», «Юлианский календарь» — `ui.date.long`, `ui.month.*` (уже есть); надпись «ЗИМА · 1703» — сезон + год.
- Верхний регистр меток («ДОХОД В МЕСЯЦ») делается стилем `text-transform: uppercase` или заранее в таблице, **не** функцией кода: для русского он безопасен, для других языков решается переводчиком.
- Запас по ширине: подписи кнопок и бейджей в макете подогнаны под русские слова; другие языки длиннее на 20–40 %: кнопки растягиваются по содержимому (минимум — ширина из макета), подписи сверху вкладок не обрезаются, а переносятся или сокращаются многоточием с подсказкой.
- Имена людей, родов, провинций — данные из мира, не таблица интерфейса.
- Тексты состояний и причин отказа — по коду ошибки команды (`ui.reason.*`), а не вручную в окне (#264).

### 12.5 Выгрузчик Penpot без токена (UI-D11, #468)

`tools/penpot_export.py` — чистый Python (только стандартная библиотека, запуск `python -I`), без сети и без работы с токенами. Читает **локальный снимок** файла Penpot (ответ бэкенда `get-file` в JSON, десятки мегабайт) и пишет блоки `board` в том же формате, что и плагинная выгрузка досок 00–13 (§12).

Порядок работы:

1. Владелец сам скачивает свежий снимок файла своими средствами (токен и ссылки остаются у него) и кладёт JSON **вне репозитория**: снимок не коммитится (36 МБ, в нём идентификаторы файла и команды). Нужен ответ `get-file` с `data.pagesIndex` и `data.components`.
2. Агент запускает `python -I tools/penpot_export.py <снимок.json> --manifest tools/penpot_layouts.json --out-dir data/ui/layout`. Манифест `tools/penpot_layouts.json` перечисляет выходные файлы и доски в каждом (по номеру «NN» или по точному имени; новая доска — новая строка в манифесте). Другие режимы: `--list` (все верхнеуровневые доски страницы «00 · Сквозной прототип»), `--board "15 / " --stdout` (одна доска в консоль, для сверки), `--only <файл.pd>` (перезаписать один файл), `--snapshot-date ГГГГ-ММ-ДД` (дата в заголовке файла), `--page <префикс>` (другая страница).
3. Сравнить `git diff data/ui/layout`: изменения должны объясняться правками владельца; затем прогнать `ctest -R "ui layout boards"` и `python -m unittest discover -s tests/tools`. Тесты выгрузчика работают на крошечном синтетическом снимке (`tests/tools/test_penpot_export.py`), настоящий снимок в репозиторий не попадает.

Правила выгрузки: слои обходятся в глубину, скрытые (`hidden`) пропускаются вместе с потомками; `x`/`y` — от левого верхнего угла доски; группа «Icon / …» сворачивается в один элемент с `paths` (число видимых контуров), линиями и заливкой первого контура; `n` у текста опускается, если текст начинается с имени слоя; не пишутся значения по умолчанию (`lh` 1.35, `ls` 0, `ta` left, `va` top, `tt`/`td` none, `fst` normal, `grow` fixed, `a` center у обводки); `r` — когда четыре угла равны, иначе `rc`; `clip = 0` у доски с включённым показом содержимого; `inst` — копия компонента (имя компонента), `main` — главный экземпляр (путь и имя; у корня доски не пишется); у контуров без собственных координат берётся прямоугольник выделения; `grow = auto-height` пишется (в файле текст растёт по высоте, а высота слоя — реальная).

**Сверка на закоммиченных досках** (снимок 2026-11-13, все 73 доски: 00–13, меню, сценарий, подсказки): совпало 3732 из 4152 строк (90 %). Сценарий и 21 доска подсказок совпадают построчно, доски 01–12 — на 90–98 %, меню — на 70–100 %, 13 — на 73 %. Все расхождения объясняются правками владельца после прошлых снимков: арт-слои «Art / …» (гравированный венок вместо щита, угловые орнаменты, бумажное зерно, обводки портретов, заголовок главы), перестановка вкладок и ширины заголовков (доски 03, 10–13), реальные цвета на доске 13 (в её старом снимке стояли заглушки `#FFFFFF`/`#000000`), `main` вместо `inst` у вариантов кнопок на досках 00 и 09 (в файле это главные экземпляры), доска 00 выросла с 770 до 7000 по высоте (компоненты M1). Системные отличия формата: тексты в файле «растут по высоте» (`grow = auto-height`, высота 18 вместо 19.5 у 13-пиксельного текста при `lh` 1.35), поэтому `grow` и высоты текстов при сверке игнорировались; в старых файлах была ошибка `@null` в прозрачности заливки; меню старой выгрузки не сворачивали иконки (без `paths` и линий), выгрузчик следует формату §12. Доски 00–13, меню и подсказки новым выгрузчиком **не** перезаписывались: окна по ним уже реализованы и сверены тестами (`hud_test`, `time_bar_test` и др.).

- **Снимок без `sim`.** `EventSnapshot { EventView event; bool placeholder; }`, `EventView` — одно модальное событие: `id`, `kind` и `category` (идентификаторы подписей `ui.event.kind.*` и `ui.event.category.*`), `title`, `subtitle`, `text` (перевод строки — перенос, длинные строки переносятся), `portrait` (файл под `assets/ui/patriarch/art`), `speaker`, `speaker_role`, `quote`, `date`, `autopause`, `default_option`, `options` (до трёх). `EventOptionView`: `title`, `detail` (стоимость или пояснение), `consequences` (`Explanation` — подсказка последствий **до выбора**), `available` и `unavailable_reason` (недоступный вариант не скрывается: тусклая заливка `paper2`, причина красным вместо строки, не в порядке Tab). Тексты событий готовые (мост E11-T19 подставляет переменные и падежи); окно добавляет только свои подписи из таблицы. **ЗАГЛУШКА:** `make_placeholder_event(loc)` — событие с доски 03 под ключами `ui.event.placeholder.*` (числа демонстрационные), пока нет движка событий (E11-T12 очередь и лимит модальных, E11-T13 автотултипы, E11-T19 мост). Форма снимка выбрана под то, что поставит E11-T19: очередь, лимит модальных окон в месяц и решение о показе остаются на стороне моста.
- **Выбор и клавиши.** На доске нет кнопки подтверждения, поэтому: наведение мыши подсвечивает вариант (зелёная заливка, светлый текст, золотой номер — на доске выбран первый), **клик выбирает** (окно скрывается, потом вызывается `on_choice(index)`: обработчик может показать следующее событие); цифры **1–3** (и цифровой блок) только подсвечивают и фокусируют вариант, **Enter** на нём выбирает; ↑/↓ (←/→) двигают подсветку, пропуская недоступные; Tab ходит по трём вариантам и не выходит из окна, подсветка следует за фокусом; кольцо фокуса (золотая рамка 2 px) показывается после клавиатуры (цифры тоже её включают) и нарисовано отдельным элементом рамки, чтобы не двигать содержимое. **Esc ничего не решает** и поглощается окном (спайк по Esc не закрывается). Игровые клавиши (пауза, скорость, камера) спят, пока окно открыто.
- **Последствия до выбора.** Вариант несёт `data-tip="event:N"`; хозяин передаёт `EventWindow::explanation(key)` в `TooltipManager` (спайк: цепочка провайдеров рядом с окном персонажа). Подсказка показывается при наведении и по фокусу с клавиатуры (§6.1); в заглушке у каждого варианта заголовок, строка «Казна −120 ₽», подпись «Последствия видны до выбора.».
- **Автопауза.** Окно зовёт `on_event_shown(EventView)` при каждом показе, хозяин решает, ставить ли паузу (`event.autopause`; настройка игрока «Пауза при событиях» и лимиты показа — решение владельца #295, E11-T12). Спайк (`--event`): ставит `TimeBar` на паузу (`press_speed(0)`), после выбора возвращает прежнюю скорость, если пауза была его.
- **Заглушка портрета.** Берётся из `assets/ui/patriarch/art` (`portrait_head_of_dynasty.jpg`, уже в реестре); новых ассетов нет. Значок герба — `icons/shield@green.svg`.
- **Отличия от доски.** Бейдж «АВТОПАУЗА» выровнен по центру (на доске выравнивание текста не задано). Строка пояснения варианта — `white-space: pre` с обрезкой по рамке 620×23 (в заглушке три пробела вокруг «·», как на доске). Больше трёх вариантов окно обрезает (в журнал пишется предупреждение): доска рассчитана на три, вопрос формы для более длинных событий — к E11-T19.
- **Спайк.** `patriarch_spike --event` показывает окно поверх карты (с `--offscreen 1920x1080 --frames 20 --shot файл.png` — снимок). Тесты: `tests/event_window_test.cpp` (прямоугольники, выбранный вариант, клик, цифры, Enter, Esc, Tab-ловушка, фокус, автопауза, недоступный вариант, подсказки, пустая таблица, 1280×720 и 21:9).

## 13. Доступность и порядок фокуса

- Фокус с клавиатуры виден всегда: золотая рамка 2 px (доска 09); активный элемент не пропадает при наведении мышью.
- Порядок Tab: верхняя полоса (пауза → скорость) → левая навигация (сверху вниз) → активное окно (слева направо, сверху вниз; вкладки перед содержимым; главное действие последним в своей колонке) → правая панель («Дела рода») → нижняя полоса. Модальное окно **захватывает** фокус и возвращает его на вызвавшую кнопку при закрытии; Esc закрывает окно или тост (в макете: подсказка «ПКМ — назад»).
- Горячие клавиши из макета: Пробел — пауза/продолжить; цифры 1–5 — скорость; цифры 1–3 в окне события — подсветить вариант (Enter подтверждает, §12.6); M — режим карты; Esc — меню или закрытие; ЛКМ — выбрать, ПКМ — назад. Привязка конкретных клавиш к пунктам навигации (в Olive Stone были [1]…[8], [Esc]) в новом макете **не указана** (#255).
- Цвет не единственный носитель смысла: риск — текст («Требует внимания», «Не хватает 40 ₽») **и** красный; выбранная карточка — рамка **и** бейдж «Выбрана»; недоступность — текст причины.
- Контраст (посчитан по токенам, WCAG): `text` на `paper` 11.2:1, `light` на `ink` 13.1:1, `light` на `green` 6.6:1, `quiet` на `panel` 7.3:1, `gold` на `ink` 8.1:1, `red` на `paper` 5.7:1, `muted` на `paper` 4.7:1 (выше 4.5, запас мал), `muted` на `paper2` **4.1:1 — ниже AA 4.5:1** (недоступная кнопка, вторичные подписи на карточках): вопрос #255 (затемнить `muted` на `paper2` или увеличить размер до 18).
- Цели нажатия ≥ 26×26 (кнопка закрытия), основные ≥ 40; зоны клика «Hit area / …» шире текста.
- Масштаб шрифта: не ниже 11 dp (§10).

## 18. Производительность RmlUi: правила для окон со списками (#93)

В замерах E3-T10 около 1% кадров при прокрутке списка давали пик CPU 10–12 мс. Причина оказалась **не** в списке «Отношения» (он виртуализирован: в документе ≈ 20 строк, окно строк сдвигается, `list window` p99 ≈ 0.04 мс) и не в генерации глифов, а в спайке: раз в 30 кадров обновлялась строка «N fps, M узлов» (`SetInnerRML` внутри `demo.rml`), а в этом же документе лежит список из 1000 строк.

**Как устроен RmlUi (6.3, `ElementDocument::UpdateLayout`):** раскладка считается **целиком по документу**, флаг «грязной» раскладки один на документ. Любая смена текста или размера, где бы она ни была, заставляет пересчитать все блоки документа, включая скрытые (`Hide()` ставит только `visibility: hidden`, `display: none` у корня документа не спасает). Документ с 1000 строк раскладывается ≈ 12 мс.

Правила:

1. Длинные списки (больше ≈ 50 строк) — только виртуализированные: в документе окно видимых строк плюс буфер, остальное — распорки (`pad_top`/`pad_bottom`), как в `CharacterWindow` (`kBufferRows`). Для нового дизайна это касается списка кандидатов, членов рода и летописи.
2. Часто меняющийся текст (счётчики, часы, readout) не кладите в документ с тяжёлым содержимым: выносите в отдельный маленький документ (как `apps/spike/ui/demo_fps.rml`); его раскладка стоит ≈ 0.02 мс. Дата и ресурсы верхней полосы — отдельный документ от окон.
3. Не меняйте текст и размеры в скрытых документах без необходимости: раскладка всё равно будет посчитана.
4. Проверка: `patriarch_spike --bench 1200 --offscreen 1920x1080` печатает гистограмму кадров и фазы UI (`list window`, `RmlUi update`, `RmlUi render`); при `PAT_BENCH_OUTLIERS=1` — номера кадров с фазой > 3 мс. Пики с периодом N кадров — признак периодического обновления текста.

Замеры (RTX 3050, 1920×1080, 1200 кадров, симуляция на скорости 5, три прогона):

| | кадр p99 / max, мс | кадров 8–16.6 мс | `RmlUi update` p99 / max, мс |
|---|---|---|---|
| до | 11.8–13.0 / 15.1–15.8 | 34 из 1170 | 11.4–12.4 / 14.2–15.1 |
| после | 4.8–5.3 / 6.9–7.0 | 0 | 0.45–0.49 / 0.56–1.02 |

Оставшийся p99 кадра ≈ 5 мс — карта (без UI p99 ≈ 3.3 мс на этой же машине) плюс UI (≈ 1 мс на кадр); пиков от UI больше нет.
