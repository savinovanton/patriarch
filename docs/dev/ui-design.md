# Дизайн интерфейса «Olive Stone» (World UI)

> Источник: макет владельца в Figma — [Patriarch Sovereign — World UI · Olive Stone](https://www.figma.com/design/XDiyizWZcVXGbpV5b2FlL7). Версия макета: «пока что такая» (2026-11-07), изменения ожидаются.
> **Статус макета: временный, тестовый формат** (владелец, 2026-11-07): интерфейс будет заменён другим; текущая реализация нужна, чтобы проверять движок, данные и игровой цикл, и не полируется.
> Экран макета: **1920×1080**, кадр «World / 01 · Обзор». Заменяет прежнюю тему «старинная карта» (#19).
> Значения цветов и размеров ниже взяты из экспортированных SVG (точные); расположение блоков — со снимков макета (приблизительное, помечено [проверить]).

## 1. Идея

Тёмный оливково-каменный интерфейс поверх карты; золото — только для рамы экрана и акцентов; светлый тёплый текст. Вся карта видна в центре, панели лежат по краям и не закрывают её без нужды.

Фон кнопок меню светлее плашек (`#3D4736` против `#282F26`): активное и обычное состояния различаются рамкой и заливкой.

## 4. Зоны экрана (кадр 1920×1080)

1. **Рама** — поверх всего, не перехватывает мышь.
2. **Левый верх** — плашка государства («Московское царство», «Государев двор») с иконкой.
3. **Верх, слева направо** — полоса ресурсов: Казна, Запасы, Войско, Вера, Влияние (значение + прирост за период).
4. **Правый верх** — три значка-сигнала (колокол, грамота, посольство) со счётчиками; ниже дата («1 сентября 1703», «Погода») и кнопки скорости (пауза, 1–5).
5. **Левый край** — вертикальное меню из 9 кнопок: Мир [1], Держава [2], Владения [3], Войско [4], Церковь [5], Хозяйство [6], Дипломатия [7], Летопись [8], Меню [Esc]. В названиях файлов макета указаны горячие клавиши.
6. **Правая панель** — «Владения» с вкладками «Города / Войска / Династии», список (Москва, Тверь, Новгород — с числами), блок «Войска» (например «Большой полк»).
7. **Правый низ под панелью** — «Дела государства»: карточки решений («Собор ожидает решения», «Прибыл посол»).
8. **Левый низ** — «Летопись»: журнал событий с временем.
9. **Правый низ** — маленькие кнопки управления картой.
10. **Центр** — карта; подписи поселений поверх неё («Москва» с иконкой).

## 6. Реализация

- Технический выбор для изображений: [ADR-0005](../adr/0005-ui-images.md) (PNG через WIC, SVG через RmlUi + lunasvg).
- Тема — общий RCSS с токенами; окна (`src/ui`) подключают его вместо собственных цветов.
- Порядок работ (UI-1, #112): ассеты и изображения → каркас HUD (плашка государства, ресурсы, левое меню, рама) → правая панель → «Дела государства» → «Летопись» → кнопки карты.

## 7. Состояние реализации (2026-11-07)

Готово в спайке (`apps/spike/ui/hud.rml`, `hud.rcss`, `olive.rcss`, `timebar.*`): рама, табличка государства, полоса ресурсов, значки-сигналы, левое меню (9 кнопок), панель «Владения» с вкладками «Города / Войска / Династии» и блоком «Войска», «Дела государства» (карточки), «Летопись», панель даты и скорости. Данные — заглушки (`make_test_hud`) до появления экономики и двора.

**Тексты (#233):** все подписи HUD, полосы времени и окна персонажа берутся из таблицы `data/loc/ru/ui.pd` через `pat::loc::Localizer` (параметры, `{n:group}`, `plural`); окна принимают `const Localizer&` и имеют `relocalize()`. Снимки несут числа и ключи, а не готовые фразы; отсутствующий ключ виден как `[[ключ]]`. Подробно — [localization.md](localization.md) §9. Добавляя подпись в окно, заведите ключ `ui.<окно>.<смысл>` в `ui.pd`, иначе `contentlint` и тесты не пропустят.

**Титры (UI-213):** окно «Титры» (`credits.rml`, `credits.rcss`, `pat::ui::CreditsWindow`) открывается пунктом «Меню» левого меню HUD; список строится из данных (`data/credits`), см. [credits.md](credits.md).

Не готово: кнопки управления картой (правый низ), подписи поселений в стиле макета, окно персонажа в теме Olive Stone, прокрутка списков, тултипы HUD. Размеры и позиции блоков измерены по снимкам макета и ждут сверки с Figma (лимит MCP).

## 8. Производительность RmlUi: правила для окон со списками (#93)

В замерах E3-T10 около 1% кадров при прокрутке списка давали пик CPU 10–12 мс. Причина оказалась **не** в списке «Отношения» (он виртуализирован: в документе ≈ 20 строк, окно строк сдвигается, `list window` p99 ≈ 0.04 мс) и не в генерации глифов, а в спайке: раз в 30 кадров обновлялась строка «N fps, M узлов» (`SetInnerRML` внутри `demo.rml`), а в этом же документе лежит список из 1000 строк.

**Как устроен RmlUi (6.3, `ElementDocument::UpdateLayout`):** раскладка считается **целиком по документу**, флаг «грязной» раскладки один на документ. Любая смена текста или размера, где бы она ни была, заставляет пересчитать все блоки документа, включая скрытые (`Hide()` ставит только `visibility: hidden`, `display: none` у корня документа не спасает). Документ с 1000 строк раскладывается ≈ 12 мс.

Правила:

1. Длинные списки (больше ≈ 50 строк) — только виртуализированные: в документе окно видимых строк плюс буфер, остальное — распорки (`pad_top`/`pad_bottom`), как в `CharacterWindow` (`kBufferRows`).
2. Часто меняющийся текст (счётчики, часы, readout) не кладите в документ с тяжёлым содержимым: выносите в отдельный маленький документ (как `apps/spike/ui/demo_fps.rml`); его раскладка стоит ≈ 0.02 мс.
3. Не меняйте текст и размеры в скрытых документах без необходимости: раскладка всё равно будет посчитана.
4. Проверка: `patriarch_spike --bench 1200 --offscreen 1920x1080` печатает гистограмму кадров и фазы UI (`list window`, `RmlUi update`, `RmlUi render`); при `PAT_BENCH_OUTLIERS=1` — номера кадров с фазой > 3 мс. Пики с периодом N кадров — признак периодического обновления текста.

Замеры (RTX 3050, 1920×1080, 1200 кадров, симуляция на скорости 5, три прогона):

| | кадр p99 / max, мс | кадров 8–16.6 мс | `RmlUi update` p99 / max, мс |
|---|---|---|---|
| до | 11.8–13.0 / 15.1–15.8 | 34 из 1170 | 11.4–12.4 / 14.2–15.1 |
| после | 4.8–5.3 / 6.9–7.0 | 0 | 0.45–0.49 / 0.56–1.02 |

Оставшийся p99 кадра ≈ 5 мс — карта (без UI p99 ≈ 3.3 мс на этой же машине) плюс UI (≈ 1 мс на кадр); пиков от UI больше нет.
