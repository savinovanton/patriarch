# Имена, отчества и портреты

> Статус: E7-T09 (готово как данные и чистые функции; вызов из рождений — E7-T12, из UI — E7-T21). Код — `src/sim/names.cpp` (`pat::sim`, `pat/sim/names.hpp`), схемы — `src/data/names_schemas.cpp`, сборщик — `src/content/names_content.cpp`, тесты — `tests/names_test.cpp`, `tests/names_content_test.cpp`. Данные — `data/names/*.pd`, тексты — `data/loc/ru/names.pd`.
> Связано: GDD 01 §2.1 (имя, отчество, пол, портрет), ADR-0006 (колонки `name`, `portrait`), эпик E7 §3 стр. 8 (поток `demography.names`), [data-authoring.md](data-authoring.md), [localization.md](localization.md), [data-reference.md](data-reference.md) (поля видов `given_name`, `surname`, `portrait`, `naming_rules`).

## 1. Из чего состоит имя

| Часть | Откуда | Где хранится |
|---|---|---|
| имя | пул `given_name` (`data/names/given_male.pd`, `given_female.pd`) | **id** объекта (`ivan`, `anna`) — в колонке `name` персонажа (интернированная строка; так же, как у рода в `name` лежит id определения) |
| отчество | **от имени отца**, форма по полу ребёнка | не хранится: выводится из `father` и колонки `name` отца |
| фамилия | **от рода** (`surname`), мужская или женская форма | не хранится: выводится из рода |
| портрет | пул `portrait` по полу и возрастной полосе | колонка `portrait` (`u16`; 0 — «без портрета») |

Формы **записаны в данных явно**, морфологического алгоритма нет: у каждого мужского имени есть `patronymic_son_key` («Петрович») и `patronymic_daughter_key` («Петровна»); у каждого рода — `male_key` («Меншиков») и `female_key` («Меншикова»). Склонять по падежам игре не нужно (в M1 имена стоят в именительном). Исключения вроде «Кузьмич/Кузьминична» и «Ильич/Ильинична» — просто другие строки в данных. У женских имён отчества нет: сборщик отклоняет женское имя с полем `patronymic_*` (`PD115`).

Данные хранят **ключи локализации**, а не тексты: `name_key = "name.given.ivan"`, сами строки — в `data/loc/ru/names.pd`. Пул получил отдельные ключи отчеств (`name.patronymic.ivan.son`, `.daughter`) и фамилий (`name.surname.menshikov.male`, `.female`). Ключи проверяет `contentlint` как все остальные (нет текста → `CL`-диагностика, лишний текст → `CL002`/`CL004`).

Полное имя собирает `sim::person_name_keys(pools, given, father_given, dynasty_id, sex)`: возвращает три ключа (`given`, `patronymic`, `surname`); часть, которую нельзя построить (отец неизвестен, отец не из пула, род без фамилии), пуста — не ошибка. Тексты по ключам и порядок слов («Анна Петровна Меншикова») — дело UI (`E7-T21`, мост `src/game`); тест `names content: names and patronymics are right for both sexes on a test set` проверяет полный цикл на мужчинах и женщинах, включая «Никитич/Никитична», «Кузьмич/Кузьминична», «Ильич/Ильинична».

## 2. Данные

```
given_name "petr" {
    sex = male
    weight = 24                                   # относительная частота в пуле
    name_key = "name.given.petr"
    patronymic_son_key = "name.patronymic.petr.son"
    patronymic_daughter_key = "name.patronymic.petr.daughter"
}
given_name "anna" { sex = female  weight = 25  name_key = "name.given.anna" }
surname "menshikov" { dynasty = dynasty:menshikov  male_key = "name.surname.menshikov.male"  female_key = "name.surname.menshikov.female" }
portrait "m_prime_1" { sex = male  stage = prime  portrait_id = 121 }
naming_rules "main" { parent_bonus = 40  grandparent_bonus = 25 }
```

Что даёт стартовый набор M1: **30 мужских и 30 женских имён**, фамилии четырёх родов из `data/dynasties/m1.pd`, **20 портретов-заглушек** (по 2-3 на пол и полосу), `naming_rules`. Пул — **общий**, это не список исторических лиц: стартовых персонажей сценария (и сверку «нет совпадений с реальными лицами рода») ведёт E30 и владелец при ревью данных; случайное сочетание вроде «Пётр Иванович Меншиков» возможно, но это рядовые имена, не привязанные к реальным людям. Расширение пула и правка весов — обычная правка `.pd`, пересборка не нужна; мод заменяет объект целиком по тому же `(вид, id)` и может добавить новые имена (в мод-корне нужны и тексты в `loc/ru/*.pd`).

Правила, которые схема не выражает, проверяет сборщик `pat::content::build_name_pools` (`PD115`, позиция — объект или поле) и итоговая `sim::validate`:

- мужское имя — обе формы отчества, женское — ни одной;
- по одному `surname` на род, и **у каждого рода из `dynasty` он должен быть** (новый род в данных → нужен `surname`);
- `portrait_id` уникален и не 0;
- в пуле есть имя каждого пола и портрет для **каждого** пола и **каждой** возрастной полосы (чтобы выбор не искал замену);
- ровно один `naming_rules`.

## 3. Выбор имени новорождённому

`sim::choose_given_name(pools, rng, context)` — **чистая функция**: мира не читает, мир не меняет, случайность берёт из переданного генератора. Вызывающий (рождение, E7-T12) передаёт `world.rng().stream("demography.names")` (поток из эпика E7 §3 стр. 8).

Вход `NamingContext`: пол; id имени «родителя той же линии» и «деда/бабки той же линии»; id имён **живых** братьев и сестёр **того же пола**. Алгоритм:

1. кандидаты — имена пула нужного пола, **кроме** имён живых братьев/сестёр того же пола (никаких двух Иванов среди живых братьев);
2. вес кандидата — `weight` из данных; если имя совпадает с именем родителя — прибавка `parent_bonus`, с именем деда — `grandparent_bonus` (прибавки складываются, если это одно имя). Для сына «родитель» — отец, «дед» — отец отца; для дочери — мать и мать матери **[предл.]**: задача говорит об отце и деде, для дочерей мы переносим правило по женской линии, чтобы имена передавались и им. Решение можно изменить только в вызывающем коде (он выбирает, чьи id передать);
3. если все имена пола заняты братьями, **исключение снимается** и имя повторяется (лучше повтор, чем безымянный; такой случай при пуле ≈ 30 имён и потолке 14 детей почти невозможен);
4. выбор взвешенный: `индекс = (draw · сумма_весов) >> 32` по накопленной сумме в порядке пула (пул отсортирован по id).

Результат — индекс в `pools.given_names` (в колонку `name` идёт `given_names[i].id`) или `kNoName`, если в пуле нет имён этого пола (тогда колонка остаётся «безымянной», как раньше).

**Правило потока (эпик E7 §3 стр. 8):** функция берёт из генератора **ровно одно число** во всех ветках (пустой пул, все имена заняты, есть бонусы…), без отбраковки: поэтому добавление условия или имени не сдвигает последовательность для остальных. Тест `names: exactly one draw is used in every branch` следит за этим для обеих функций. Одинаковый seed и порядок вызовов дают те же имена (`names: the same seed gives the same names…`).

## 4. Выбор портрета

`sim::choose_portrait(pools, rng, sex, stage)` — равномерный выбор среди портретов этого пола и этой возрастной полосы (`LifeStage` из `demography.hpp`: ребёнок, подросток, зрелый, средний возраст, старость; границы — `demography_rules.life_stages`). Если для полосы портретов нет (мод, неполный пул), берётся **ближайшая** полоса того же пола (из двух равноудалённых — младшая), а если портретов этого пола нет вовсе — 0. Одно число из генератора в любой ветке.

Новорождённому — полоса `Child`. Когда персонаж переходит в следующую полосу, система вызывает функцию снова (смена полос и расписание — E7-T10/T11; сами гравюры и их соответствие лицу — E26). Раскладка id заглушек **[предл.]**: `100·пол + 10·полоса + номер` (мужские 101…, женские 201…).

## 5. Как это подключается дальше

- **E7-T12 (рождения):** `Birth` берёт `NamePools` и поток `demography.names`; имя — `choose_given_name`, портрет — `choose_portrait(…, Child)`; затем `set_character_name(id, interner.intern(given_names[i].id))`, `set_character_portrait`. Порядок извлечений из потока фиксирован: сначала имя, потом портрет.
- **E7-T21 (мост «снапшот → UI»):** `find_given_name` по колонке `name` персонажа и его отца + `person_name_keys` + `Localizer` дают «Анна Петровна Меншикова».
- **E30 (сценарий):** исторически заданные персонажи получают `name` как id имени из пула (при необходимости имя добавляют в данные).

## 6. Открытое и допущения

- **[проверить] Отчество в 1703 году.** Отчество на -ович/-евич было отличием высшего круга; остальные писались «Иванов сын», а женские формы на -овна/-евна встречались как «честь» ещё реже. Для читаемости игра даёт отчество всем членам рода единообразно. Если владелец захочет исторической строгости — это добавление поля «вичество» к рангу/должности (E10), данные уже хранят обе формы.
- **[проверить] Частоты имён** (`weight`) — предложение по общему впечатлению о частоте православных имён среди знати начала XVIII века, не статистика; несколько имён пула редки или поздни для конкретных родов (Владимир, Екатерина, Лев, Александр — растут позже). Правится в данных без пересборки.
- **Имена по святцам.** Имя в реальности давали по именинам (святой дня рождения или крещения). Это не моделируется; хук для него — расширение `NamingContext` датой и поправка весов (`E22`).
- **Брак и фамилия.** Фамилия берётся из рода, переданного вызывающим; смена фамилии женщины при браке — правило E8 (вызывающий передаёт род мужа).
- **Баланс.** Значения `parent_bonus = 40` и `grandparent_bonus = 25` — **[предл.]**: при сумме весов ≈ 400 имя отца получает примерно 10 % шанса, деда — 6 %.
