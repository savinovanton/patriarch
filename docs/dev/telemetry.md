# Телеметрия подсистем (E2-T06)

Телеметрия — диагностический наблюдатель. Она выключена по умолчанию, не входит в
`World`, хеши, WU, сохранения и реплеи и не должна участвовать в решениях симуляции.
Таймеры хранят целые наносекунды; перевод в микросекунды выполняет только вывод.

## simcli

```powershell
.\out\win-msvc\tools\Release\simcli.exe --days 800 --seed 7 --telemetry --telemetry-json out/timing.json --telemetry-csv out/timing.csv
.\out\win-msvc\tools\Release\simcli.exe --days 800 --seed 7 --speed unlimited --telemetry --telemetry-window 256
```

- `--telemetry` включает сбор и печатает сводку после прогона.
- `--telemetry-json FILE` и `--telemetry-csv FILE` также включают сбор; можно указать
  оба файла — они получат одну и ту же сводку.
- `--telemetry-window N` задаёт окно последних N тиков (1…16 384, по умолчанию 1 024).
  До заполнения окна учитываются только завершённые тики, а не пустая ёмкость.
- `--quiet` / `--hash-only` подавляют таблицу, сохраняя явно запрошенные файлы.
- Поддерживаются прямой запуск, `--speed`, `--load`, `--replay`, `--verify-determinism`.
  В последнем режиме наблюдается эталонный прогон, который сравнивается с вариантами
  без наблюдателя. После загрузки/restore старое окно очищается.
- Ошибки записи возвращают exit code 1; одинаковые пути выходных файлов отклоняются.

Базовые метрики:

| Имя | Что измеряется |
|---|---|
| `sim.tick` | Полный тик после открытия диагностического кадра |
| `sim.tick.weekly/monthly/quarterly/yearly` | Та же полная длительность, только на соответствующих календарных границах |
| `sim.commands.internal` | Обработка команд прошлого тика |
| `sim.commands.external` | Получение и обработка внешней очереди |
| `system.<имя>` | Вызов конкретной системы, только когда наступил её cadence |

Теги границ не образуют разбиение: годовой тик может одновременно быть месячным,
квартальным и недельным. Это не сумма времени всех недельных/месячных систем.
Вложенные интервалы **inclusive**, поэтому родитель и дочерние зоны нельзя складывать.

## Значение агрегатов

JSON schema 1 имеет `unit: "ns"`, ёмкость/размер окна, первый/последний tick index и
массив метрик в порядке регистрации. Для метрики:

- `calls` — число завершённых вызовов в окне, `active_ticks` — число тиков с вызовами;
- `last_ns` / `last_calls` — последнее завершённое значение;
- `per_tick` — сумма длительностей данной метрики на каждом тике, включая нули;
- `active` — суммы только на тиках, когда были вызовы;
- обе группы содержат `samples`, `total_ns`, `mean_ns`, `p50_ns`, `p95_ns`, `p99_ns`,
  `max_ns`; mean округлён вниз до наносекунды, квантили — **nearest-rank**.

При нескольких вызовах за тик квантили относятся к **сумме на тике**, а не отдельным
вызовам. Для редкой системы `per_tick.p95` может быть нулём — смотрите также `active`.
CSV содержит две строки на метрику (`kind=per_tick/active`), единицы также наносекунды.
Имена экранируются для JSON/CSV. Переполнение сумм насыщается и помечается `saturated`;
такую сводку нельзя считать точной. Флаг коллектора сохраняется до очистки окна.

Консоль печатает **active-tick** mean/p50/p95/p99 в микросекундах. Общая строка
`tick time (ms)` измеряет вызов `tick()` снаружи за весь прогон и использует тот же
nearest-rank; её окно и границы отличаются от внутреннего `sim.tick`.

## API и ограничение памяти

```cpp
auto enabled = simulation.enable_telemetry(1024); // после регистрации систем
if (!enabled) { /* обработать enabled.error() и не продолжать */ }
simulation.run_days(800);
auto summary = simulation.telemetry_snapshot(); // только между тиками
```

`Simulation::add_system()` отключает сбор, поскольку меняет раскладку метрик;
после регистрации включите его заново. `restore_state()` очищает окно, сохраняя ID.
Включение/отключение и доступ к живому коллектору — только в потоке симуляции между
тиками. Дополнительные зоны регистрируются заранее:

```cpp
auto registered = simulation.telemetry()->register_metric("economy.monthly");
// Сохранить полученный MetricId как диагностический идентификатор.
// В System::run():
PAT_SCOPED_TIMER(context.telemetry, metric_id, "economy.monthly");
```

Макрос совмещает RAII-таймер и существующую Tracy-зону; имя Tracy — строковый литерал.
ID устраняет поиск/регистрацию строк в горячем пути. `nullptr`/неактивный коллектор не
читают часы. Имена, регистрация, snapshot/export могут выделять память; begin/end/record
и запись таймера используют заранее выделенные слоты. Произвольные worker-потоки не
должны писать в один коллектор: он **single-writer**, без mutex и TLS. Worker-измерения
нужно собирать отдельно и сливать на границе задачи; wall time не меняет WU.

Окно — общее по тикам, а не «последние N запусков каждой системы». По умолчанию
выделяются 64 × 1 024 слота по 16 байт + 1 024 tick index по 8 байт; это около 1 МиБ
плюс имена/служебные объекты. Ограничения фабрики: 128 метрик и 1 048 576 слотов
всего. Превышение возвращает ошибку. История/сортировка не находятся внутри таймеров.

`core::Telemetry::snapshot(true)` возвращает собственную историю по возрастанию
порядка кадров. Без `true` история не копируется. Оба варианта — отделённые значения,
которые не меняются при последующих тиках. Сам живой коллектор читать из UI нельзя.

## Будущий оверлей и Tracy

```cpp
auto summary = runner.latest_telemetry(); // atomic shared_ptr<const TelemetrySnapshot>
if (summary) {
    // Читать metrics/per_tick/active; null означает, что сбор выключен.
}
```

Runner строит и публикует сводку вместе с обычной публикацией мира; сортировка
выполняется **вне tick-таймера**, но имеет свою стоимость в потоке симуляции.
Мир и телеметрия — отдельные atomic-ссылки: для строго парного отображения сверяйте
`summary->last_frame` с tick index мира. Сам оверлей в E2-T06 не добавляется.

Tracy остаётся существующей опцией `PATRIARCH_ENABLE_TRACY`: новые command/system
scope используют её макросы, конец тика отмечается `PAT_PROFILE_FRAME()`.
Сборщик числовых агрегатов не требует Tracy. Проверка отдельной опциональной Tracy
конфигурации продолжает отслеживаться задачей #32.

## Проверка и бенчмарк

```powershell
ctest --preset win-msvc-debug -R "telemetry|golden|simcli_determinism"
.\out\win-msvc\bench\Release\bench.exe --benchmark_filter=sim.telemetry_tick --benchmark_min_time=0.1s --benchmark_repetitions=3 --benchmark_out=out/telemetry-bench.json --benchmark_out_format=json
```

`sim.telemetry_tick/0` — наблюдатель выключен, `/1` — включён. Каждый batch начинает
один и тот же мир (100 родов, 400 провинций, 5 000 персонажей, seed 7), выполняет
32 тика. Restore, snapshot/sorting и хеш — вне измерения; `real_time` бенчмарка относится
к batch, `wall_ns_per_tick` и `observer_ns_per_tick` — к одному тику.

Автоматическая сверка требует 32 завершённых кадра и вызова `sim.tick`, сумму внутренних
длительностей не больше внешнего интервала того же batch и одинаковый итоговый хеш
в обоих режимах. Разница внутренних/внешних часов не называется «чистыми накладными
расходами»: внешний интервал включает открытие/закрытие кадра и инструментирование.
Сравнение off/on показывает суммарную дополнительную стоимость включённого наблюдателя.
Порогов времени в тестах нет; нестабильные измерения не используются для точных выводов.

Целевые тесты покрывают окно и wrap-around, неактивные/повторные вызовы, агрегацию и
экспорт, насыщение, RAII, каденсы, неизменность World/WU/журнала/save bytes, runner и
реальный CLI (включая threaded/replay). Golden-значения и версии игровых форматов не менялись.

## Результат на целевом ПК, 2026-11-07

[Исходный JSON бенчмарка](../benchmarks/E2-T06-telemetry-benchmark.json): Windows 11,
i5-12400F, MSVC 19.44 Release, logical CPU 0, 3 повтора, минимум 0.1 с на измерение
и 0.01 с прогрева. Одна запланированная пара off/on, без повторов ради результата.
Окно в бенчмарке — 32 тика; snapshot/sorting выключены из измеряемого интервала.

| Режим | Внешнее среднее, мкс/тик | Внутренний sim.tick, мкс/тик | RSD внешнего среднего |
|---|---|---|---|
| Выключен | 8.215 | — | 3.49% |
| Включён | 8.583 | 8.542 | 4.00% |

Номинальная разница +0.368 мкс (+4.48%) в этом прогоне не является точной универсальной
ценой: три повтора дают ограниченную оценку разброса, доверительный интервал не строился.
Внутреннее среднее не превышает внешний интервал; это проверено для каждого batch.
Совпадает итоговый хеш обоих режимов. Из опубликованного JSON убраны только host_name
и executable, добавлены параметры и SHA-256 измеренных исходников; timings не изменялись.

Отдельный `simcli --verify-determinism --days 800 --seed 7 --telemetry` завершился
успешно с итоговым хешем `f3b290c3f3e40b42` и 800 завершёнными кадрами телеметрии.
Это проверка совместимости с replay/save/threaded, а не бюджет позднего игрового мира.
Целевые проверки прошли на Windows в Debug/Release/ASan; накладные расходы Tracy,
публикация сводок runner и настоящий оверлей этим бенчмарком не измерены.
