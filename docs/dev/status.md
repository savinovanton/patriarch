## 2. Что уже умеет код (быстрый тур)

```cpp
#include "pat/sim/demo_scenario.hpp"   // временный сценарий-заглушка (не контент игры)
#include "pat/sim/runner.hpp"          // поток симуляции со снапшотами
#include "pat/sim/replay.hpp"          // реплеи
#include "pat/sim/save.hpp"            // сохранения

using namespace pat::sim;
Simulation sim = demo::make_simulation({/*seed*/ 1});
sim.run_days(365);                                         // 1 тик = 1 день, юлианский календарь, старт 1703-01-01
sim.submit(Command{DynastyId(), cmd::AdjustHonor{DynastyId(0), 10}});   // из потока UI; применится в начале тика
auto snap = sim.snapshot();                                // shared_ptr<const World>, безопасно читать из другого потока
auto bytes = serialize_save(sim.world(), sim.pending_internal());       // сохранение (zstd)
```

- **Мир** (`World`): таблицы династий/провинций/персонажей (SoA), индексы, `check_invariants()`, `compute_hash()` (хеш по частям: calendar/rng/dynasties/provinces/characters).
- **Команды**: 5 заготовок (`SetProvinceOwner`, `CreateCharacter`, `KillCharacter`, `SetDynastyHead`, `AdjustHonor`); каждая проходит `validate()` и пишется в `CommandLog`.
- **Цикл**: календарь → внутренние команды → внешние команды → системы по каденсу (Daily/Weekly/Monthly/Quarterly/Yearly), учёт WU, арена на тик, `TaskExecutor` (пока последовательный).
- **Поток**: `SimulationRunner` (скорости, `step(n)`, публикация снапшотов).
- **Реплей/сейв**: форматы `PRP1`, `PSV1`; golden-тесты закрепляют хеши.
- **CLI**: `simcli --help`.

## 3. Ближайшие шаги (рекомендуемый порядок «сначала риск»)

1. **E3 сокращённый (≈22 дня)** — самый рискованный кусок: SDL3 + D3D11 + RmlUi + объёмный рельеф. Задачи — `docs/epics/E03-engine-spike.md`. Первые под-шаги: E3-T01 (окно SDL3), E3-T02 (рендерер D3D11, `IRenderer`), E3-T03 (`tools/mapgen`: процедурный рельеф + провинции), E3-T04 (CDLOD-рельеф, камера, выбор лучом). В `vcpkg.json` добавить `sdl3`, `rmlui`, `freetype` (и `imgui` для dev-оверлеев) — с записью в ADR/обновлением baseline.
2. **E2 (≈20 дней)** — бенчмарки (Google Benchmark уже в `vcpkg.json`), `tools/stressgen`, спайки A/B/C, CI-гейт регрессий. Начинать с E2-T01/T02 (можно параллельно с E3).
3. Затем M1 по `docs/02-epics-roadmap.md` (эпики E4, E5…E13).

Решения, которые нужны от владельца до/во время E3 (см. `docs/03-open-questions.md`, «вопросы по объёмной карте»): границы карты, 3D-модели юнитов/зданий или маркеры, сезоны, стилизация, источник DEM, минимальная видеокарта.

## 4. Известные ограничения и долги

- Игровой код — заготовки: пять команд и три сущности нужны для отработки механизмов; реальные правила появятся с M1 по GDD.
- `clang-cl`, `clang-tidy`, Linux в CI не подключены; **совпадение golden-хешей на другом компиляторе/ОС не проверено** (на MSVC во всех конфигурациях совпадает).
- Интеграция Tracy (`PATRIARCH_ENABLE_TRACY`) заведена, но не проверялась (нет порта в `vcpkg.json`).
- Способ публикации снапшотов — глубокая копия `World` (просто и безопасно); оптимизацию выберет E2-T05.
- `TaskExecutor` пока только последовательный; потоковый пул — по результатам E2-T03.
- `StaticVec` вместо `SmallVec` (без выхода в кучу).
- Контент: русская локализация, события и DSL не начаты (E4/E11/E22).
- Даты исторических реформ и имя местоблюстителя в GDD помечены `[проверить]`.
