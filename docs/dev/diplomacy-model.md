## 3. Типы и единицы

- Мнение, доверие, сила, очки согласия — `std::int32_t` (целые пункты; в таблицах `i16`/`u8`); дроби — промилле `‰`, усечение к нулю после **каждого** умножения; ни `float`, ни `double`.
- Деньги — копейки `i64` (`Kopecks`); в данных — рубли `_rub` или копейки `_kop`, как в `economy.pd`.
- Даты — `Date`; `kNoDate` — «бессрочно».
- Перечисления (стабильны навсегда, `u8`): `TreatyKind` 1 `alliance`, 2 `pledge`, 3 `marriage_pact`, 4 `claim_support`, 5…15 резерв M2 (`trade`, `patronage`, `settlement`, `passage`); `OfferKind` 1…4 = `TreatyKind` (заключить), 16 `favor`, 17 `dissolve` (расторгнуть по согласию); `FavorKind` 1 `credit`, 2…7 резерв M2 (`vote`, `endorse`, `support_suit`); `TreatyState` 1 `Active` (закрытые строки удаляются, история — в журнале); `Answer` 1 `Accept`, 2 `Refuse`, 3 `Counter`; `TreatyEnd` 1 `Expired`, 2 `Mutual`, 3 `TiesEnded`, 4 `ClaimGone`, 5 `HouseExtinct`, 6 `Breach`; `BreachCause` 1 `BreakTreaty`, 2 `Tonsure`, 3 `BreakBetrothal`, 4 `Denounce`, 5 `SupportWithdrawn`, 6 `SupportSwitched`, 7 `Event`.
- Коды причин модификаторов `RelationReason` (`u16`, своё пространство, не `OpinionReason` E7): 1 `Gift`, 2 `FavorGranted`, 3 `Ingratitude`, 4 `OfferRefused`, 5 `TreatyHonoured`, 6 `TreatyBroken`, 7 `Denounced`, 8 `FalseDenunciation`, 9 `Scenario`, 10…99 резерв E15, 100…199 — события E11 (ключ в данных события).

## 4. Таблицы

`World::diplomacy()` — семь таблиц; все обходы по возрастанию ключа; производные индексы в сейв не попадают.

### 4.1 `DiplomacyMeta` — одна строка (раздел 112)

| Колонка | Тип | Смысл |
|---|---|---|
| `enabled` | `u8` | 0 — дипломатия выключена: команды 200…211 (кроме 211) отклоняются `Disabled`, системы не работают, `political_gain` = 0 |
| `flags` | `u8` | бит 0 `ai_may_offer_to_player` (стартовое значение из данных, меняет 211) |
| `next_treaty_id`, `next_offer_id` | `u32` | монотонные счётчики (с 1) |
| `log_seq` | `u32` | номер последней записи журнала (курсор on-action E11) |
| `signed`, `broken`, `refused`, `expired` | `u32` | счётчики для метрик T16 |

### 4.2 `RelationTable` — отношения «род → род» (раздел 113)

По возрастанию `(a, b)`; ≤ `kMaxRelationsPerHouse = 40` строк на `a` и ≤ `kMaxRelationRows = 4096` всего; `a ≠ b`, оба — роды (не корона, не Церковь).

| Колонка | Тип | Смысл |
|---|---|---|
| `a`, `b` | `DynastyId` | направление: «как `a` относится к `b`» |
| `trust` | `u8` 0…100 | доверие `a` к `b`; без строки — `trust_default` (50) |
| `flags` | `u8` | бит 0 — вражда (§5.4); биты 1…3 — резерв M2 (уровень вражды, месть по наследству) |
| `gift_ready` | `Date` | раньше этой даты `a` не может дарить `b` (кулдаун) |
| `propose_ready` | `Date` | раньше этой даты `a` не может слать `b` предложения (после отказа `b` или разрыва договора `a`) |
| `created` | `Date` | для тай-брейка вытеснения |

Строка нужна, если есть модификатор, доверие ≠ 50, вражда, будущая дата кулдауна, договор, долг услуги или открытое предложение между `a` и `b`. **Вытеснение** (при создании 41-й строки рода `a`): из строк без договора, без долга и без открытых предложений удаляется строка с наименьшей значимостью `|Σ модификаторов| + |trust − 50|`, ничья — больший `b`; если вытеснить нечего — команда игрока/ИИ отклоняется `RelationLimit`, системная реакция пропускает модификатор и пишет `RelationSkipped` в журнал. Пустые строки (всё по умолчанию, даты в прошлом) удаляет `diplomacy.decay`.

### 4.3 `RelationModTable` — модификаторы мнения (раздел 114)

По возрастанию `(a, b, slot)`; ≤ `kMaxModsPerRelation = 6` на пару.

| Колонка | Тип | Смысл |
|---|---|---|
| `a`, `b` | `DynastyId` | |
| `slot` | `u8` 0…5 | порядок добавления (сдвигается при удалении) |
| `reason` | `u16` | `RelationReason` |
| `initial` | `i16` −100…100 | значение при появлении |
| `months_total`, `months_left` | `u8` 1…120 | срок затухания и остаток; текущее значение `initial · months_left / months_total` (усечение к нулю) |
| `since` | `Date` | |

Один модификатор каждой причины на пару: повтор той же причины **пересчитывает** запись (подарок суммируется с коридором, обида берёт более тяжёлое из двух и полный срок). При седьмом разном модификаторе вытесняется запись с наименьшим `|текущее значение|`, ничья — меньший `slot`.

### 4.4 `TreatyTable` — договоры (раздел 115)

По возрастанию `id`; ≤ `kMaxTreaties = 512`; на род ≤ `max_treaties_per_house = 8` (данные, жёсткий потолок кода 8); не больше одного договора каждого вида на неупорядоченную пару.

| Колонка | Тип | Смысл |
|---|---|---|
| `id` | `u32` | `next_treaty_id` |
| `kind` | `u8` | `TreatyKind` |
| `a`, `b` | `DynastyId` | `a` — инициатор (`pledge`: вноситель; `claim_support`: сторонник), `b` — другая сторона |
| `start`, `end` | `Date` | `end = kNoDate` у `marriage_pact` |
| `amount_kop` | `i64` | залог на счёте короны (`pledge`), иначе 0 |
| `claimant` | `CharacterId` | претендент (`claim_support`), иначе пусто |
| `person_a`, `person_b` | `CharacterId` | первая пара помолвки/брака, по которой заведён `marriage_pact` (для тултипа), иначе пусто |
| `flags` | `u8` | бит 0 `public` = 1 всегда в M1 (тайные — M2, E14); бит 1 — поддержка уже выставлена (`claim_support`) |

### 4.5 `OfferTable` — открытые предложения (раздел 116)

По возрастанию `id`; ≤ `kMaxOffers = 256`; ≤ 3 открытых на неупорядоченную пару; ≤ 2 открытых от ИИ-родов роду игрока и ≤ 1 от каждого ИИ-рода (§14.3). Отвеченное, отозванное или пустое предложение **удаляется** (итог — в журнале).

| Колонка | Тип | Смысл |
|---|---|---|
| `id` | `u32` | `next_offer_id` |
| `kind` | `u8` | `OfferKind` |
| `from`, `to` | `DynastyId` | предлагающий и ответчик |
| `months` | `u16` | срок договора (0 — для `favor`, `dissolve`) |
| `amount_kop` | `i64` | залог или сумма услуги |
| `depositor` | `u8` | `pledge`: 0 — вносит `from`, 1 — вносит `to` |
| `claimant` | `CharacterId` | `claim_support` |
| `treaty` | `u32` | `dissolve`: какой договор |
| `favor_kind` | `u8` | `favor`: `FavorKind` |
| `created`, `answer_on` | `Date` | `answer_on` — день решения ответчика (§7.2) |
| `round` | `u8` | 0 — исходное, 1 — встречное (больше раундов нет) |

### 4.6 `FavorTable` — долги услуг (раздел 117)

По возрастанию `(debtor, creditor)`; ≤ `kMaxFavorRows = 512`; `count` 1…3 (`max_favors_owed`); строка с 0 удаляется; `since` — дата первого непогашенного долга; долг старше `favor_expiry_months` (120) списывается без последствий.

### 4.7 `DiplomacyLog` — кольцо журнала (раздел 118)

64 записи по 32 Б: `seq u32`, `date`, `kind u8` (1 `OfferMade`, 2 `Accepted`, 3 `Refused`, 4 `Countered`, 5 `NoAnswer`, 6 `Withdrawn`, 7 `Void`, 8 `Signed`, 9 `Ended`, 10 `Broken`, 11 `Gift`, 12 `FavorGranted`, 13 `FeudOn`, 14 `FeudOff`, 15 `PactSkipped`, 16 `RelationSkipped`), `a`, `b`, `ref u32` (договор/предложение), `param u16` (вид, причина конца, причина нарушения), `top[3] u16` (коды `Breakdown` трёх главных факторов). Источник on-action 140…145 (§13.1), ленты слухов (M2) и dev-окна.

### 4.8 Производное (не сохраняется) и память

Индексы `offers_by_answer (answer_on, id)`, `treaties_by_end (end, id)`, `treaties_of[house]` и `rows_of[house]` пересобираются при загрузке и после каждой команды E15. Память: 100 родов × 40 строк × 20 Б ≈ 80 КБ, модификаторы (в среднем 2 на строку) ≈ 128 КБ, договоры 512 × 48 Б ≈ 25 КБ, предложения 256 × 48 Б ≈ 12 КБ; для 4 родов сценария M1 — ≤ 20 КБ.

## 5. Отношения: мнение, доверие, сила, обиды

### 5.1 Мнение

```
opinion(a→b) = clamp( kin + head + faith + Σ mods + Σ treaty_bonus , −100, 100 )
  kin   = kin_weight‰  · dynasty_relation(a, b)                     // 700‰, E8 §8.4.1
  head  = head_weight‰ · trunc(get_opinion(глава a, глава b))       // 300‰, E7-T17; нет главы — 0
  faith = faith_opinion_term(a, b)                                  // E31; до E31 — 0
  mods  = текущие значения модификаторов строки (a, b)              // §4.3
  treaty_bonus: alliance +25, claim_support +15, pledge +10, marriage_pact +10 за каждый
               действующий договор пары (симметрично)              // данные, [предл.]
```

Каждое слагаемое усекается к нулю отдельно; `Breakdown` 20000 (§12) содержит узел `clamp`, поэтому `Σ дочерних == корню` точно. Мнение — **функция** (`relation_opinion(world, rules, a, b, Breakdown*)`), не хранится; пара без строки считается той же функцией с нулём модификаторов (договор всегда имеет строку). Дробные `Fixed32` мнения E7 усекаются к целому до умножения. Слагаемые GDD 07 §3.2 «разница рангов» и «давление императора» в мнение **не входят**: ранг и сила — в согласии (§7.3, слагаемое силы), давление императора — слагаемое 20206; «император велел не дружить» — M2.

**Пример (DIP-A7).** Голицыны → Нарышкины: `dynasty_relation` = 20 → 700‰ → **14**; глава о главе 10 → 300‰ → **3**; вера одна → **0**; подарок 75 ₽ (+6, 12 мес., осталось 12) → **+6**; донос Нарышкиных 8 мес. назад (−15 на 36 мес., осталось 28: −15·28/36 = −11,67) → **−11**; союз → **+25**. Итог 14 + 3 + 0 + 6 − 11 + 25 = **37**; тултип: «Мнение 37 из-за: родство и связи +14, отношение главы +3, подарок +6 (ещё 12 мес.), донос −11 (ещё 28 мес.), союз +25».

### 5.2 Затухание

`diplomacy.decay` в месячный слот рода `a` (`is_monthly_slot(a.index, today)`, дни 1…28) для каждой строки `a`: `months_left −= 1`, при 0 модификатор удаляется; затем доверие и флаг вражды (§5.3, §5.4); затем удаление пустых строк. Это не команды (ADR-0006 D5: «затухание мнений — не команда»), изменения хешируются частью 62.

### 5.3 Доверие

| Событие | Изменение `trust(жертва → нарушитель)` `[предл.]` |
|---|---|
| Нарушение `alliance` / `claim_support` | −40 |
| Нарушение `pledge` | −30 |
| Нарушение `marriage_pact` | −25 |
| Публичное нарушение — третьим родам, у которых уже есть строка к нарушителю | −5 (`public_breach_trust`) |
| Донос `b` на `a` (подан, `Denounce` в журнале) | −10 |
| Договор исполнен до срока (`Expired`) | +5 обеим сторонам |
| Ежемесячно, пока есть действующий договор пары | +1, не выше `trust_treaty_ceiling` (80) |
| Ежемесячно без договоров (месяцы с номером, кратным 3) | на 1 к 50 |

Доверие хранится (в отличие от мнения): это память о поведении, которую нельзя пересчитать из текущего состояния. Тултип показывает значение и последнюю причину изменения из журнала.

### 5.4 Обиды и вражда (#697 A)

Обида — модификатор с отрицательным значением, причиной и сроком 24…60 мес. `[предл.]`: отказ на предложение −5/12 мес. (не обида, «досада»; при `NoAnswer` — ничего), неблагодарность должника −10/24, донос −15/36, ложный донос (вердикт «оклеветал») ещё −10/24, нарушение `marriage_pact` −30/36, `pledge` −25/36, `alliance`/`claim_support` −40/48. Отдельной таблицы обид и уровня вражды нет.

**Вражда** — бит 0 `flags` строки: включается в слот затухания при `opinion(a→b) ≤ feud_enter` (−60), выключается при `≥ feud_exit` (−50); без строки — `in_feud(a, b) = opinion(a→b) ≤ −60` без гистерезиса. Следствия: ИИ отказывает в любом предложении без счёта (причина `Feud`), ИИ не дарит и не просит услуг; игроку — предупреждение в конструкторе. Смена флага пишет `FeudOn`/`FeudOff` в журнал (on-action 145). Мировая, вира, посредничество, месть по наследству — M2 (§20).

### 5.5 Сила рода и «страх» (не хранится)

```
house_power(h)   = honor(h) / 20 + favor_x100(h) / 500                 // честь E7, милость E10 (0…100 → 0…20)
fear(r of p)     = clamp(house_power(p) − house_power(r), −20, 20)      // Breakdown 20100
arrogance(r)     = Σ trait_hints.dipl_arrogance черт главы r                // proud = 10 [предл.]
```

Пример: честь 300 и милость 70 у предлагающего (15 + 14 = 29), честь 200 и милость 50 у ответчика (10 + 10 = 20) → страх **+9**; глава ответчика спесив (`proud`) → слагаемое силы 9 − 10 = **−1**.

## 6. Договоры

### 6.1 Общее

Шаблоны — `treaty_kind` в `diplomacy.pd` (§15): срок (min/default/max, мес.), бонус мнения, штрафы нарушения (доверие, обида, срок обиды), базовая выгода, риск, `breakable` (можно ли разорвать командой 205), включён ли вид в M1. Договор заключается только через предложение (§7) или системно (`SignTreaty` 206: сценарий, событие; `RegisterMarriagePact` 210). Ни один договор **не создаёт** войны, казуса белли, армий и права прохода (GDD 06 §10; `passage_allowed` E16 не меняется). Все договоры M1 публичны (`flags` бит 0).

| Вид | Стороны | Срок `[предл.]` | Даёт | Нарушение (кто) | Штраф жертве → нарушителю |
|---|---|---|---|---|---|
| `alliance` | 2, симметрично | 24…120 мес., 60 | мнение +25; вес в согласии (через мнение); вес в позиции E12 (`allies_of`, §19); ИИ-союзник не доносит на союзника; `political_gain` брака +15 | `BreakTreaty`; донос на союзника (`Denounce` в журнале) | доверие −40, обида −40/48 |
| `pledge` | вноситель `a`, бенефициар `b` | 12…60 мес., 36 | мнение +10; деньги на счёте короны (§6.3) | вноситель: `BreakTreaty`, донос на бенефициара; бенефициар: `BreakTreaty` | вноситель-нарушитель теряет залог в пользу `b`; доверие −30, обида −25/36 |
| `marriage_pact` | 2 дома с помолвкой/браком E8 | бессрочно | мнение +10; `political_gain` +5 | `BreakBetrothal{Voluntary}` или `Tonsure` супруга из другого дома (актор — нарушитель) | доверие −25, обида −30/36 |
| `claim_support` | сторонник `a`, дом претендента `b` | 12…60 мес., 36 | мнение +15; `SupportClaim` `a` за претендента | сторонник снимает поддержку или поддерживает другого; дом претендента — `BreakTreaty` | доверие −40, обида −40/48 |

Лимит 8 считает все виды. Брачный договор при полном лимите **не заводится** (запись `PactSkipped`), брак E8 не страдает; добровольные договоры при полном лимите отклоняются `TreatyLimit`.

### 6.2 Союз (#694 A)

Союз — взаимное признание без военных обязательств: никаких голосований, блоков, взаимной обороны и общего похода до M2 (E18, E34). Что он даёт в M1: (1) +25 к мнению в обе стороны; (2) через мнение — вес в `accept_score` любых договоров и услуг; (3) `marriage_political_gain` +15 при оценке брака между союзниками (§19); (4) `allies_of(world, h)` — вход позиции ИИ-рода E12-T13 (тянет лояльность к союзникам, §19); (5) ИИ-род не доносит на союзника (фильтр `is_ally` в `PoliticalPlanner` E17 и `stance_actions` E12); игрок может, но это нарушение союза.

### 6.3 Залог мира (#696 A)

Подписание: `transfer(вноситель → корона, 206 pledge_posted, 207 pledge_held, amount)`; без `can_afford` — подписание не состоится (`Void`, причина `NoMoney`). Конец по сроку, по согласию (`dissolve`), при `TiesEnded`/`HouseExtinct` бенефициара — `transfer(корона → вноситель, 208 pledge_released, 209 pledge_paid, amount)`. Нарушение вносителем — `transfer(корона → бенефициар, 208, 209, amount)`; нарушение бенефициаром — возврат вносителю, штрафы бенефициару. Угас род вносителя — деньги бенефициару (`HouseExtinct`). Счёт короны может уйти в минус (возврат без ограничения). Суммы: `pledge_min_rub` 100…`pledge_max_rub` 5 000 `[предл.]`. Без экономики (`economy().enabled == 0`) вид `pledge` недоступен (`NoEconomy`). Пример (DIP-A8): залог 500 ₽ на 36 мес.: при подписании у рода −50 000 коп. по 206, у короны +50 000 по 207; через 36 мес. у короны −50 000 по 208, у рода +50 000 по 209; сумма по счетам за каждый месяц 0.

### 6.4 Брачный договор (D6)

Один `marriage_pact` на неупорядоченную пару домов, пока между ними есть хотя бы одна живая помолвка или брак E8. Заводится системой (`RegisterMarriagePact`, 210) по журналу: `RespondMarriage` с исходом `Accepted` (создаёт помолвку), `Betroth` (67, сценарий/событие) или `Wed` (78) между домами без действующего договора этого вида. Закрывается:

| Событие в журнале | Итог |
|---|---|
| `BreakBetrothal` по добровольной причине, актор — дом `Z` пары | нарушение `Z` (`BreachCause::BreakBetrothal`) |
| `Tonsure` супруга (супруги), чей брак связывает дома пары; актор — дом `Z` | нарушение `Z` (`BreachCause::Tonsure`) |
| `Die`, `EndMarriage` (аннулирование системой), `BreakBetrothal` не добровольно (`Ineligible`, смерть) | если связей между домами не осталось — `SettleTreaty{TiesEnded}` без штрафов |

Командой 205 брачный договор не рвётся (`NotBreakable`). После нарушения новый `marriage_pact` той же пары заводится только с новой помолвкой и не раньше `propose_ready` нарушителя.

**Пример (DIP-A2).** Дом мужа `X` постригает жену из дома `W` (союз и брачный договор действуют; до события `dynasty_relation` 20, глава `W` о главе `X` 10, доверие `W → X` 60): мнение `W → X` = 14 + 3 + 25 + 10 = **52**. В день `Tonsure` E8 сам ставит главе `W` мнение о главе `X` −40 (10 → −30) и снимает брачную связь (`dynasty_relation` 20 → 15). На следующий день `diplomacy.treaties` видит `Tonsure` в журнале и выпускает `ApplyTreatyBreach{marriage_pact, breaker X, Tonsure}`: договор закрыт (бонус −10 ушёл), доверие 60 → **35**, обида −30 на 36 мес., третьим родам со строкой к `X` доверие −5, событие `on_treaty_broken`. Мнение: 10 (700‰·15 = 10,5) − 9 (300‰·(−30)) − 30 + 25 = **−4**. Через 12 мес. (обида −20, мнение глав −18 → −5): 10 − 5 − 20 + 25 = **10**. Повторный вызов на тот же `Tonsure` невозможен: договора уже нет. «Бонус к враждебным схемам» родни жены (GDD 07 DIP-A2) — M2 (E14).

### 6.5 Поддержка претензии на престол (#693 C)

`claim_support` связывает сторонника `a` и дом претендента `b`; претендент `claimant` обязан быть в `ClaimTable` E12 с домом `b`. У сторонника — не больше одного действующего `claim_support` (E12: одна поддержка на дом).

1. Принятие предложения создаёт договор (§7.4). На следующий день `diplomacy.treaties` видит `RespondOffer{Accept}` в журнале и выпускает `SupportClaim{claimant, support = 1}` с актором `a` (источник `Internal`; правка E12-T08, §19). Если сторонник поддерживал другого претендента без договора — поддержка переключается без штрафа.
2. День после выпуска: если в `ClaimSupportTable` у `a` не `claimant` (команда E12 отклонена) — `SettleTreaty{ClaimGone}` без штрафов; иначе ставится бит 1 `flags`.
3. Нарушение сторонника: в журнале `SupportClaim` с актором `a` и `support = 0` по `claimant` (`SupportWithdrawn`) или `support = 1` за другого (`SupportSwitched`). Нарушение дома претендента — только `BreakTreaty`.
4. Конец без штрафов: `WithdrawClaim` или смерть претендента, `TransferThrone` (престол разрешён), снятие претензии системой E12 — `ClaimGone`; срок — `Expired` (поддержка в E12 **остаётся**, сторонник волен снять её без штрафа).

## 7. Предложения и согласие

### 7.1 Жизненный цикл

`ProposeTreaty` (202), `AskFavor` (201) или `ProposeTreaty{kind = dissolve}` создают `OfferRow`; ответчик — ИИ (род вне `player_dynasties` или под автопилотом E17) или игрок.

| Ответчик | Когда решается | Как |
|---|---|---|
| ИИ-род | в день `answer_on = created + (h mod 7)` (0…6 дней), `h` — `core::HashStream` (FNV-1a 64, `pat/core/hash_stream.hpp`) от `(kOfferDelaySalt, id)`, применяется на следующей границе тика → ответ виден через **1…7 дней** | `diplomacy.offers` считает `treaty_accept_score` по состоянию этого дня и выпускает `RespondOffer` (`Internal`, актор — ответчик) с зафиксированными счётом, порогом и тремя факторами; `apply` проверяет допустимость (стороны живы, лимиты, деньги), но счёт не пересчитывает |
| Игрок | до `created + offer_answer_days` (30) | `RespondOffer` от рода игрока; в день срока без ответа — система выпускает `RespondOffer{Refuse, NoAnswer}`: без модификаторов мнения (DIP-A6), `propose_ready` предлагающего к игроку +`ai_offer_cooldown_days` (90) |

Отзыв — `WithdrawOffer` (204) только предлагающим. Предложение пустеет (`Void`), если до ответа исчезла сторона, претендент, договор для `dissolve`, или у вносителя нет денег при согласии.

### 7.2 Последствия ответа

| Исход | Эффекты |
|---|---|
| `Accept` | договор создаётся (`dissolve` — `SettleTreaty{Mutual}`, `favor` — §8.2); если ответчик должен предлагающему — долг −1 (гасится); журнал `Accepted` + `Signed`; on-action 143 и 140 |
| `Refuse` | предлагающему к ответчику модификатор `OfferRefused` −5/12 мес. (кроме `NoAnswer` и отказа по вражде — там ничего); `propose_ready(from → to)` = сегодня + `refusal_cooldown_days` (180); если ответчик должен предлагающему — долг −1 и предлагающему `Ingratitude` −10/24 мес.; журнал с тремя факторами |
| `Counter` | только в раунде 0; исходное удаляется (`Countered`), создаётся предложение `to → from` с `round = 1` и изменёнными условиями (§7.5); встречное на встречное недоступно |

### 7.3 `accept_score` (GDD 07 §4.3) — с точки зрения ответчика `r`, предлагающий `p`

| Код | Слагаемое | Формула (целые, усечение к нулю) `[предл.]` |
|---:|---|---|
| 20201 | мнение | `500‰ · opinion(r→p)` |
| 20202 | доверие | `400‰ · (trust(r→p) − 50)` |
| 20203 | выгода условий | `clamp(value × (1000 + greed)/1000, −40, 40)`; `greed` = Σ `trait_hints.dipl_greed` черт главы (`greedy` 500), только для положительной выгоды; `value` — по виду, ниже |
| 20204 | сила и спесь | `fear(r of p) − arrogance(r)` (§5.5) |
| 20205 | совпадение с целями | E17 `goal_affinity(view, r, kind)` 0…10, если у `r` есть агент; иначе запасное правило: `alliance`/`pledge` +5 при подозрении к `r` ≥ 30 или без договоров; `claim_support` (сторонник) +5 при позиции `Plotter`; иначе 0 |
| 20206 | давление императора | `−300‰ · suspicion(p)` (0…100 → 0…−30): связь с подозреваемым опасна |
| 20207 | риск и обиды | `−(risk(kind) + 250‰ · Σ |отрицательных модификаторов r→p|)`; `risk`: `claim_support` (сторонник) 10, прочие 0 |

`value` по виду: `alliance` `8 + (60 − months)/12`; `pledge` для бенефициара `+min(30, amount_rub·4/100)`, для вносителя `5 − min(30, amount_rub·4/100)`, плюс `(36 − months)/12`; `claim_support` для сторонника `claim_strength(claimant)/4 − 10`, для дома претендента +30; `favor` (`credit`) для дарителя `5 − min(30, amount_rub·4/100)`; `dissolve` `−base_value` договора (для бенефициара залога ещё `−min(30, amount_rub·4/100)`); долг: если `r` должен `p` — **+30** (`favor_call_weight`, узел 20224). Обиды намеренно учтены дважды (в мнении и с весом 250‰ в риске): «память» сильнее текущей приязни.

**Порог.** `threshold = accept_threshold (20) + Σ trait_hints.dipl_threshold черт главы + сдвиг архетипа` (`Breakdown` 20250). Черты `[предл.]`: `cautious` +10 («подозрительный»), `proud` +5, `ambitious` −5 («честолюбивый»: рискует), `generous` −5, `diplomat` −5; `greedy` — через `greed` в выгоде («жадный»). Архетип E17 (если есть агент): Интриган +5, Лоялист −5 для союза с родом позиции `Loyalist` («верный»), прочие 0. **Жёсткие отказы без счёта:** вражда (`Feud`); у ответчика 8 договоров (`Limit`); вид выключен в данных.

**Согласие** — `accept_score ≥ threshold`; без ГСЧ; **три главных фактора** — три слагаемых с наибольшим `|вклад|`, ничья — меньший код.

**Пример (DIP-A1).** Игрок `p` предлагает союз на 60 мес. роду `r`: мнение `r → p` 40 → **+20**, доверие 60 → **+4**, выгода 8 → **+8**, сила 0, цели (запасное правило: у `r` нет договоров) **+5**, подозрение императора к `p` 30 → **−9**, обид нет → **0**. Итог **28 ≥ 20** — согласие; главные причины: мнение +20, давление императора −9, выгода +8. Ответ применится через 1…7 дней (хеш номера).

### 7.4 Встречное (один раунд)

Если `threshold − counter_margin (15) ≤ accept_score < threshold` и вид допускает уступку, ответчик перебирает варианты по порядку данных и выпускает первый, при котором его счёт ≥ порога: `alliance` — срок 36, затем 24 мес.; `pledge` — сумма ×1,5 (бенефициар), затем срок −12 мес.; `favor` — сумма ×½; `claim_support`, `dissolve` — нет. **Пример:** тот же союз, но глава `r` осторожен (`cautious`, порог 30): 28 < 30, 28 ≥ 15 → вариант «36 мес.»: выгода 8 + 2 = 10 → счёт 30 ≥ 30 → `Counter{months = 36}`; игрок видит встречное во «Входящих» на 30 дней.

### 7.5 Прогноз для игрока и ИИ-инициатора (`Breakdown` 20300)

`treaty_forecast(view, p, r, terms)` — сумма **видимых** слагаемых (20201 мнение главы и рода о `p` — видно, 20202, 20203, 20204, 20206, 20207) против базового порога 20 с допуском ±10: «вероятно» / «неясно» / «маловероятно». Скрыты слагаемое целей (20205) и сдвиги порога от архетипа; черты учитываются, только если `public`. Один и тот же прогноз зовут конструктор договора (UI) и `DiplomacyPlanner` (тест утечек AI-A4).

## 8. Действия

### 8.1 Подарок — `GiveGift` (200)

`amount ≥ min_gift_rub` (10), `≤ max_gift_rub` (2 000), `can_afford`; цель — живой род, не свой, не корона; `gift_ready(a→b) ≤ today`. Деньги: `post_money(a, 106 gifts_bribes, −amount)` и `post_money(b, 13 grants_in, +amount)` в одной команде (F1; сумма по счетам 0, тест команды). Мнение `b → a`: модификатор `Gift` = `min(gift_cap (20), текущий Gift + amount_rub · 8/100)`, срок 12 мес. заново (`Breakdown` 20400). Кулдаун пары — 30 дней. Пример (DIP-A8): 50 ₽ → +4 на 12 мес.; у дарителя −5 000 коп. по 106, у получателя +5 000 по 13. Без экономики — `NoEconomy`. ИИ не дарит роду во вражде.

### 8.2 Услуга — `AskFavor` (201, #694 A)

`a` просит `b` об услуге вида `credit` (`favor_min_rub` 50…`favor_max_rub` 1 000): предложение §7 с выгодой для дарителя `5 − min(30, amount_rub·4/100)`. При согласии: `b` платит `a` двумя одиночными проводками 106/13 (как подарок; `b` проверяет `can_afford` в `apply`), долг `a` перед `b` +1 (≤ 3; при 3 — `FavorDebtFull` на этапе запроса), модификатор `FavorGranted` `a → b` +5/12 мес. Долг гасится: (1) когда должник принимает любое предложение кредитора (+30 к его согласию); (2) когда должник отказывает кредитору — долг −1 и обида `Ingratitude` −10/24 мес. у кредитора; (3) списанием через 120 мес. Других потребителей долга в M1 нет; голос, рекомендация, поддержка иска — M2. Пример: опора на род с мнением 50 к просителю, доверие 60, подозрение к просителю 30, сумма 100 ₽ → 25 + 4 + 1 + 0 + 0 − 9 − 0 = **21 ≥ 20** — услуга оказана.

### 8.3 Расторжение — `BreakTreaty` (205)

Сторона договора в любой момент; это **нарушение** с штрафами вида (§6.1), деньги залога — по §6.3; `propose_ready(нарушитель → жертва)` = сегодня + 730 дней. Расторгнуть без штрафа — только по согласию (`ProposeTreaty{dissolve}`) или дождаться срока. Кулдауны и цены: данные `costs` (§15); очки внимания ИИ — `ai.pd`-таблица E17 получает строки E15: `GiveGift` 2, `AskFavor` 2, `ProposeTreaty` 3, `BreakTreaty` 3, `WithdrawOffer` 0, `RespondOffer` 0.

### 10.2 Правила `validate` / `apply`

- `validate` чистая, по снимку; `apply` повторяет проверки, которые могли устареть за тик (стороны живы, лимиты, деньги, предложение ещё открыто), и при провале пишет `Void` в журнал без побочных эффектов.
- Актор — род; игрок действует только за роды `player_dynasties`, ИИ — за свои; системные команды (206…210) извне отклоняются.
- Денежные шаги внутри одной команды — либо все, либо ни одного (сначала `can_afford`, потом проводки).
- Без `enabled` — `Disabled` (кроме 211); без экономики — денежные виды и команды `NoEconomy`.

## 14. ИИ

### 14.1 Ответы без агента

Ответ ИИ-рода всегда даёт `diplomacy.offers` (§7.1) — работает в мире без E17 и для родов без агента. Агент E17 только **инициирует**.

### 14.2 `DiplomacyPlanner` (E15-T12) на интерфейсе `Planner` (E17-T07)

`PlannerId::Diplomacy = 7`, цели E17 без новых ([ai-model.md](ai-model.md) §8.1): `protect_self` — союз, залог (вноситель) с родами высокой силы и без вражды; `secure_line` — сближение перед сватовством (подарок, услуга роду лучшей партии из `rank_matches` E8); `gain_favor` — подарки и услуги родам с высокой милостью; `prepare_plot` — `claim_support` для своего претендента (просить) или за кандидата заговора (предлагать). Кандидаты — роды, видимые через `AiView`, по `(польза ↓, id ↑)`; оценка — `treaty_forecast` (только видимые слагаемые, AI-A4), а не полный `accept_score` ответчика. Против мигания: не рвать договор моложе `min_treaty_age_days` (365), кроме вражды; после разрыва — `propose_ready` 730 дней; после отказа — 180; гистерезис E17 ×1,15. Причины решений — `AiReason` 450 `OfferSent`, 451 `GiftSent`, 452 `FavorAsked`, 453 `TreatyBroken`, 454 `NoPartner`, 455 `FeudBlock`, 456 `TreatyLimit`, 457 `FlickerGuard`, 458 `TreasuryLow`, 459 `PlayerInboxFull`, 460 `PairCooldown`, 461 `ForecastLow`, 462 `DissolveAsked` (463…499 резерв). Бюджет — ≤ 0,3 мс на проход агента, цена кандидата в WU — данные E15.

## 16. Инварианты (`check_invariants`, T02…T11)

- Строки отношений: `a ≠ b`, оба — существующие роды; ≤ 40 на `a`; `trust` 0…100; модификаторов ≤ 6, `months_left ≤ months_total`, одна причина — один модификатор.
- `opinion` −100…100 для любой пары (свойство функции; тест на границах).
- Договоры: стороны существуют и различны; `start ≤ end` или `end = kNoDate` (только `marriage_pact`); ≤ 8 на род; ≤ 1 вида на пару; ≤ 1 `claim_support` на сторонника; у каждого договора есть строки `a→b` и `b→a`; `pledge`: `amount_kop > 0`; сумма действующих залогов = проводки 207 − 208 короны с начала партии (свойство прогона, тест T08, не `check_invariants`); `marriage_pact` — между домами есть помолвка или брак E8 (проверка в конце дня).
- Предложения: стороны существуют, `from ≠ to`; ≤ 3 на пару; ≤ 2 от ИИ роду игрока и ≤ 1 от рода; `round ≤ 1`; `answer_on ≥ created`; у `dissolve` — договор существует.
- Долги: 1…3; должник ≠ кредитор.
- Сумма парных проводок 206/207 и 208/209 по счетам = 0 (E-M3); подарок и услуга — 106 и 13 на равную сумму в одной команде (тест).
- Видимость: планировщик не читает мнения чужих родов друг о друге и скрытые слагаемые (AI-A4).
