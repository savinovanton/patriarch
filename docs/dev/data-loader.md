# Реестр контента и загрузчик

> Статус: E4-T04 (готово). Код — `src/data` (`pat/data/content_source.hpp`, `content_registry.hpp`, `content_loader.hpp`), тесты — `tests/content_loader_test.cpp`.
> Формат файлов и коды `PD001…PD024` — [data-format.md](data-format.md); схемы и коды `PD101…PD110` — [data-schemas.md](data-schemas.md). Здесь — загрузка нескольких корней, переопределение, ссылки, хеш контента и коды `PD111…PD114`.

Загрузчик берёт **упорядоченный список корней** (корень 0 — базовая игра, следующие — моды), читает все файлы `*.pd`, разбирает и проверяет их по схемам (`SchemaSet`), применяет переопределения, разрешает перекрёстные ссылки и строит **реестр** — типизированные таблицы определений плюс 64-битный хеш контента. Модуль зависит только от `core`; единственное место, где используется файловая система, — `DirectorySource`.

```cpp
DirectorySource base("data");
DirectorySource mod("mods/my_mod/data");
const ContentSource* roots[] = {&base, &mod};              // порядок списка = порядок загрузки
LoadResult r = load_content(roots, make_schemas());       // schemas — SchemaSet (E4-T05)
for (const LoadError& e : r.errors) log(e.format());       // ВСЕ ошибки, отсортированы
if (r.ok()) {
    const ContentObject* t = r.registry.find("trait", "greedy");
    save.content_hash = r.registry.content_hash();         // для сохранений (формат здесь не менялся)
}
```

## 1. Источники (`ContentSource`)

Интерфейс из трёх методов: `name()` (для сообщений), `list_files()` (относительные пути со `/`, любой порядок) и `read_file(path)`. Реализации:

- `DirectorySource(path)` — каталог на диске, обход рекурсивный, только обычные файлы, ссылки на каталоги не раскрываются; путь в сообщениях относительный, с разделителем `/`, UTF-8.
- `MemorySource` — файлы в памяти (тесты, инструменты); `add_unreadable` и `fail_listing` имитируют ошибки ввода-вывода.

Загрузчик **сам** отбирает файлы с точным расширением `.pd` (регистр важен: `a.PD`, `a.pd.bak` игнорируются) и **сам** сортирует пути побайтово (беззнаковое сравнение UTF-8, `/` — обычный байт 0x2F). Порядок, в котором источник отдаёт файлы, ни на что не влияет.

## 2. Порядок и переопределение

1. Корни обрабатываются в порядке списка; внутри корня — файлы в порядке путей. Файлы под каталогом `loc/` (таблицы локализации, [localization.md](localization.md)) пропускаются: их читает `pat::loc`, в схемы и хеш контента они не попадают.
2. Каждый файл: чтение → `parse_pd` → проверка `format_version` (§3) → `validate_file`.
3. Ключ объекта — пара `(вид, id)`. Объект **более позднего корня целиком заменяет** объект того же вида и id из более раннего (без слияния полей); запоминается, какой корень и файл дали действующее определение (`ContentObject::root`, `::file`).
4. Один и тот же `(вид, id)` дважды **внутри одного корня** — ошибка `PD112` в месте второго определения с указанием места первого; остаётся первое в порядке «путь, затем позиция в файле». Один id в разных видах — не конфликт.
5. Объект, повреждённый ошибкой (синтаксис или схема), в реестр не попадает, но его `(вид, id)` запоминается как «битый»: ссылки на него не порождают вторую, вводящую в заблуждение ошибку `PD111`. Объект, внутри которого парсер нашёл синтаксическую ошибку, не проверяется по схеме (иначе возникли бы ложные `PD102`) — он отбрасывается целиком; заодно отбрасывается и объект, непосредственно предшествующий ошибке, если ошибка находится между объектами (запись, потерянную парсером целиком, нельзя отличить от ошибки внутри предыдущей).

## 3. Версия формата и миграции

`format_version` — первая запись файла (`PD020`, если нет — сообщает парсер). Загрузчик сравнивает её с `LoadOptions::current_version` (по умолчанию `kCurrentFormatVersion = 1`):

- версия **новее** текущей — `PD021` (позиция — значение в заголовке); файл не загружается;
- версия **старее** — цепочка шагов `MigrationRegistry::add(N, шаг)` («N → N+1»; шаг правит `ParsedFile` на месте и возвращает сообщение об ошибке либо `nullopt`); нет шага — `PD021` («no migration from version N to N+1»), шаг вернул ошибку — `PD114`;
- миграция выполняется до проверки по схемам, поэтому и хеш контента не зависит от того, в какой версии записан файл. Сейчас реестр шагов пуст (версия 1 — единственная).

## 4. Реестр

- `ContentRegistry::tables()` — таблицы **по имени вида** (побайтово); для каждого вида схемы таблица есть всегда (возможно, пустая). `table(kind)`, `find(kind, id)` — двоичный поиск.
- `ContentTable::objects()` — объекты **по возрастанию id** (побайтово). Порядок не зависит от имён файлов, порядка обхода и порядка корней. Это единственный порядок итерации, на который можно полагаться.
- Идентификаторы интернируются (`core::StringInterner`, `registry.ids()`, `ContentObject::id`) **после** принятия всех переопределений, в порядке (вид, id) — значения `StringId` зависят только от действующего контента.
- Хранится `TypedObject` (вид, id, позиция, типизированное тело); `root`/`file`/`pos` нужны только сообщениям.
- Реестр перемещаемый, не копируемый. При ошибках в нём лежит всё, что загрузилось корректно (для инструментов вроде `contentlint`); игра при `!ok()` контент использовать не должна.

## 5. Перекрёстные ссылки

После загрузки всех корней проверяется каждое поле типа `Type::reference(kind)` (в том числе внутри списков, вложенных блоков и словарей) **только у действующих объектов** (ссылки внутри перекрытого объекта не проверяются). Нет объекта `(kind, id)` — `PD111` в позиции значения-ссылки, в файле и корне ссылающегося объекта, с подсказкой `did you mean` по существующим id этого вида либо пояснением, что объектов вида нет вообще.

## 6. Хеш контента

`ContentRegistry::content_hash()` — 64 бита (`core::HashStream`, FNV-1a, как у хешей состояния), считается по каноническому байтовому виду **действующего** контента:

- вид (по порядку), число объектов, для каждого — id и поля тела в порядке схемы (повторяемые поля, списки и словари — в порядке файла: это данные);
- значение: явный тег типа, затем целые как little-endian фиксированной ширины, строки с префиксом длины, `Fixed` — сырым значением; значение по умолчанию и явно записанное равное ему значение дают один хеш;
- **не входят**: имена и пути файлов, позиции, комментарии, пробелы и форматирование, порядок объектов в файле и порядок полей внутри объекта, `StringId`, корень, давший определение, затенённые определения.

Следствия: перенос объекта между файлами или корнями и правка комментариев хеш не меняют; изменение значения, добавление/удаление объекта, смена порядка корней, меняющая итог переопределения, — меняют. Хеш определён и при ошибках загрузки, но осмысленен только для `ok()`. Формат изменять только с новым «магическим числом» (`kHashMagic` в `content_registry.cpp`). Хеш предназначен для записи в сохранения (проверка «этот контент совпадает с тем, на котором играли»); сам формат сохранений в E4-T04 не менялся.

## 7. Ошибки

`LoadError{root, root_name, file, diagnostic}`; `format()` даёт `[root 1 'mods/a'] traits/core.pd:3:5: error[PD111]: …` (для ошибки корня целиком — `[root 1 'mods/a'] error[PD113]: …`). Загрузка **не останавливается** на первой ошибке: в результат попадают ошибки всех корней и файлов (ошибки парсера и схем — с кодами `PD0xx`/`PD101…PD110`, их же отдельно перечисляют data-format.md и data-schemas.md). Список отсортирован по `(индекс корня, путь файла, позиция, код, текст)` — результат один и тот же при любом порядке, в котором источник отдаёт файлы.

| Код | Смысл | Позиция |
|---|---|---|
| `PD111` | неразрешённая ссылка: нет объекта `kind:id`; подсказка «did you mean» | значение-ссылка |
| `PD112` | повтор `(вид, id)` внутри одного корня; в сообщении — место первого определения | ключ второго определения |
| `PD113` | корень или файл нельзя прочитать (нет каталога, отказ в доступе, ошибка чтения) | нет (`файл` либо только корень) |
| `PD114` | шаг миграции формата вернул ошибку | значение `format_version` |
| `PD115` | правило между объектами, нарушенное при сборке контента **потребителем** (не загрузчиком), например двое товаров с одним `slot` в `data/economy/` (`pat::content`, E9-T18) | ключ или объект, к которым относится нарушение |
| `PD021` | (из data-format.md) версия формата новее текущей или нет пути миграции | значение `format_version` |

## 8. Что не входит в E4-T04

Схемы и определения игры (E4-T05, каталог `data/`), локализация (E4-T06, готово: [localization.md](localization.md), модуль `src/loc`), горячая перезагрузка (E4-T07), утилита `contentlint` (E4-T08). Подключение к `sim`/`spike` не выполнено.
