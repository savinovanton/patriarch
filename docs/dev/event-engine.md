## 1. Что здесь решено и что нет

Документ фиксирует **форму** движка событий, а не содержание событий:

1. границы M1 и M2 (§2) и слои (§3);
2. формат `event`/`option`/`event_modifier`/`event_settings` в `.pd` (§4), области и переходы (§5), язык правил: триггеры, значения, эффекты (§6);
3. байткод, виртуальную машину, лимиты и правила детерминизма (§7);
4. **каталоги**: on-action, ≈ 40 триггеров и значений, ≈ 40 эффектов с числовыми кодами и соответствием командам (§8);
5. состояние в `World`, теги команд 96…127, разделы сейва 48…63, части хеша (§9);
6. показ игроку: очередь, ИИ-выбор, автопауза, `EventView` для UI-D07 (§10);
7. цепочки, кулдауны, `once`, исторические якоря (§11, §14), индекс триггеров и диспетчер (§12), автотултипы (§13);
8. тексты и локализация (§15), `contentlint` и коды ошибок (§16), рамки контента (§17), dev-инструменты (§18);
9. бюджеты (§19), версии, хеш и golden (§20), план T02…T22 с поправками (§21), контент-пакеты (§22), тесты (§23), риски (§24), правки других документов (§25).

## 3. Слои и файлы

```
core ← sim ─────────────── events: Program, Vm, Catalog (коды), EventSet (тип), EventState (World), системы events.resolve / events.dispatch
core ← data (.pd, схемы: + Type::rules()) ← content ── events: компилятор .pd → EventSet; EV-ошибки; EventSet::hash()
sim, loc ← game ────────── event_bridge: Preview → ui::Explanation, EventView, очередь → UI; формат даты и имён
engine ← ui ────────────── EventWindow, окна «Журнал» и «Настройки событий» (ui не знает sim)
tools ──────────────────── contentlint (EL-правила), simcli events, simevents
```

| Что | Где | Зависит от |
|---|---|---|
| `Program`, `Instr`, `Vm`, `Catalog` (триггеры/эффекты/значения/списки/on-action с кодами, сигнатурами, ключами тултипов), `EventSet`/`EventDef` (скомпилированный вид), таблицы состояния, `EventDispatcher`, `EventQueue` | `src/sim/events/` (`include/pat/sim/events/*.hpp`) | `core`, `sim` |
| Компилятор `compile_events(registry, catalog) → EventSet`, схемы видов `event`/`event_modifier`/`event_settings`, `EventSet::hash()`, коды `EV1xx` | `src/content/events/` | `data`, `sim`, `core` |
| `build_event_view(world, set, loc, instance) → ui::EventView`, `build_event_queue`, `build_journal`, мост `Preview → Explanation` | `src/game/event_bridge.*` | `sim`, `loc`, `ui` (типы), `core` |
| `contentlint` (правила `EL2xx`, §16), `simcli events`, `tools/simevents` | `tools/` | `content`, `sim`, `loc`, `data` |
| События, модификаторы, настройки | `data/events/<пакет>/*.pd`, `data/events/modifiers.pd`, `data/balance/events.pd` | |
| Тексты, шаблоны тултипов и летописи | `data/loc/ru/events/<пакет>.pd`, `data/loc/ru/events/common.pd` | |
| Эталонные события и корпус ошибок | `tests/data/events/` (golden T21), `tests/data/contentlint/bad/events_*` | |

Правила слоёв: `sim` собирается и тестируется **без `data`** (тесты — на вручную собранных `EventSet`); `EventSet` — тип `sim`, поэтому `Simulation::set_events(shared_ptr<const EventSet>)` (содержимое, не состояние, как `set_economy_rules`); сам `World` `EventSet` не хранит.

## 4. Данные: форматы файлов событий

Файлы — обычные `.pd` (UTF-8, первая запись `format_version = 1`), виды объектов верхнего уровня: `event`, `event_modifier`, `event_settings`. Типы и обязательность полей проверяет схема (E4-T03); **содержимое блоков `trigger`, `immediate`, `after`, `effect`, значений и `limit`** — тип схемы `Type::rules()`: парсер и схема принимают любой блок записей (операторы разрешены), компилятор (`src/content/events`) разбирает его по каталогам с позициями `файл:строка:столбец` в ошибках `EV1xx`.

### 4.1 Пример (замена псевдоформата GDD 08 §4.2)

```
format_version = 1

event "estate.embezzling_administrator" {
    scope = province                      # на ком срабатывает; получатель — владелец-род
    type = provincial                     # метка окна (ui.event.kind.provincial)
    category = economy                    # пул гравюр/звук и подпись внизу
    review = draft                        # draft | reviewed (reviewed ставит владелец)
    on = monthly_pulse
    mean_time_to_happen = { months = 24
        modifier = { factor = 0.5  trigger = { corruption >= 0.5 } } }
    cooldown = { months = 36 }

    trigger {
        exists = administrator            # переход должен дать область
        corruption > 0.3
    }
    immediate { administrator = { save_scope_as = governor } }
    speaker = scope:governor              # портрет и «говорящий» в окне

    option "denounce" {
        ai_chance = { base = 20  add = { value = owner.honor  divide = 5 } }
        trigger { owner = { honor >= 30 } }          # недоступен: причина покажется в окне
        effect {
            owner = { change_honor = -5 }
            change_control = 5
            scope.governor = { change_opinion = { target = root.owner.acting_head  value = -20 } }
        }
    }
    option "hush" {
        ai_chance = 40
        effect {
            owner = { pay = 200 }                     # неявное условие «хватает денег» добавит компилятор
            set_flag = { name = hushed_theft  days = 365 }
        }
    }
    option "ignore" {
        ai_chance = 40
        effect {
            add_modifier = { name = "estate.ignored_theft"  months = 12 }
            change_control = -3
        }
    }
}
```

Тексты — в `data/loc/ru/events/estate.pd`: `evt.estate.embezzling_administrator.title`, `.desc`, `.opt.denounce`, `.opt.hush`, `.opt.ignore` (ключи выводятся из id; переопределяются полями `title`, `desc`, `text`).

**Синтаксические соглашения блоков правил** (на ядре `.pd`, §4 data-format):
- запись `ключ оператор значение`; `=`, `!=`, `<`, `<=`, `>`, `>=`; ключи повторяются (мультикарта, порядок записей сохраняется и **значим**);
- ключ — идентификатор с точками: **путь** `spouse.age`, `owner.head.honor`, `scope.governor.corruption`, `root.dynasty` (первый сегмент — `root`, `scope.<имя>` или переход/значение текущей области; ссылки `scope:имя` допустимы только в позиции **значения**, потому что ключом может быть лишь идентификатор);
- числовой ключ — вес в `random_list` (`30 = { … }`);
- блок `имя = { … }` и `имя { … }` равны; один главный аргумент допускает скаляр (`change_honor = -5` вместо `change_honor = { value = -5 }`);
- длительность — блок `{ days = N }` / `{ months = N }` / `{ years = N }` (сумма допустима); месяц = 30 дней, год = 365 `[предл.]` только для таймеров и MTTH, календарь юлианский;
- числа: целые и десятичные; десятичные — точная дробь → `Fixed` (data-format §3.2), `0.3` в `corruption` — доля 0…1 (единицы значений — в каталоге §8).

### 4.2 Поля `event`

| Поле | Тип | Обяз. | По умолчанию | Смысл |
|---|---|---|---|---|
| `scope` | `character\|dynasty\|province\|realm` | да | — | корневая область (§5) |
| `type` | `personal\|family\|provincial\|court\|imperial\|church\|military\|background\|hidden` | да | — | тип GDD 08 §3; подпись окна `ui.event.kind.<type>`, правила показа по умолчанию |
| `category` | идентификатор | да | — | пул иллюстраций и звук, подпись `ui.event.category.<id>`: `court, war, church, crisis, death, finance, family, economy, general` (набор — данные) |
| `image` | строка | нет | `category` | ключ пула гравюр (E26); в M1 — только категория |
| `tags` | список идентификаторов | нет | `[]` | для `sim-events`, фильтров, ИИ |
| `on` | идентификатор или список | нет¹ | — | on-action (§8.1): `monthly_pulse`, `on_death`, `on_marriage.bride` (роль после точки) |
| `trigger` | правила | нет | всегда | условия; блок = И |
| `mean_time_to_happen` | длительность (+`modifier`) | нет | — | MTTH для пульсов (§12.4); взаимоисключающе с `chance` |
| `chance` | значение-аккумулятор, % | нет | — | вероятность на действие/пульс (для не-пульсовых `on`) |
| `cooldown` | длительность | нет | — | пауза после срабатывания на этой области |
| `cooldown_group` | идентификатор | нет | — | общая пауза для группы событий на области |
| `once` | `scope\|global` | нет | — | один раз на область / один раз за партию |
| `window` | `{ from = дата  to = дата }` | нет | — | окно дат (юлианских); `anchor = yes` — исторический якорь (§14) |
| `pool` | идентификатор | нет | — | взвешенный пул: из прошедших ворота событий одного пула на одной области срабатывает одно (§12.5) |
| `weight` | значение-аккумулятор | нет | `100` | вес в пуле |
| `priority` | целое 0…100 | нет | `50` | порядок индекса и очереди (больше — раньше) |
| `urgency` | `critical\|important\|info` | нет | по `display` | класс очереди и автопаузы (§10.2) |
| `display` | `modal\|notification\|silent` | нет | по `type`: `hidden`, `background` → `silent`; `imperial` → `notification`; иначе `modal` | форма показа игроку-получателю |
| `autopause` | `auto\|yes\|no` | нет | `auto` | `auto`: да для `modal` и `critical` |
| `demotable` | `yes\|no` | нет | `yes` | модальное событие сверх лимита понижается до уведомления с ИИ-выбором (#496) |
| `rumor` | `yes\|no` | нет | `no` | фоновое событие, о котором может узнать игрок (#497) |
| `survives_death` | `yes\|no` | нет | `no` | экземпляр не отменяется при смерти области-корня (для `on_death` — всегда `yes`) |
| `group_key` | идентификатор | нет | — | группировка однотипных уведомлений («три провинции сообщают о волнениях») |
| `immediate` | эффекты | нет | — | выполняются при срабатывании **до** показа (сохранение областей, флаги) |
| `after` | эффекты | нет | — | выполняются после эффектов выбранного варианта |
| `speaker` | область-значение | нет | — | «говорящий» окна: портрет, имя, роль |
| `title`, `subtitle`, `desc`, `quote` | ключ локализации | нет | `evt.<id>.title`… | `subtitle` и `quote` необязательны |
| `option` | блок с меткой (повторяется) | да² | — | 1…`kMaxOptions` (= 4; для модальных `contentlint` держит ≤ 3, #498) |
| `single_option` | `yes\|no` | нет | `no` | у `modal` допускается один вариант «Понятно» |
| `review` | `draft\|reviewed` | нет | `draft` | статус текстов (#294) |
| `history` | `unchecked\|checked` | нет | — | у исторических событий; `checked` — историчность проверена (#294) |
| `sources` | список строк | нет | — | источники для `history` |
| `notes` | строка | нет | — | заметка автора, игнорируется |

¹ Без `on` событие запускается только `trigger_event` (цепочка) или `FireEvent` (dev, сценарий). ² У `hidden` вариантов нет, эффекты — в `immediate`.

### 4.3 Поля `option`

| Поле | Смысл |
|---|---|
| метка (`option "denounce"`) | имя варианта, уникально в событии; ключ текста `evt.<id>.opt.<имя>` |
| `trigger` | **доступность**: ложь → вариант виден, но недоступен, показывается причина (первое невыполненное условие, §13.3) |
| `show_if` | **видимость**: ложь → вариант скрыт совсем (редко; индексы вариантов при этом сохраняются, §10.4) |
| `ai_chance` | значение-аккумулятор (вес выбора ИИ), по умолчанию `10` |
| `effect` | эффекты варианта |
| `default` | `yes` — вариант, подсвеченный в окне по умолчанию; иначе первый доступный |
| `neutral` | `yes` — вариант без эффектов допустим (`contentlint` иначе ругается, `EL205`) |

Неявные условия: эффект каталога с пометкой «требует средств» (`pay`) добавляет к доступности варианта `can_afford(сумма)` и причину «Не хватает N ₽» (по образцу `can_afford` E9/E8); неявное условие видно в `Trace`, но не в исходном файле.

### 4.4 Вид `event_modifier`

## 5. Области и переходы

Область (scope) — типизированная ссылка: `(kind: u8, id: u32)`; `kind` ∈ `character=1`, `dynasty=2`, `province=3`, `realm=4`, зарезервированы `church=5`, `army=6`, `scheme=7`, `plot=8`, `faith=9`, `treaty=10`. `realm` — синглтон (`id = 0`). Тип области проверяет компилятор: триггер или эффект «провинции» в области «персонаж» без перехода — `EV102` (EVT-A4).

### 5.1 Переходы (`scope` → `scope`)

| Из | Ключ | В | Когда пусто | Источник |
|---|---|---|---|---|
| `character` | `dynasty` | `dynasty` | никогда (живой в режиме династии всегда в роду) | E7 |
| `character` | `father`, `mother` | `character` | отсутствует (родитель мог умереть: область допустима, `is_alive = no`) | E7 |
| `character` | `spouse` | `character` | не женат/не замужем | E7 |
| `dynasty` | `head` | `character` | спор о наследстве (`head` пуст, #486) — используйте `acting_head` | E7/E8 |
| `dynasty` | `acting_head` | `character` | нет | E8 |
| `dynasty` | `heir` | `character` | наследник не назначен/не определён | E8 |
| `dynasty` | `regent` | `character` | регентства нет | E8 |
| `province` | `owner` | `dynasty` | «ничья» | E9 |
| `province` | `administrator` | `character` | нет управителя | E9 |
| `realm` | `emperor` | `character` | до E12 — персонаж по флагу сценария (Пётр I), иначе пусто | E12 (заглушка M1) |
| `realm` | `emperor_dynasty` | `dynasty` | то же | E12 |
| любая | `root` | область корня события | никогда | движок |
| любая | `scope.<имя>` | сохранённая `save_scope_as` | имя не сохранено — ошибка компиляции | движок |
| любая | `this` | текущая | никогда | движок |

Пустой переход в **триггере** даёт «ложь» (блок не выполняется), в **эффекте** — блок пропускается; предикат `exists = <переход>` проверяет явно. Область умершего персонажа допустима только как корень `on_death` и как сохранённая (архивная запись); эффекты над умершим отклоняются командами (`UnknownEntity`), в триггере доступны `is_alive`, `age_at_death`, `dynasty`, `father`, `mother`.

### 5.2 Списки (для итераторов `any_/all_/count_/every_/random_/ordered_`)

| Список | Из → элементы | Порядок по умолчанию | Верхняя граница M1 |
|---|---|---|---|
| `living_member` | `dynasty` → `character` | по `id` ↑ | 256 |
| `child` | `character` → `character` | `(birth_date, id)` ↑ | 32 |
| `sibling` | `character` → `character` | `(birth_date, id)` ↑ | 32 |
| `owned_province` | `dynasty` → `province` | по `id` ↑ | 128 |
| `realm_dynasty` | `realm` → `dynasty` | по `id` ↑ | 128 |
| `claimant` | `dynasty` → `character` (спор E8) | сохранённый порядок | 4 |

Перебор «всех живых персонажей мира» и «всех провинций мира» **запрещён** (`EV107`): стоимость O(мир) на каждую сущность недопустима (ADR-0002 P8); для выборки «кого-то из рода/провинций рода» есть списки выше. Список строится в арене тика один раз на вход итератора и усекается до границы (усечение учитывается счётчиком, §7.4).

## 6. Язык правил

Язык — **блоки записей на ядре `.pd`** (D2): тот же разбор, те же позиции ошибок; смысл блока задаёт место, где он стоит (`trigger`, `effect`, `limit`, значение). Один набор правил на три применения: исполнение (`Run`), причина недоступности (`Trace`), автотултип (`Preview`).

### 6.1 Триггеры (булевы блоки)

Блок триггера — **И** своих записей, вычисляемых по порядку с коротким замыканием. Допустимые записи:

| Запись | Смысл |
|---|---|
| `имя = yes\|no` | предикат каталога без аргументов (`is_adult = yes`); `no` — отрицание |
| `имя = значение` | предикат с одним главным аргументом (`has_trait = greedy`, `has_flag = hushed_theft`) |
| `имя = { аргумент = … }` | предикат с аргументами (`has_building = { building = mill }`) |
| `путь оператор значение` | сравнение значения каталога или пути с числом, датой или другим значением: `age >= 16`, `owner.honor < 30`, `date >= 1703.05.16`, `skill.martial > scope:rival.skill.martial` (статический аргумент значения — суффикс через точку: `skill.martial`) |
| `значение = { аргумент = …  value оператор N }` | значение каталога с аргументом-областью: `opinion_of = { target = scope:governor  value >= 10 }`, `kinship_degree = { target = scope:rival  value <= 3 }` |
| `and = { … }`, `or = { … }`, `not = { … }`, `nor = { … }` | логика; `not` — не(И), `nor` — не(ИЛИ) |
| `exists = переход` | переход даёт область (§5.1) |
| `переход = { … }`, `scope.имя = { … }` | вход в область; пустой переход → ложь |
| `any_<список> = { count >= N  … }` | существует (число ≥ N, по умолчанию 1) элементов списка, удовлетворяющих условиям внутри |
| `all_<список> = { … }` | все элементы удовлетворяют (пустой список → истина) |
| `random_chance = процент` | предикат броска (`12.5` = 12,5 %); один бросок из потока события; не кэшируется |

Нет `trigger_if`/`else` (M2); условную логику выражают `or`/`and`/`not`. Предикаты с побочным эффектом запрещены; единственный «недетерминированный» предикат — `random_chance`, и он использует поток события (§7.3).

### 6.2 Значения-аккумуляторы

Числа, зависящие от состояния (`ai_chance`, `weight`, `chance`, суммы эффектов, веса `random_list`), — **блок-аккумулятор**: записи выполняются по порядку над одним накопителем `Fixed64`; результат — накопитель в конце.

```
ai_chance = {
    base = 20                                       # начальное значение (по умолчанию 0)
    add = { value = owner.honor  divide = 5 }       # операнд — вложенный аккумулятор
    if = { limit = { has_trait = greedy }  add = 20 }
    if = { limit = { has_trait = honest }  subtract = 15 }
    min = 0
    max = 100
}
```

| Запись | Операнд | Действие |
|---|---|---|
| `base` / `value` | число, путь, `scope:имя.путь`, значение каталога, вложенный блок | накопитель := операнд (только как первая запись блока) |
| `add`, `subtract`, `multiply`, `divide` | то же | арифметика с насыщением (§7.3); деление на 0 → результат 0 и счётчик `div_zero` |
| `min`, `max` | то же | накопитель := min/max(накопитель, операнд) |
| `if = { limit = { триггер } … записи … }` | | записи выполняются, если `limit` истинно |
| `round`, `floor`, `ceiling` | — | округление до целого (к нулю для `round`, см. §7.3) |

Операнд-число — литерал `Fixed` (целое или десятичное), путь (`owner.honor`), значение каталога (`age`, `skill.martial`, `variable.reputation`; с аргументом-областью — блок `{ opinion_of = { target = scope:x } }`), **число элементов списка** (`add = { count_child = { limit = { is_adult = yes } } }`) или вложенный аккумулятор. Скаляр вместо блока (`ai_chance = 40`) — аккумулятор из одного `base`. Каждый шаг (`add`, `multiply`, ветка `if`) получает код и значение для **разложения** `Breakdown` (§13.2): автор не пишет подсказок.

### 6.3 Эффекты

Блок эффекта — последовательность записей, выполняемых **по порядку** в текущей области:

| Запись | Смысл |
|---|---|
| `имя = значение` / `имя = { … }` | эффект каталога (§8.3) |
| `переход = { … }`, `scope.имя = { … }` | вход в область: эффекты внутри выполняются над ней; пустой переход — блок пропущен |
| `if = { limit = { … }  … }`, `else_if = { limit … }`, `else = { … }` | условное выполнение; `else_if`/`else` относятся к ближайшему предшествующему `if` |
| `random_list = { 30 = { … }  70 = { … } }` | один бросок, ветвь по весам (целые ключи; ветвь может содержать `modifier = { factor = … trigger = { … } }` для веса); до 8 ветвей |
| `random = { chance = 25  … }` | с вероятностью `chance` % выполнить блок (один бросок) |
| `every_<список> = { limit = { … }  … }` | для каждого элемента, прошедшего `limit` |
| `random_<список> = { limit = { … }  weight = {…}  … }` | один элемент (по весам, по умолчанию равные) |
| `ordered_<список> = { limit = { … }  order_by = значение  max = N  … }` | элементы по убыванию `order_by`, затем по `id` ↑, не более `max` (по умолчанию 1) |
| `save_scope_as = имя` | запомнить текущую область под именем (до конца экземпляра события, ≤ 8 имён) |
| `hidden_effect = { … }` | выполнить без строки в тултипе |

Новая область внутри итератора — элемент списка; `root` и сохранённые области доступны везде. Эффект не возвращает значения; чтение собственных ещё не применённых команд невозможно (§7.6).

### 6.4 Единицы и преобразования

| Величина | Единица в правилах | Внутри |
|---|---|---|
| деньги (`pay`, `receive`, `treasury`) | рубли, `Fixed` (0,01 ₽ точно) | копейки `int64` (`economy::Kopecks`) |
| проценты (`random_chance`, `chance`, `random`) | число 0…100 | ppm `int`, `ppm = raw × 10 000 / 2³²` целой арифметикой |
| доли (`corruption`) | 0…1 | `Fixed32` как в E9 |
| очки (честь, единство, престиж, навыки, мнения) | пункты шкалы E7 | `Fixed32` |
| возраст | годы (целое, усечение) | |
| даты | `Г.ММ.ДД`, юлианский календарь | `sim::Date` |

## 7. Байткод и виртуальная машина

### 7.1 Модель

`Program` — неизменяемый результат компиляции одного блока: `code[]` (инструкции по 8 байт: `u16 op | u16 a | i32 b`), пул констант `i64 consts[]` (сырые `Fixed64`, ключи `u64`), таблица отладки «инструкция → узел исходного блока (файл, строка, столбец)», оценка стоимости. Событие компилируется в набор программ: `trigger`, `immediate`, `after`, для каждого варианта `available`, `visible`, `ai_chance`, `effect`; плюс `weight`, `chance`, `mtth_modifiers`. Программы **не сохраняются**: компиляция идёт при каждой загрузке (≤ 500 мс на 550 событий `[предл.]`).

ВМ стековая: слово стека — 64 бита (`Fixed64`, ключ, область `kind:8|id:32`, булево). Типы проверяет компилятор, ВМ их не проверяет (кроме границ и лимитов). **Хост** — интерфейс, через который ВМ читает и пишет всё внешнее; благодаря ему ВМ тестируется без `World` событий (T04) и не зависит от таблиц T02:

```
struct VmHost {
  const World&            world;        // чтение мира (персонажи, рода, провинции, экономика)
  EventStateReader&       state;        // флаги, переменные, модификаторы, цепочки, кулдауны (интерфейс; в T02 — над таблицами)
  Pcg32&                  rng;          // поток события (events.run / events.mtth / events.ai)
  Date                    today;
  CommandSink&            commands;     // эффекты над чужим состоянием → Command (буфер)
  StateOpSink&            state_ops;    // эффекты над состоянием событий (буфер, коммит по успеху)
  Tracer*                 tracer;       // Trace: журнал листьев; nullptr вне Trace
  PreviewSink*            preview;      // Preview: дерево строк последствий; nullptr вне Preview
  VmScratch&              scratch;      // арена тика: списки итераторов, стек
};
```

### 7.3 Арифметика и детерминизм ВМ (NFR-DET-1)

1. Все числа ВМ — `Fixed64` (Q32.32); целые — частный случай. `float`/`double` в ВМ, компиляторе и каталогах **запрещены** (grep-проверка в CI, как у `sim`).
2. Умножение и деление — через `muldiv` 128-бит с усечением к нулю (как `core::Fixed`); **переполнение — насыщение** к границе типа и счётчик `saturations`, а не `PAT_ASSERT` и не неопределённое поведение (в Release утверждения выключены, поведение обязано быть определено); деление на ноль — 0 и счётчик `div_zero`; всё это попадает в отчёт запуска и в `sim-events`, но не прерывает программу.
3. Преобразование к целевому полю команды (`Fixed32`, целое) — зажим к диапазону поля; зажим учитывается счётчиком. Проценты → ppm — §6.4.
4. **Случайность** — только `world.rng().stream(...)`: на каждое событие потоки `events.mtth`, `events.run`, `events.ai` с индексом = младшие 32 бита `EventKey` (`stream("events.run", key32)`); пулы — `events.pool` по ключу пула. Добавление/удаление события не сдвигает броски других. Число извлечений зависит только от исполненных инструкций: `RAND_PERMILLE` и `RAND_PICK` берут ровно одно `bounded(…)`, невыбранные ветви извлечений не берут; бросок MTTH — одно извлечение на кандидата, прошедшего дешёвые ворота (§12.3). Поэтому потребление потока события — детерминированная функция состояния мира, а не порядка загрузки и не других событий.
5. **Порядок** — только определённый: списки §5.2 по `id` или `(birth_date, id)`; сортировка с полным порядком (ключ, затем `id`), `std::stable_sort`/`std::sort` по полному ключу; никаких `unordered_*`, адресов, потоков, времени (wall time в логике запрещено; WU — абстрактные единицы).
6. Результат запуска — функция (`world` до запуска, состояние событий, поток события, дата): повторный запуск даёт **тот же буфер команд и операций** байт в байт (тест T04).

### 7.4 Лимиты и откат

| Лимит | Значение `[предл.]` | Превышение |
|---|---:|---|
| `kMaxStack` | 32 слов | ошибка компиляции `EV106` (проверка при компиляции по максимальной глубине выражений) |
| `kMaxScopeDepth` | 8 | `EV106` |
| `kMaxIterNest` | 3 (`every_` внутри `every_` внутри `every_`) | `EV106` |
| `kMaxFanout` | 256 элементов на вход итератора, ниже по §5.2 | список усекается, счётчик `truncated` |
| `kMaxTriggerInstr` | 4 000 инструкций на запуск триггера | откат запуска (`ABORT: instr`) |
| `kMaxEffectInstr` | 40 000 на запуск `immediate`/варианта/`after` | откат |
| `kMaxCommandsPerRun` | 64 команд | откат |
| `kMaxStateOpsPerRun` | 128 операций | откат |
| `kMaxSavedScopes` | 8 имён | `EV106` |
| `kMaxOptions` | 4 | `EV106` |
| `kMaxProgramBytes` | 64 КиБ на событие | `EV106` |
| `max_chain_depth` (данные) | 8: глубина `trigger_event` без задержки внутри одного тика | запуск пропущен, запись в историю `ChainDepthExceeded` |
| `max_timer_chain` (данные) | 32: глубина цепочки, идущей через таймеры | то же |

**Откат.** Командный буфер и буфер операций состояния **коммитятся только после успешного конца запуска**; при превышении лимита (или `ABORT`) оба буфера отбрасываются, броски остаются потраченными (детерминированно), в кольцо истории пишется `EventAborted{событие, причина}`, на событие накладывается кулдаун `abort_disable_months` (состояние, а не память процесса — воспроизводится реплеем). В тестах любой откат — провал (`contentlint` ловит неограниченные циклы заранее).

**WU.** Запуск возвращает расход в WU (§7.2); `events.dispatch` списывает сумму в `WorkBudget` тика для телеметрии. События **не пропускаются** при исчерпании квоты (в отличие от ИИ): пульс полный, иначе меняется семантика; превышение видно в телеметрии (`over_budget`), решается оптимизацией, а не отсечением (ADR-0002 P6: миллисекунды — метрика, не условие остановки логики).

### 7.5 Режимы выполнения

| Режим | Что меняется | Для чего |
|---|---|---|
| `Run` | `EMIT` кладёт `Command` в буфер, `STATE` — операцию; броски берутся из потока | игра |
| `Trace` | как `Run` для триггеров, но на листьях пишется `TraceLeaf{узел, результат, значения}`; без побочных эффектов и **без извлечений из потока** (`random_chance` даёт «шанс N %» без броска) | причина недоступности варианта (§13.3), `dump_scope`, отладка |
| `Preview` | `EMIT`/`STATE` пишут в `PreviewSink` строки «эффект + аргументы» вместо команд; `RAND_PICK`/`random` **не бросают**: ВМ обходит все ветви (до 8) и пишет их с вероятностью; `if` идёт по **реальным** условиям; итераторы идут по реальным спискам, но в строку пишется число элементов и первые три | автотултип последствий (§13.1) |

`Trace` и `Preview` не извлекают чисел из потоков и не меняют состояния: вызов из UI между тиками безопасен и не сдвигает реплей. ВМ собирается дважды (`run<false>`/`run<true>`) без накладных расходов в `Run`.

### 7.6 Время применения

Команды из буфера `Run` попадают в `TickContext::emit` и применяются **в начале следующего тика** (ADR-0001: `validate` → `apply` на границе тика). Внутри одного запуска чтение состояния видит мир **до** собственных ещё не применённых эффектов; события пишутся с этим учётом (например, «вычесть деньги и проверить остаток» — два шага через таймер). Операции с состоянием событий (флаги, таймеры) коммитятся в конце запуска и видны следующему запуску сразу. Отклонённая команда (`validate`) не отменяет событие: запись `EffectRejected{команда, причина}` в историю и счётчик.

### 8.6 Контракт с E8: `on_regent_usurpation` и #491

Решение владельца #491: попытка захвата власти регентом-матерью **другого рода** запускает **отдельное событие**; исход выбирает движок событий, контент пишется отдельно; прямой `SetDynastyHead` для неё не выполняется. Следствия для E11:

1. `on_regent_usurpation` — живое после E8-T17; `param.foreign = 1`, когда дом регента ≠ управляемому дому. E8 для `foreign = 1` **не** применяет захват сама, а лишь выдаёт запись `RegencyCheck{usurp = 1}` с этим флагом (уточнение E8-T17, #312).
2. Исходы события выбирают **команды E8** (`assign_regent`, `dismiss_regent`, `resolve_succession_dispute`, `grant_land`, `disown`) и штрафы/мнения (`change_unity`, `change_opinion`). Какого «исхода захвата» команда не существует (E8 запретил прямой перенос главенства): если пакет C02 решит, что «регент закрепляется», E8-T17 обязана предоставить для этого команду или оставить исход как «регентство продлено» (решает ревью пакета).
3. Событие — контент пакета C02 (`family.foreign_regent_power_grab`, варианты: совет рода решает, скандал, вмешательство короны (E12; до неё — недоступно)); область — `dynasty`, `speaker = scope:regent`.

| E-9 | Кулдауны: `until` ≥ `kForever`-метка или дата; цепочки: `updated ≥ started` |
| E-10 | `modal_count ≤ границы`, `modal_month` — допустимое значение |
| E-11 | Производные индексы (очередь таймеров по `due`, счётчики по областям) равны пересборке из таблиц (`rebuild_derived_indexes()`) |
| E-12 | `Chosen` без записи `option` невозможен; `Pending`-экземпляр с `defer_until ≠ kNoDate` невозможен |

### 9.4 Сохранение, загрузка, сверка с контентом

- **Схема:** `kStateSchema` +1 — **один подъём в T03** на все разделы 48…57 (первый свободный номер на момент слияния; по состоянию на 2026-11-14 схема 11, E8-T03 возьмёт 12, тогда T03 — следующий); миграция «пусто → пусто» (событий не было); `PRP1`/`PCL1`/`PSV` — без версий (теги 96…109 < 128).
- **Фикстура прежней схемы** (`tests/data/saves/…_v<N-1>.psv`), тест round-trip посреди таймера, ожидающего модального экземпляра, цепочки, `Chosen`-но-неприменённого варианта; корпус порчи (усечения, раздутые счётчики, ключи неизвестных видов) — чек-лист [save-format.md](save-format.md) §7.4.
- **Сверка с контентом** — функция `events::reconcile(world, set)`, вызываемая **загрузчиком (слой `content`/`game`)** после `load_state`, а при горячей перезагрузке — после подмены набора: строки с неизвестным `EventKey` (таймер, кулдаун, очередь, цепочка, история) удаляются с записью `Cancelled`/`Disabled` в историю; экземпляр очереди, у которого число вариантов уменьшилось, отменяется; флаги и переменные не трогаются (литералы без набора ключей не отличить от «нужных»). В обычном режиме набор совпадает по `events_hash` (отказ при несовпадении, ADR-0011 §5), и `reconcile` — холостая; в `--dev` и при перезагрузке она выполняется и меняет состояние детерминированно.
- **Загрузка:** `rebuild_derived_indexes()` строит очередь таймеров по `due` и счётчики; `check_invariants()` непуст — ошибка загрузки; `events.dispatch` продолжает с `incident_cursor` без повторов и пропусков.

### 9.5 Очистка при смерти и вымирании

Конец тика (после обработки действий этого тика): для каждого `Die` из журнала удаляются строки с областью `(character, id)` — флаги, переменные, кулдауны, модификаторы, цепочки, таймеры (`trigger_event` с этой областью), `Pending`/`Deferred`-экземпляры с корнем в ней (запись `Cancelled`), кроме экземпляров событий с `survives_death = yes` (для `on_death` — всегда). Порядок «сначала события `on_death`, потом очистка» позволяет им читать флаги умершего. Вымирание рода (`Extinction`) чистит область `(dynasty, id)`. Провинции не умирают. **Таймер с отложенным действием нельзя вешать на умершего** — событию `on_death` надо перенести продолжение на `dynasty` (компилятор предупреждает `EL218`).

## 10. Показ игроку, ИИ и мост UI

### 10.1 Жизненный цикл экземпляра

```
          ворота (кулдаун/окно/предфильтр/MTTH/триггер) ── прошли ──► fire(событие, корень, области, depth)
                                                                         │ immediate (Run), история Fired, кулдаун/once
        hidden / silent ────────────────────────────────────────────────┤
        получатель ИИ или игрок не управляет ──► ai_choose ─► Chosen ─► resolve (эффекты варианта, after) ─► готово
        получатель — игрок:
           display = notification ──► вариант «по умолчанию» выполняется сразу, запись в журнал (§10.6)
           display = modal ──► Pending (очередь) ──ChooseEventOption──► Chosen ──events.resolve──► готово
                                  │  DeferEvent ──► Deferred ──(defer_until)──► Pending
                                  └─ лимит месяца ──► Demoted (понижено): ai_choose + запись журнала (#496)
```

Экземпляр существует в сейве только в состояниях `Pending`, `Deferred`, `Chosen`; `Resolved` — удаление строки и запись `Fired` (с выбранным вариантом) в историю. Выбор применяется **ровно один раз**: `events.resolve` обрабатывает `Chosen` и удаляет строку в том же вызове; сейв посреди — `Chosen` вернётся в `events.resolve` после загрузки (тест T21).

### 10.2 Очередь игрока (T12)

| Правило | Значение |
|---|---|
| Класс очереди | `critical` (смерть главы, кризис, раскрытие схемы), `important`, `info`; порядок: класс, затем `priority ↓`, затем `instance ↑` |
| Лимит модальных окон | `modal_per_month` (6) или `modal_per_month_crisis` (12) за календарный месяц, счётчик `modal_count` в разделе 48; `critical` в лимит не входит |
| Излишек | событие с `demotable = yes` понижается до уведомления **с ИИ-выбором** и строкой журнала «решение принято без вашего участия» (#496); иначе `Deferred` до начала следующего месяца |
| Отсрочка | `DeferEvent`: до `defer_max` раз по `defer_days`; после — недоступна, причина показывается (#496) |
| Ожидание | `Pending` не истекает: игра на паузе по автопаузе (#496) |
| Размер | `kMaxQueue = 64` на всех игроков; при переполнении новые модальные понижаются |
| Группировка | уведомления с одним `group_key`, получателем и датой сливаются в одну запись журнала с числом (плюрал в шаблоне) |

Влияние множителя частоты (`frequency_permille`, D18): MTTH событий-получателей-игроков умножается/делится на множитель (§12.4); `frequency_applies_to = player` по умолчанию (#496).

### 10.3 Получатель и ИИ-разрешение

**Получатель** — род, который «владеет» экземпляром:

| Область события | Получатель |
|---|---|
| `character` | `character.dynasty` |
| `dynasty` | сам род |
| `province` | `province.owner` (ничья — получателя нет: событие `silent` или отклонено компилятором по `type`) |
| `realm` | все роды из `player_dynasties` (по одному экземпляру на игрока); ИИ-родов нет |

Род — «игрок», если он в списке `player_dynasties` раздела 48 (командой `SetEventSettings`; до E30 список задаёт сценарий, после E30-T03 единственным источником становится `GameSetup`, раздел меняется миграцией — риск §24). У мира без игроков (`simcli`, AI-only прогоны) все решения ИИ.

**ИИ-выбор** (`ai_choose`): доступные варианты (`available` = вычисленный триггер); вес = `max(0, ai_chance)` (аккумулятор, `Run`, **без** разложения); один бросок `bounded(Σ весов)` из `events.ai` (индекс — `EventKey`), если Σ = 0 — первый доступный вариант и **бросок всё равно берётся** (одно извлечение на решение); вариант без доступных — событие отменяется записью `Cancelled`. Функция выбора — точка подмены (`EventChooser`) для утилити-ИИ E17.

### 10.4 Вид события для UI-D07 (`EventView`, мост T19)

Мост (`src/game/event_bridge`) читает `World`, `EventSet` и `Localizer` и строит **готовый снимок без типов `sim`** (форма — `src/ui/include/pat/ui/event_window.hpp`, [ui-design.md](ui-design.md) §12.6):

| Поле `EventView` | Откуда |
|---|---|
| `id` | десятичная запись `instance` (непрозрачна для окна; хозяин по ней шлёт `ChooseEventOption`) |
| `kind` | `type` события → `ui.event.kind.<type>` (`personal`, `family`, `provincial`, `court`, `imperial`, `church`, `military`) |
| `category` | `category` → `ui.event.category.<id>` |
| `title`, `subtitle`, `text`, `quote` | `loc` с подстановкой областей, падежей и пола (§15); `text` — перенос строки как есть |
| `portrait` | файл портрета области `speaker` (E7-T09, пул портретов); пусто — заглушка по категории |
| `speaker`, `speaker_role` | имя в именительном (`{speaker.full}`), строка роли из шаблона `role.<…>` («Глава рода Шереметевых», «Ваш сын») |
| `date` | дата `fired_on` строкой (форматтер `game`) |
| `autopause` | поле экземпляра (бит 0 флагов) |
| `default_option` | индекс варианта с `default = yes` или первого доступного |
| `options[≤ 3]` | `title` — `evt.<id>.opt.<имя>`; `detail` — автострока стоимости/пояснения или `….detail`; **`consequences` — `Explanation` из `Preview` (§13.1)**; `available` — бит `avail_mask`; `unavailable_reason` — готовая строка из `Trace` (§13.3), пусто у доступного |

**Индексы вариантов.** У вариантов с `show_if = no` в `EventView` нет строки, поэтому мост хранит `option_map[i] → индекс программы`; окно возвращает позицию `i`, хозяин переводит её в `ChooseEventOption.option`. Вариантов в окне **не больше `EventWindow::kMaxOptions = 3`**; событие с большим числом вариантов `contentlint` отклоняет (`EL206`) до решения [#498](https://github.com/savinovanton/patriarch/issues/498).

**Очередь.** Мост отдаёт `EventQueueView { modal: [EventView], notifications: [JournalRow], autopause_pending }`; хозяин показывает **первое** модальное; `on_choice(i)` → `submit(ChooseEventOption)`; следующее показывается после снимка, где экземпляр исчез. Решение «показывать ли» и счётчики показа — на стороне хозяина; лимит месяца и класс — в симе (§10.2).

### 10.5 Автопауза

Сим выставляет `autopause_pending` (производное, не сохраняется): есть `Pending` экземпляр с битом 0 **или** запись журнала `critical`, которую игрок ещё не подтвердил. `SimulationRunner` проверяет флаг **на границе тика** и, если игровая настройка «пауза при событиях» включена (опция бегуна, **не** состояние мира и не влияет на реплей), останавливается — окно появляется в тот же снимок, где появился экземпляр, без гонки «ещё N тиков на скорости 5». `EventWindow::on_event_shown` остаётся для хозяина без бегуна (спайк). Пауза и скорость в `World` не входят; реплей воспроизводит только команды (`ChooseEventOption` — внешняя команда на дате ответа). Приоритет `critical`: смерть главы, раскрытие схемы, фаза кризиса ≥ 3 (E12/E14) — по `urgency` события.

### 10.6 Уведомления, журнал, летопись, слухи

- **Журнал** (раздел 57): запись = ключ шаблона/события + три числа; текст строит мост на текущем языке (локализация не хранится). Фильтры UI — по `kind`, `urgency`; подтверждение — `AcknowledgeJournal`.
- **Летопись** (E7-T16, `ChronicleKind::Note`): события пишут в неё через `record_chronicle` с ключом шаблона `chronicle.<тип>`; `param` — стабильный код `0x40000000 | hash30(ключ)` (бит 30 — «происхождение E11»; коды 101…103 — здоровье и совершеннолетие, 200…299 — E8, остальные < 0x40000000 свободны); мост сопоставляет код шаблону по таблице ключей `chronicle.*`. **Дублей с E7 нет:** факты (рождение, смерть, смена главы) по-прежнему пишет мир, события — только «редакторские» записи.
- **Слухи** (#497, рекомендация A): событие с `rumor = yes` у **чужого** рода пишет в журнал игрока `kind = Rumor` с задержкой `rumor_delay_days`, если род в «круге» (`dynasty_relation` ≥ порога данных) или событие `imperial`; модальных окон и автопаузы нет. До решения владельца в M1 живут только флаг в схеме и фильтр-заглушка.

## 11. Цепочки, кулдауны, `once`

### 11.1 `trigger_event`

`trigger_event = { id = estate.audit_followup  months = 3 }`:

- **без задержки** — мгновенный запуск в той же фазе диспетчера: ворота события (триггер) вычисляются в области вызова; глубина = глубина вызывающего + 1; глубина > `max_chain_depth` (8) — запуск пропущен (`ChainDepthExceeded`);
- **с задержкой** — строка раздела 51 `(due = сегодня + срок, seq)`; при наступлении срока диспетчер запускает событие с **той же областью**; `depth` в строке — глубина цепочки; `depth > max_timer_chain` (32) — запуск пропущен;
- ворота цепочечного запуска: триггер события проверяется (если `force = yes` — нет); кулдаун и `once` **не** проверяются (цепочка — продолжение), если не задано `respect_cooldown = yes`;
- область запуска по умолчанию — текущая; `scope = scope:имя` задаёт другую (сохранённую); тип обязан совпасть со `scope` события (`EV102`);
- умершая область → таймер удалён очисткой (§9.5): **EVT-A3** («при смерти флаг удалён, B не срабатывает») выполняется без особой проверки в событии.

### 11.2 Кулдаун, группа, `once`

| Конструкция | Строка в разделе 52 | Проверка ворот |
|---|---|---|
| `cooldown = {…}` | `(ключ события, область, until = сегодня + срок)` при срабатывании | `until > today` → пропуск |
| `cooldown_group = g` | `(ключ группы g \| бит 63, область, until)` — то же значение пишется для группы | любое событие группы на области в паузе |
| `once = scope` | `(ключ события, область, kForever)` | есть строка → пропуск навсегда |
| `once = global` | `(ключ события, realm 0, kForever)` | есть → пропуск у всех |

Откат запуска (`EventAborted`) ставит событию кулдаун `abort_disable_months` на **области запуска** (и счётчик в историю). Просроченные строки (`until ≤ today`) удаляются ленивой очисткой по слоту области (раз в месяц, `is_monthly_slot`), не позже.

### 11.3 Флаги, переменные, модификаторы, цепочки

Флаг/переменная/модификатор/цепочка принадлежат области `(kind, id)`; имя — литерал → `u64`-ключ (D6, D24). Флаги и модификаторы — с датой истечения (`days|months|years`, иначе бессрочно): истекшие снимаются ленивой очисткой по слоту области, а **чтение** (`has_flag`, `has_modifier`) считает истёкшее отсутствующим сразу (чтение ≤ даты). Глобальные флаги и переменные — область `(realm, 0)`. Цепочка (`start_chain`, `set_chain_step`, `end_chain`) — именованная запись «где мы в сюжете»: нужна панели dev, `sim-events`, `contentlint` (граф) и очистке; сама ход цепочки задаётся `trigger_event` и таймерами. Переменные — `Fixed64`; операции `change_variable` с `add|multiply|min|max` насыщаются (§7.3).

### 11.4 Пример EVT-A3

```
event "estate.audit" { … option "ignore" { effect {
    set_flag = { name = audit_pending  months = 6 }
    trigger_event = { id = estate.audit_result  months = 3 }
} } }
event "estate.audit_result" { scope = province  type = provincial …
    trigger { has_flag = audit_pending }       # флаг снят очисткой, если провинция/род исчезли, или истёк
    …
```

## 12. Индекс триггеров и диспетчер

### 12.1 Структуры

Компилятор строит для `EventSet`:

- `by_action[scope_kind][action_code] → vector<EventIdx>` — события в порядке `(priority ↓, EventKey ↑)`, каждое событие — в каждом из своих `on`;
- `pulse[scope_kind][pulse] → vector<EventIdx>` — то же для `monthly_pulse` и др.;
- `windows → vector<EventIdx>` по `window.from` (события с окном дат);
- у события: `prefilter` — список «дешёвых необходимых условий», выделенных из верхнего И `trigger` (диапазон возраста, пол, `is_head_of_dynasty`, `is_player_controlled`, `has_flag`) и проверяемых **без входа в ВМ**; `ppm` (MTTH) и `ppm_mods`; ключи кулдауна/группы/`once`.

### 12.2 Откуда берутся действия

Диспетчер собирает **вхождения** (`Occurrence{действие, корни, `scope:`-области, param}`) в **фиксированном порядке источников**:

1. **Журнал применённых команд тика** — `CommandLog` с индекса начала тика (только применённые записи, `outcome = None`; источник `External`/`Internal` не различается, отклонённые пропускаются): `Birth`, `Die`, `Marry`/`Wed`, `EndMarriage`, `ComeOfAge`, `Conceive`, `GrantTrait`/`RevokeTrait`, `SetDynastyHead`, `SetProvinceOwner`, а также команды E8 (§8.1). Порядок — порядок журнала.
2. **`IncidentLog`** — записи с `seq > incident_cursor` по возрастанию; курсор в разделе 48 сдвигается в конце прохода.
3. **Хвост летописи за сегодня** — по возрастанию `dynasty id`: записи с `date = today`, нужных видов (`HeadChanged`, `Note` 101/102). Стоимость — одно сравнение даты последней записи на род (100 родов).
4. **Календарь и пульсы** — `on_game_start`, `daily_pulse`, `monthly_pulse` и др.: перебор сущностей по слоту (`is_monthly_slot(index, today)`), по возрастанию `id`.

Для `on_province_owner_changed` старый владелец берётся из **производной копии владельцев** провинций (`prev_owner[]`, 400 × `u32`, не сохраняется, не хешируется): обновляется в конце каждого прохода диспетчера, после загрузки равна загруженному миру (команды следующего тика ещё не применены) — поэтому в паре «команда в тике N → вхождение в тике N» значение корректно и после сохранения/загрузки между тиками.

### 12.3 Тик диспетчера (`events.dispatch`, ежедневная система, регистрируется последней)

0. **Таймеры:** все строки раздела 51 с `due ≤ today` по `(due, seq)` — запуск (§11.1).
1. **Окна дат:** события с `window` и `daily_pulse`, у которых `today ∈ [from, to]` (§14).
2. **Действия:** вхождения источников 1…3 в порядке; для каждого вхождения и каждого подписанного события по `by_action[kind][action]`; кандидат `(EventIdx, scope)` встречается **один раз за тик** (дедуп отсортированным вектором).
3. **Пульсы:** для каждого вида области, пульс которого сегодня, — сущности слота по `id ↑`; для каждой — подписанные события по `pulse[kind][…]`.
4. **Ворота** кандидата, по порядку (дешёвое — раньше): кулдаун/`once` (двоичный поиск в разделе 52) → окно дат → `prefilter` → **бросок MTTH/`chance`** (§12.4, один бросок из `events.mtth` на кандидата) → триггер (ВМ). Кандидат, не прошедший, не оставляет следов (кроме расходованного броска).
5. **Пулы и лимит:** прошедшие по сущности группируются по `pool` (§12.5); на сущность за пульс срабатывает не более `fire_cap_per_pulse` (1) пульсовых событий: первое по `(priority ↓, EventKey ↑)` после пулов; остальные пропущены (их бросок потрачен — они бросят снова в следующем пульсе).
6. **Запуск:** `fire` (§10.1) для каждого победителя по порядку; запуски вызывают `trigger_event` (мгновенные — в той же фазе, с учётом глубины).
7. **Очередь и очистка:** `avail_mask` ожидающих экземпляров пересчитывается; истёкшие отсрочки возвращаются; лимит месяца, группировка уведомлений; очистка осиротевших строк (§9.5); обновление `prev_owner[]`; курсоры.

`events.resolve` (регистрируется **перед** `events.dispatch`, обе — после доменных систем) обрабатывает `Chosen`-экземпляры: `Run` программ `effect` выбранного варианта и `after`, коммит буферов, `Resolved`.

### 12.4 MTTH → вероятность в ppm

`mean_time_to_happen = { months = 24 }` на `monthly_pulse`: среднее число пульсов до события при независимых бросках `p` — `1/p`, поэтому

```
p_ppm = clamp( 10^6 × длина_пульса_в_днях / MTTH_в_днях , 1 , 10^6 )     (целое деление с округлением к ближайшему)
        длина пульса: месяц = pulse_month_days (30), квартал = 91, год = pulse_year_days (365); месяц MTTH = 30 дней, год = 365 [предл.]
```

24 мес. на месячном пульсе → `41 667` ppm. `modifier = { factor = 0.5  trigger = … }` **множит MTTH**: `p' = p × 1000 / factor_permille` (множитель — целое ‰, `Fixed` → ‰ усечением), зажим `[1, 10^6]`; несколько модификаторов перемножаются по порядку. Множитель частоты игрока: `p'' = p' × frequency_permille / 1000` (только для получателя-игрока при `frequency_applies_to = player`). **Бросок:** `bounded(10^6) < p_ppm` из потока `events.mtth` события. `chance` (процент аккумулятором) — тот же бросок с `p = chance × 10⁴` ppm; без `mean_time_to_happen` и `chance` — вероятность 1.

**Порядок «бросок → триггер»** (вместо «триггер → бросок») сокращает число входов в ВМ в `1/p` раз (24× при MTTH 24 мес.); распределение то же (события независимы), бросок берётся **у каждого** кандидата, прошедшего дешёвые ворота. Рассуждение «число извлечений зависит от состояния» корректно: оно зависит от `prefilter` и кулдаунов — детерминированных функций состояния; поток **свой у события**, поэтому на чужие события это не влияет.

### 12.5 Пулы

Событие с `pool = p` и прошедшее ворота (включая триггер) на сущности **конкурирует** с другими прошедшими событиями пула `p` на той же сущности: победитель — взвешенный выбор `bounded(Σ weight)` из потока `events.pool` (индекс — ключ пула); вес — `weight` (аккумулятор, `Run`). Проигравшие не срабатывают и кулдаун не получают. Пул — способ «случайно одно из»: поведение для `on_death`/`on_birth` без спама.

### 12.6 Бюджет и план замера (T05, **до** компилятора)

Оценка для M1 (110 событий; подписки: ≈ 40 на `[character][monthly]`, ≈ 15 на `[province][monthly]`, ≈ 10 на `[dynasty][monthly]`, остальное — на действия): в день слот месяца даёт ≈ 180 персонажей, ≈ 14 провинций, ≈ 4 рода → ≈ 7 200 + 210 + 40 кандидатов; кулдаун (двоичный поиск ≈ 40 нс) + бросок (≈ 5 нс) → ≈ 0.35 мс; доля, прошедшая бросок (≈ 1/24), заходит в ВМ (≈ 300 вызовов × ≈ 300 нс ≈ 0.09 мс); источники действий (журнал ≈ 1 000 записей/год, инциденты, хвост летописи) < 0.05 мс. **Итого ≈ 0.5 мс среднее** при бюджете ≤ 1 мс `[предл.]`; пик — месячные дни с рождениями/смертями и цепочками ≈ 2…3 мс. Эта оценка **не подтверждена**: E2-T04 дал 3.26 мс mean / 5.20 мс p99 для 500 определений на плотном потоке (100 месячных пульсов, 400 на действия, дешёвые целочисленные условия) без производителя и fan-out.

T05 обязана: (1) собрать стенд на плотном потоке E2-T04-генератора (5 000 персонажей, 400 провинций, 100 родов; M1 110 событий и «релиз» 550) и записать mean/p99/max **по стадиям** (источники, ворота, ВМ, запуск) в `docs/benchmarks/E11-T05-dispatch.md`; (2) доказать **«индекс = полный обход»** на каждом тике (как E2-T04); (3) при превышении бюджета выбрать из: расширение `prefilter`, кэш «следующая дата, когда сущность может пройти» (колесо), снижение fan-out, пакетирование — **решение или issue с числами до T06** (риск §24).

## 13. Автотултипы

### 13.1 `Preview` → `Explanation`

`explain_option(world, set, instance, option)` (T13, слой `sim`/`game`): запускает программу `effect` варианта в режиме `Preview` над областью экземпляра и получает **`PreviewTree`**: узлы `{код эффекта, аргументы (Fixed/ключи/области), порядок}`, группы «случайно» (ветви с вероятностью, сумма 100 %), «для каждого из N» (с первыми тремя), «если …» (по реальным условиям). Мост `game` переводит дерево в `ui::Explanation` (метка/значение/термы/подвал), используя шаблоны локализации `tooltip.effect.<имя>` с аргументами (`{value}`, `{target}`, `{n:plural(…)}`): «Честь −5», «Запустится событие через 3 мес.», «С вероятностью 30 %: …». Ручных описаний у вариантов нет. Строка `detail` варианта — первый денежный узел («−120 ₽») или текст автора.

### 13.2 Разложения чисел

`ai_chance`, `weight`, MTTH, шансы показываются тем же `Breakdown` (семейство 13000, §8.5): корень — итог; слагаемые — шаги аккумулятора (`add`, `multiply`, ветви `if`) с кодом и значением, подпись шага — из ключа `tooltip.trigger.<имя>`/`tooltip.value.<имя>` либо из исходного текста записи; единицы — по типу значения (пункты, ppm, ‰).

### 13.3 Причина недоступности (`Trace`)

Для варианта с ложным `trigger` ВМ в режиме `Trace` возвращает **первый невыполненный лист** (по порядку записей) с аргументами: «Требуется честь рода от 30 (сейчас 22)» (`tooltip.trigger.<имя>.fail`: `{need}`, `{have}`). Недоступный вариант не скрывается (UI-D07). Неявное условие «хватает денег» даёт «Не хватает 40 ₽».

### 13.4 «Показанное = применённое»

Один вычислитель (ВМ). Тесты T13/T21: (а) для каждого эталонного варианта множество строк `Preview` без `random` совпадает с командами `Run` (по коду эффекта и аргументам); (б) для `random_list` — каждая выданная командой ветвь входит в `Preview`, вероятности ветвей равны долям весов; (в) полнота: для каждой записи каталога есть шаблон `tooltip.*` в RU (`loc-check`, T14); (г) golden строк эталонных тултипов; (д) `Trace` и `Preview` не меняют ни мира, ни состояния событий, ни потоков (хеш до и после).

## 14. Исторические якоря и окна дат

Событие с `window = { from = 1703.05.16  to = 1703.12.31 }` и `anchor = yes` — **исторический якорь** (GDD 08 §8.3): опционален (переключатель `anchors_enabled` в настройках партии, раздел 48), **не принудителен**: срабатывает, только если `trigger` истинен в окне (ход партии мог сделать его невозможным). Диспетчер хранит отсортированный список окон; на шаге 1 (§12.3) вычисляются события, у которых сегодня окно открыто и нет `once`-строки; триггер проверяется **ежедневно** в пределах окна, но только для таких событий (область `realm`, `daily_pulse` допустим только здесь). Окно, которое прошло без срабатывания, — пассивный факт (запись `Disabled` в историю, не ошибка). `history = checked` и `sources = […]` обязательны для якорей в релизе; даты `[проверить]` сверяются с источниками. M1 содержит механизм, но **ни одного живого якоря** (сценарии 2–4 и якоря — M2/E30, GDD 08 §16).

### 15.3 `review` и `history`

Решено владельцем (#294): `review = draft` по умолчанию, `reviewed` ставит **только владелец** (агент не меняет поле на `reviewed`); у исторических событий `history = unchecked|checked`; `contentlint --release` падает на `draft` и `unchecked` (§16). ИИ-черновики допустимы только с ручной редактурой (GDD 08 §10.2 п. 5); поле видно в PR-ревью и в отчёте `simevents`.

## 17. Контент: рамки и процесс

### 17.1 Рамки под возрастной рейтинг 12+ (владелец; [#495](https://github.com/savinovanton/patriarch/issues/495))

Целевой рейтинг VK Play — **12+**. Рекомендация (вариант A, действует до ответа владельца): события — **сдержанная историческая драма**.

- **Насилие и смерть**: называются и подаются через последствия (потеря, траур, приказ, приговор), **без натуралистичных подробностей** (кровь, пытки, увечья, агония); казнь — как решение и факт, не как сцена; болезнь — симптомами и последствиями уровня «лихорадка, слабость», без клинических описаний.
- **Дети**: нет насилия над детьми и их смерти «в кадре» (болезнь ребёнка — факт и забота рода); нет сцен с детьми, имеющих сексуальный подтекст.
- **Сексуальное**: никакой эротики и насилия; браки и внебрачные дети — фактом и последствиями (честь, наследство, слухи).
- **Религия и этнос**: сдержанно (GDD 05 §11); без оскорблений по вере, происхождению, полу; религиозное насилие — текстом, без подробностей.
- **Вещества и самоубийство**: алкоголь и табак — реалии эпохи без побуждения; самоубийство не делается сюжетом выбора.
- **Лексика**: без ненормативной лексики и современных ругательств; архаичная стилизация — умеренная, без анахронизмов.

Реализация — **данные**: `data/lint/content_rating.pd` (список слов и оборотов, `EL215`); ревью владельца поправляет список. Точные критерии возрастной маркировки (ФЗ-436) и правил площадки — `[проверить]` по источникам ([store-pages.md](store-pages.md)); **это не юридическая консультация**, а рамка для авторов.

### 17.2 Тексты

60…120 слов на событие; серьёзная историческая драма, лёгкая стилизация без пародии; варианты — **одна фраза-действие** (последствия показывает автотултип); единый «голос» летописи; нет анахронизмов в словах и реалиях (стоп-слова + чек-лист); ИИ-черновик — с обязательной ручной правкой, `review = draft`; исторические факты `[проверить]` сверяются с источниками. Эталонные события (5–10) пишутся в T21 как образцы тона для пакетов.

### 17.3 Чек-лист автора события

`scope` и `type` выбраны осознанно; триггер дешёвый условиями вперёд; кулдаун/MTTH/`once` заданы; у каждого варианта есть последствие или `neutral`; цепочка закрыта (флаг/таймер/`end_chain`); есть ключи `evt.<id>.*` и `chronicle.*` у записей; `contentlint` без ошибок; `fire_event` в консоли показал окно и тултипы; `sim-events` на сценарии M1 не показал «мёртвого» или «спама»; для исторических — `history`, `sources`.

Общие тесты движка: юнит каждой инструкции, триггера, эффекта (границы, насыщение, деление на 0); повторный запуск → тот же буфер; grep-проверки на `float`, `double`, `unordered_*`, `rand`; фаззинг компилятора (случайные блоки); `check_invariants` на каждом шаге долгих прогонов; ASan/UBSan. Golden T02…T20: ни одно существующее значение не меняется (демо, `dynasty.v1`, экономика, `simcli_m1`).

## 24. Риски

| Риск | Митигация |
|---|---|
| Бюджет диспетчера не подтверждён (E2-T04: 3.26/5.20 мс при 500 определениях) | §12.6: оценка ≈ 0.5 мс; замер T05 **до** T06; порядок «бросок → триггер», `prefilter`, при необходимости колесо следующей даты, issue с числами |

| Коды ведомости `EventIncome`/`EventExpense` меняют хеш счетов | выдаются после E8-T03 (стабильный хеш `kLegacyLedgerLines = 31`) |
| Отклонённые эффекты (цели умерли между запуском и применением) | запись `EffectRejected`, счётчик в `simevents`; события пишутся с учётом (§7.6) |
| Список выбора ИИ `ai_chance` порождает «глупые» решения | M1 — по весам; E17 подменяет `EventChooser`; `EL222` ловит пустые веса |
| Патч контента ломает сейвы с цепочками (`events_hash`) | текст/`review`/`history` в хеш не входят; политика мягкой совместимости правил — E13-T07/M2 |
| Контент ≈ 55 дн. при одном авторе, ИИ-черновики, «усталость от событий» | пакеты по 5–13 событий, `review`, лимиты и класс очереди, `simevents`, рамки §17 |
| Доменные эпики E10/E12/E14/E31 не разложены, пакеты C05…C11 оценены ориентировочно | пакеты помечены; пересмотр при разборе эпиков; движок и C01…C04 от них не зависят |
| Предложенные тексты шаблонов тултипов расходятся с применением | один вычислитель, тест §13.4, `loc-check` |
| Горячая перезагрузка рвёт состояние | `reconcile` после подмены, запись в историю, только dev |
| Рост эпика (моды, шаблонные события, якоря, статы модификаторов) | граница §2 жёсткая; каждый запрос — задача M2/E22 |
