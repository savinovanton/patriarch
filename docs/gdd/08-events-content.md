# GDD 08 — События, правила и контент

> Статус: **черновик v0.1**. Числа помечены **[предл.]**; формат данных — предложение, окончательно подтверждается в эпике E4.
> Покрывает: FR-EVT-1…3, FR-DATA-1, FR-UI-4 (уведомления), FR-UI-5 (локализация), FR-GOAL-3 (летопись), NFR-MOD-1, сценарии (GDD 02 §11), объём и пайплайн контента (E22).
> Эпики: **E4** (данные и контент-пайплайн), **E11** (движок правил), **E22** (контент), **E25** (локализация), **E26** (арт: портреты, иллюстрации), **E30** (сценарии).
> Зависимости: все предыдущие GDD (триггеры, эффекты, области действия берутся из каждой системы), ADR-0001/0002 (детерминизм, компиляция правил, индекс триггеров).

## 1. Назначение

События — это **слой драмы** поверх систем: они превращают числа в историю («Меншиков подкупил писаря», «Сын вернулся из Голландии вольнодумцем»). Контент (события, сценарии, имена, тексты) — **основной объём работы** и главный риск соло-проекта. Система должна давать:

1. **Простой и безопасный способ писать контент** (читаемый формат, проверка ошибок, быстрая перезагрузка).
2. **Эффективное исполнение**: события не должны проверяться «все × все каждый тик» (ADR-0002 P5).
3. **Объяснимость**: игрок видит последствия вариантов в тултипах, автоматически сформированных из правил (FR-UI-3).
4. **Масштабируемый объём**: шаблонные и обобщённые события вместо тысяч уникальных текстов.
5. **Открытость**: формат пригоден для модов (NFR-MOD-1).

## 2. Основные сущности

| Сущность | Что это |
|---|---|
| **Событие (Event)** | Единица повествования: триггер, текст, варианты, последствия |
| **Область (Scope)** | Контекст события: персонаж, род, провинция, империя, Церковь, армия, схема, заговор… |
| **Триггер (Trigger)** | Условие запуска (подписка на «действия» + проверка условий) |
| **Эффект (Effect)** | Изменение состояния (команда внутри симуляции) |
| **Вариант (Option)** | Выбор игрока (или ИИ) с условиями, эффектами, текстом |
| **Цепочка (Chain)** | Связанные события через флаги/таймеры |
| **Сценарий (Scenario)** | Стартовое состояние мира, флаги и «запалы» кризиса |
| **Модификатор (Modifier)** | Временный/постоянный набор эффектов на области |
| **Запись летописи (Chronicle entry)** | Короткая фраза в журнале рода для итогов |

## 3. Типы событий

| Тип | Кому показывается | Пример | Показ |
|---|---|---|---|
| **Личное** | Игроку, если касается главы/членов рода | «Сын требует удел» | Модальное окно с выбором |
| **Родовое** | Игроку (род) | «Спор о наследстве» | Модальное |
| **Провинциальное** | Игроку, если владелец | «Бунт в Курске» | Модальное/уведомление |
| **Придворное** | Игроку, если затрагивает | «Челобитная принята» | Уведомление или модальное |
| **Империи** | Всем (информирование) | «Пётр объявил поход» | Уведомление |
| **Церковное** | Игрок/всем | «Выбор иерарха» | Уведомление/модальное |
| **Военное** | Игрок | «Мятеж в полку» | Модальное |
| **Фоновое (ИИ)** | Только ИИ (игрок видит итог) | «Меншиков женит сына» | Запись в «Слухах»/летописи |
| **Скрытое/сценарное** | Никому | Запал сценария (fuse) | Нет UI |

**Показ:** модальные окна с выбором ограничены бюджетом (см. §9), остальное — уведомления и летопись.

## 4. Язык правил (DSL)

### 4.1 Требования

- читаемый, **текстовый**, с минимумом синтаксиса;
- строгая **типизация областей** (scope): нельзя использовать триггер «провинция» в области «персонаж» без явного перехода;
- компиляция в **AST/байткод** при загрузке (ADR-0002 P5), интернирование идентификаторов (`u32`), без разбора строк на тике;
- **автогенерация тултипов** из дерева правил (по шаблонам локализации);
- версия формата (`format_version`) для миграций и модов.

### 4.2 Структура события (пример, псевдоформат)

> Синтаксис ядра формата (`.pd`) — в [docs/dev/data-format.md](../dev/data-format.md). Пример ниже — псевдоформат: выражения и вызовы (`has_favor(...)`, `20 + (...)`, `+ 20 if ...`) определит E11 как расширение ядра, а `format_version` задаётся один раз на файл.

```
event "court.embezzling_governor" {
    format_version = 1
    scope = character                      # кому принадлежит событие
    tags = [ court, economy ]
    category = court
    image = "engraving.court_ledger"       # из пула иллюстраций

    trigger {                              # когда может запуститься
        is_adult = yes
        has_office = governor
        any_in_scope(province_owned) { corruption > 30 }
    }
    on = monthly_pulse                     # подписка на действие (индекс триггеров)
    mean_time_to_happen = { months = 24 }  # средняя частота при выполнении условий
    cooldown = { months = 36 }
    weight_modifiers = {
        + 20 if trait(greedy)
        - 15 if has_trait(honest)
    }

    title = "evt.court.embezzling_governor.title"
    desc  = "evt.court.embezzling_governor.desc"

    option "evt.court.embezzling_governor.opt_denounce" {
        ai_chance = 20 + (opinion_of(emperor) / 5)
        trigger { has_favor(emperor) >= 30 }
        effect {
            start_scheme = { type = denounce, target = scope:governor }
            change_honor = -5
        }
    }
    option "evt.court.embezzling_governor.opt_hush" {
        ai_chance = 40
        effect {
            pay = 200
            add_secret = { subject = scope:governor, type = embezzlement }
        }
    }
    option "evt.court.embezzling_governor.opt_ignore" {
        ai_chance = 40
        effect { add_modifier = { name = "mod.ignored_theft", duration = { months = 12 } } }
    }
}
```

### 4.3 Скопы (scopes) и переходы

Типы областей: `character`, `dynasty`, `province`, `realm`, `church`, `army`, `scheme`, `plot`, `faith`, `treaty`. Переходы: `owner`, `holder`, `spouse`, `father`, `head`, `capital`, `emperor` и т.д. — только допустимые по схеме. Сохранённые ссылки: `scope:name` (сохранены через `save_scope_as`).

### 4.4 Триггеры (условия)

Группы условий: свойства области (возраст, навыки, черты, честь, `unrest`), отношения (мнение, договоры, родство), состояние империи (фаза, стабильность), события времени (`date >=`), флаги/переменные, случайность (`random_chance`), перечисления (`any_in_scope`, `count_in_scope`, `all_in_scope`). Булевы операторы: `and`, `or`, `not`, `nor`, сравнения.

### 4.5 Эффекты

Эффекты сводятся к **командам симуляции** (ADR-0001): изменение ресурсов, чести, мнений; создание схем; назначение на должность; смерть, болезнь, рождение; изменение настроений провинции; запуск других событий (`trigger_event`), таймеров, флагов; добавление/снятие модификаторов; запись в летопись. Эффекты не могут произвольно менять память — только через разрешённые операции, проверяемые типами.

Управляющие конструкции: `if/else`, `random_list`, `every_in_scope`, `random_in_scope`, `ordered_in_scope` (с сортировкой по детерминированному ключу).

### 4.6 Переменные и флаги

- **Флаги** (булевы), **переменные** (числа `Fixed`), **таймеры** (`on_expire = event_id`) — привязаны к области; имеют срок жизни, автоматически очищаются при удалении области (персонаж умер → его флаги в архив/удаляются).
- Глобальные флаги сценария.

### 4.7 Автоген тултипов

Для эффектов и триггеров определены **шаблоны локализации** (`tooltip.effect.change_honor`, `tooltip.trigger.has_trait`). Игрок видит: «Честь −5; запустится схема “донос”; шанс…», без ручного написания тултипов для каждого варианта. Это обеспечивает FR-UI-3 и снижает количество текстов.

### 4.8 Валидатор (обязательный)

Утилита `content-lint` запускается в CI и локально:
- типизация областей и параметров;
- существование ссылок (черты, должности, события, локализационные ключи, изображения);
- достижимость: нет «мертвых» событий (никто не запускает), нет бесконечных циклов цепочек без выходов;
- проверка вариантов: у модального события ≥ 2 варианта (или явный `single_option`), нет вариантов без эффектов (кроме нейтрального);
- баланс-линты: большие числа, дублирующиеся ключи, пустые тексты;
- совместимость версий формата.

## 5. Триггеры и производительность

### 5.1 Подписки на действия (индекс триггеров)

События подписываются на **действия (on-actions)**, которые генерирует симуляция:

`on_birth`, `on_death`, `on_marriage`, `on_divorce/tonsure`, `on_coming_of_age`, `on_office_assigned/removed`, `on_scheme_started/discovered/completed`, `on_battle_resolved`, `on_siege_end`, `on_crisis_phase_changed`, `on_stability_threshold`, `on_province_unrest_threshold`, `on_faith_changed`, `on_treaty_signed/broken`, `on_succession`, `monthly_pulse`, `yearly_pulse`, `quarterly_pulse` (по областям).

При действии проверяются **только** подписанные события для этой области; «все события × все сущности каждый тик» не выполняется (ADR-0002 P5).

### 5.2 Пульсы и случайные события

- **Пульсы** (`monthly_pulse` и т.п.) идут по очереди со сдвигом `id % 28` (персонажи, провинции) — нагрузка распределена.
- Случайные события используют **средний интервал (MTTH)** и кулдауны: вероятность считается из `mean_time_to_happen` и выбирается детерминированным PRNG потока «events»; не «бросок на каждого каждый день».
- Для событий типа «возможен у многих» используются **выборки**: перед проверкой отбирается случайный поднабор области (напр., 10% персонажей в пульс), чтобы ограничить стоимость.

### 5.3 Бюджет

- Квота единиц работы (WU) на тик для событий [предл.]: ≤ 1 мс среднее, ≤ 3 мс пик.
- Кэш результатов триггеров на текущий день (одинаковые условия для одной области не пересчитываются).
- Сложные условия (`any_in_scope` по большим множествам) требуют **индексов** (по роду, провинции, должности) — заранее строятся при загрузке.

## 6. Показ событий и уведомления

### 6.1 Очередь

- События игрока складываются в **очередь** по приоритету (критичные → важные → информационные).
- **Автопауза** на модальных событиях и на «критичных» уведомлениях (кризис, смерть главы, раскрытие схемы, фаза 3+).
- **Лимит модальных окон** в месяц [предл.: 6 при низкой фазе, 12 при кризисе]; излишек превращается в уведомления/откладывается.
- Группировка однотипных событий («Три провинции сообщают о волнениях»).

### 6.2 Окно события

Заголовок, иллюстрация (гравюра из пула), текст с подстановкой переменных, варианты с краткими последствиями (автотултип), подсказки по шансам. При необходимости — «подумать» (отложить) и «переслать совету».

**Звук (решено):** небольшой набор звуков по категориям событий (двор, война, Церковь, кризис, смерть, финансы) — 5–10 звуков; общая фоновая музыка без отдельных тем под события. **Иллюстрации (решено):** категориальные пулы ~60–100 гравюр, каждое событие берёт изображение из пула по категории и тегам; все ассеты учтены в реестре с источником и лицензией.

### 6.3 Журнал (inbox) и летопись

- **Журнал**: все уведомления за период, фильтры по типам и приоритету.
- **Летопись**: автоматические записи (рождения, браки, смерти, должности, схемы, бои, вехи) — шаблонные фразы; входят в итоговый экран (FR-GOAL-3).

## 7. Тексты и локализация

### 7.1 Ключи и структура

`evt.<id>.title`, `evt.<id>.desc`, `evt.<id>.opt_<name>`, `chronicle.<type>`, `tooltip.<kind>`. Файлы локализации по языкам (RU основной, EN предл.), формат — ICU MessageFormat или собственный (ADR-0001), с поддержкой плюралов и пола.

### 7.2 Склонения и пол в русском

Проблема: имена, фамилии и титулы нужно склонять («передал Ивану Петровичу Меншикову»). Подход:
- **Каталоги имён** — таблицы имён и отчеств с заранее заданными формами (род., дат., вин., твор., предл.) для мужчин и женщин; число имён ≈ 300 [предл.];
- **Фамилии родов** — формы в данных рода (для реальных родов вручную; для вымышленных пользовательских/процедурных — через простые правила или ввод форм);
- **Титулы и должности** — формы в данных;
- в тексте: `{actor|gen}`, `{actor.name|dat}`, `{count|plural:one,few,many}`, `{actor.sex|m:он,f:она}`.
- Для процедурных названий (например, собственная Церковь, GDD 05) формы вводятся/генерируются по ограниченному набору шаблонов; проверка в `loc-check`.

### 7.3 Стиль текста

- Серьёзная историческая драма; лёгкая стилизация под эпоху без архаичного перегруза; без пародии (решено по GDD 05, тон).
- Короткие тексты: **60–120 слов** на событие; варианты — одна фраза-действие + автотултип последствий.
- Нет анахронизмов в словах и реалиях (проверка по списку стоп-слов и чек-листу).
- Религиозное насилие — сдержанно, текстом (GDD 05 §11).
- Единый «голос» летописи.

## 8. Сценарии

### 8.1 Структура файла сценария

```
scenario "boyar_plot" {
    format_version = 1
    start_date = 1703.01.01
    name = "scen.boyar_plot.name", desc = "scen.boyar_plot.desc"
    difficulty_tags = [ intrigue ]
    stability_init = 58, components_init = { ... }
    emperor = "peter_i", agenda_init = [ northern_war, taxes ]
    dynasties = [ ... ]            # присутствующие роды и стартовые данные
    characters = [ ... ]           # вымышленные персонажи родов; Пётр I — исторический якорь
    provinces_ownership = { ... }
    flags = { fuse.boyar_plot = 1 }
    scripted_events = [ ... ]      # запалы и якоря
    goal_presets = [ survive, office, score, throne, sandbox ]
}
```

### 8.2 Четыре сценария

Описаны в GDD 02 §11.1. Для каждого — набор **запалов** (fuse events), 10–20 событий цепочки и 5–10 «подсказок» для лояльного и узурпаторского путей.

### 8.3 Исторические якоря

Опциональны (настройка партии): Петербург, Полтава, Синод, дело царевича, указ о престолонаследии и др. (GDD 02 §11.2). Реализованы как события с **окнами дат**, условиями и несколькими исходами; **не принудительны**: ход игры может сделать их невозможными.

## 9. Баланс частоты и «усталость от событий»

- Целевой темп: **1 значимое решение в 2–4 игровых недели** при обычной скорости [предл.]; в кризисе — чаще.
- Приоритет: события, **связанные с действиями и целями игрока**, выше случайного «фона».
- Группы кулдаунов (`cooldown_group`): однотипные события не повторяются слишком часто.
- Настройка «частота событий» (низкая/средняя/высокая) для игрока.
- Телеметрия: статистика частоты по событиям в AI-only прогонах (§12.3).

## 10. Объём и источники контента

### 10.1 План объёма [предл.]

| Группа | M1 (MVP) | Релиз |
|---|---|---|
| Династия и личная жизнь (GDD 01) | 20 | 80 |
| Престол, кризис, сценарии (GDD 02) | 25 (1 сценарий) | 120 (4 сценария + якоря) |
| Двор и интриги (GDD 04) | 25 | 70 |
| Экономика и владения (GDD 03) | 10 | 50 |
| Религия и Церковь (GDD 05) | 15 | 50 |
| Армия и война (GDD 06) | 5 | 40 |
| Дипломатия (GDD 07) | 5 | 30 |
| Родовые «характерные» события (20 родов × 3–5) | 0–4 | 80 |
| Общие (болезни, погода, внешний мир) | 5 | 30 |
| **Итого** | **~110** | **~550** |

### 10.2 Как снизить трудоёмкость

1. **Шаблонные события**: один шаблон с «слотами» (персонаж, тип, исход) → десятки вариантов (болезнь, ссора, несчастный случай).
2. **Обобщённые события** с областями-параметрами (любой владелец провинции с проблемой X).
3. **Автотултипы** (§4.7) вместо ручных описаний последствий.
4. **Летопись из шаблонов** (одна фраза на тип).
5. **Тексты:** черновики могут готовиться с помощью инструментов (включая ИИ), но всегда **редактируются вручную** и проходят проверку на историческую и стилистическую корректность — в проекте нет «сырого» сгенерированного текста.
6. **Приоритезация:** сначала события, которые двигают системы; «характерные» и флейвор — позже.

### 10.3 Пайплайн контента

```
пишем события (DSL + loc) → content-lint → in-game fire (dev console) → AI-only прогон (частота)
   → ревью исторической корректности → сборка пакета → игровой плейтест
```

## 11. Инструменты (для соло-разработчика)

| Инструмент | Что делает |
|---|---|
| **content-lint** | Статическая проверка (§4.8), запуск в CI |
| **loc-check** | Проверка полноты и склонений локализации |
| **event-graph** | Строит граф цепочек (HTML/Graphviz) для проверки логики |
| **sim-events** | Запускает события на тестовых состояниях, пишет статистику срабатываний |
| **Dev-консоль** | `fire_event`, `set_flag`, `give_trait`, `jump_to_date`, `dump_scope` |
| **Горячая перезагрузка** | Изменение файлов контента → перезагрузка в игре без перезапуска |
| **Подсветка синтаксиса** | Грамматика для редактора (tree-sitter / TextMate) для файлов `.pev` (рабочее расширение) |
| **Экспорт локализации** | Таблицы для сторонних переводчиков (CSV/PO) |

## 12. Сохранения, моды, тесты

### 12.1 Сохранения

В сейв входят: флаги и переменные областей, таймеры и отложенные эффекты (очередь), кулдауны, состояние цепочек, счётчики летописи. Все ссылки — по ID; при загрузке проверяются; устаревшие флаги чистятся (GC).

### 12.2 Моды

- Мод — папка с манифестом (`mod.manifest`: имя, версия формата, зависимости, порядок загрузки).
- Правила слияния: **добавление** новых ID, **замена** по ID (override), **патч** (явные точечные изменения).
- Валидатор применяется к модам; ошибки не роняют игру, а отключают мод с сообщением.
- Гарантия стабильности формата: `format_version`, миграции.

### 12.3 Тесты

- **Юнит-тесты DSL**: разбор, типизация, компиляция, исполнение на тестовых мирах.
- **Интеграционные**: запуск цепочки на тестовом состоянии; проверка эффектов и тултипов.
- **Golden-тесты** для автотултипов и локализации (стабильные строки).
- **AI-only прогоны** (GDD 07 §13.1): метрики частоты событий (медиана, p95), нет «спама» и «мёртвых» событий.
- **Детерминизм**: seed + команды → одинаковая цепочка событий.

## 13. Интерфейс

| Элемент | Содержание |
|---|---|
| **Окно события** | Иллюстрация, текст, варианты + автотултипы, «отложить» |
| **Журнал** | Все уведомления, фильтры, поиск |
| **Летопись** | Хронология рода, экспорт в итоговый экран |
| **Настройки событий** | Частота, исторические якоря (вкл/выкл), автопауза, подсказки |
| **Dev-панель (debug)** | Список активных цепочек, флаги, очередь отложенных эффектов |

## 14. Производительность и данные

- События и сценарии — файлы контента; компиляция при загрузке (≤ 500 мс на ~550 событий [предл.]).
- В памяти события — байткод (десятки КБ); состояние цепочек — разреженное.
- Индексы подписок: массив по `on-action`, внутри — отсортированный список событий по приоритету.
- Бюджеты: событийная обработка ≤ 1 мс на тик среднее; загрузка контента ≤ 1 с; горячая перезагрузка ≤ 300 мс.

## 15. Критерии приёмки

### 15.1 Тесты

- **EVT-A1.** Событие с триггером `has_office = governor` при `monthly_pulse` запускается только у обладателей должности; вероятность соответствует MTTH в долгом прогоне.
- **EVT-A2.** Автотултип варианта отражает все эффекты (честь, схема, деньги) без ручного текста.
- **EVT-A3.** Цепочка: событие A ставит флаг и таймер; через N месяцев запускается B; при смерти персонажа флаг удалён, B не срабатывает.
- **EVT-A4.** Контент с ошибкой типа (триггер провинции в области персонажа) блокирует загрузку в CI и отключается в игре с сообщением (для мода).
- **EVT-A5.** Лимит модальных окон: в одном месяце показано не более лимита, остальные — уведомления.
- **EVT-A6.** Склонение: имя «Иван Петрович Меншиков» в дательном падеже даёт «Ивану Петровичу Меншикову»; плюрал «3 провинции» корректен.
- **EVT-A7.** Горячая перезагрузка меняет текст события без перезапуска; ошибка в файле не роняет игру.
- **EVT-A8.** Детерминизм: два прогона с одним seed дают идентичную последовательность событий и выбор ИИ.

### 15.2 Инварианты

- каждая ссылка в событии (черта, должность, событие, ключ локализации, изображение) существует;
- у модального события ≥ 2 варианта;
- таймеры и флаги принадлежат существующим областям;
- число событий в очереди игрока ограничено; нет бесконечных циклов `trigger_event` (глубина ≤ N).

## 16. Границы MVP (M1)

**Входит:** сценарий **«Боярский заговор»** (решено), движок правил v1 (скопы `character`, `dynasty`, `province`, `realm`; ~40 триггеров, ~40 эффектов), on-actions (рождение, смерть, брак, должность, схема, фаза кризиса, месячный/годовой пульсы), компиляция в байткод, автотултипы, валидатор `content-lint` (основные проверки), локализация RU с склонением имён, очередь и окно события, журнал и летопись (шаблоны), ~110 событий, 1 сценарий, dev-консоль и горячая перезагрузка.

**Не входит в M1 (M2):** сценарии 2–4, исторические якоря, шаблонные события в широком масштабе, моды (манифест, merge), EN-локализация (RU + EN к релизу, решено), экспорт локализации, `event-graph` и `sim-events` в полном объёме, редактор-подсветка (можно раньше, по желанию), родовые флейвор-события.
