# E2-T03 — спайк стоимости тика

`tick_spike` измеряет шесть макетов на данных `stressgen`: армии ежедневно,
схемы еженедельно, экономика 6 сословий × 10 товаров на провинцию, торговля
30 узлов × 10 товаров (для `year60`), ежегодная демография и ежедневный ИИ с WU-квотой.
Это отдельный инструмент; игровой `TaskExecutor`, правила симуляции, PSV1/PSL1
и golden-хеши не меняются. Интеграция телеметрии в `simcli` — E2-T06.

```powershell
cmake --build --preset win-msvc-release --target tick_spike
python tools/tick_spike/run_matrix.py --exe out/win-msvc/tools/tick_spike/Release/tick_spike.exe --output out/E2-T03-results.json
```

По умолчанию матрица: 3 профиля × 2 режима × 4 числа потоков (1/2/4/6) × 2 размера
порции (64/256), по 10 игровых лет и 3 повтора. Порядок 48 вариантов перемешан
фиксированным seed 20261106 для уменьшения зависимости от порядка/нагрева.
Сам seed мира — 7. `--profiles`, `--threads`, `--grains`, `--years`, `--repetitions`
позволяют задать меньшую матрицу. Каталог вывода должен существовать.
Скрипт сохраняет исходные цифры, SHA-256 исходников и проверяет одинаковые конечные
хеши у всех вариантов одного профиля. Он отвергает измерения Debug.

Один вариант (`tick_spike --help` — параметры):

```powershell
.\out\win-msvc\tools\tick_spike\Release\tick_spike.exe --profile year60 --mode stagger --threads 4 --grain 64 --years 10 --repetitions 3
```

`--days` задаёт короткий прогон для проверки инструмента. Сравнение burst/stagger по
конечному хешу корректно на границах полных календарных месяцев; внутри месяца
применена разная доля работы. `--ai-wu` по умолчанию 4096; одна оценка кандидата = 1 WU,
на рассмотрение рода — 32 кандидата. Квота распределяется на главном потоке до dispatch,
остаток работы переносится круговым курсором. Результат не зависит от времени/планирования.

## Что именно измеряется

- `burst`: все месячные сущности обрабатываются 1-го числа.
- `stagger`: эквивалент `is_monthly_slot(id, date)`, `id % 28`, без повторов 29–31-го.
- Оба варианта читают общий снимок прошлого месяца. Результаты на границе месяца
  совпадают; порядок и размер порций не меняют численный результат.
- `threads=1` использует настоящий `SerialExecutor`. Остальные варианты — отдельный
  экспериментальный `PoolExecutor`: N−1 постоянных рабочих потоков + вызывающий поток,
  общий атомарный курсор порций и синхронное завершение batch. Порция одна — без пробуждения
  пула. Он не поддерживает вложенные вызовы, несколько производителей или исключения в body.
- Windows: процесс получает N логических CPU, сначала по одному на физическое ядро,
  затем SMT-потоки, если запрошено больше физических ядер. Пул создаётся после ограничения.
  JSON содержит фактические `affinity_cpus` и число обнаруженных физических ядер
  текущей processor group. На Linux ограничение выбирает логические CPU из allowed mask,
  физическая топология не определяется; на macOS affinity не поддержана.
- Один прогрев 31 день на повтор, затем сброс состояния вне измеряемого интервала.
  Создание мира/пула, копирование начального состояния, хеширование и JSON не входят во время.
- Таймер полного тика включает календарь, снимок месяца, работу подсистем, квоту,
  dispatch и ожидание рабочих потоков. Времена подсистем — wall time, а не сумма CPU-time
  потоков. Стоимость таймеров входит в итог; разница с суммой подсистем — overhead harness.
- RNG демографии выполняется в фиксированном порядке на вызывающем потоке и входит
  в замер демографии. Внутри parallel_for записи только в непересекающиеся диапазоны;
  результаты не упорядочиваются по времени завершения.

JSON содержит mean/p50/p95/p99/max полного тика, такие же значения по старшему
календарному импульсу (daily/weekly/monthly/yearly), активные замеры каждой подсистемы,
её средний вклад на тик и количество работы. Перцентили — nearest rank. Пробы с неактивными
подсистемами не входят в их active-перцентили. На 10 лет × 3 повтора приходится только
30 годовых импульсов, поэтому годовой p99 фактически равен максимуму малой выборки.
RSD считается по средним трёх повторов; `stable=true` только при ≥ 3 повторах и RSD ≤ 5%.
Шумные строки не подходят для гейта регрессий.

## Границы выводов

Формулы и коэффициенты — численные макеты с SoA-раскладкой и заданной кардинальностью,
не игровой баланс. Демография рассчитывает здоровье и маркеры рождений/смертей, без
создания/удаления сущностей и изменения индексов. Нет поиска пути, DSL событий, полного
игрового ИИ, обработки команд и публикации снапшотов UI. Замер не подтверждает бюджет
готовой игры или минимального ПК. Профиль питания/частота CPU не меняются инструментом.
`year1` и `year60` имеют разное число персонажей/нагрузки; их отношение не проверяет
NFR-PERF-3 «при одинаковых размерах мира».

Две целевые проверки: `ctest --preset win-msvc-debug -L tick_spike` — покрытие/повторное
использование пула, равенство Serial/Pool и burst/stagger за полный месяц, WU и корректность
CLI-отчёта. В CI нет порогов времени и полной измерительной матрицы.
