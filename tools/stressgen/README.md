# stressgen — синтетические миры (E2-T02)

Генератор данных для бенчмарков E2. Создаёт валидный `World` напрямую, без прогона
десятков игровых лет. Числа и записи здесь — тестовая нагрузка, а не баланс или
исторический контент игры.

```powershell
cmake --build --preset win-msvc-relwithdebinfo --target stressgen
.\out\win-msvc\tools\stressgen\RelWithDebInfo\stressgen.exe --profile year60x3 --seed 7 --output out/year60x3.psv
```

Получаются два файла:

- `out/year60x3.psv` — обычный сейв (`PSV1`, схема мира 4), читается существующим `simcli --load`;
- `out/year60x3.psv.psl` — реальные синтетические записи армий, схем, договоров и
  событий для бенчмарков. Игровой `World` пока не содержит этих систем.

Мир строится в **режиме династии** (ADR-0006: id персонажей не переиспользуются, очередь
жизненных событий заполнена) и использует колонки E7-T02: имена, ветви (1–3 на род),
портреты, навыки, шкалы, черты, образование детей, плановые смерти, единство и закон наследования
родов; основатели каждого рода (первые двое) состоят в браке, остальные — их дети (E7-T03). Значения случайные в допустимых границах и берутся из отдельного потока ГСЧ
`stress.persons`, поэтому прежние потоки (`stress.characters` и др.) не сдвинуты. Библиотека:
`WorldConfig::dynasty_mode = false` возвращает форму E1 (без режима и новых данных в хеше).

Решение об отдельном файле принято владельцем: [#72](https://github.com/savinovanton/patriarch/issues/72).
Каждый файл пишется через `write_file_atomic`. Заголовок нагрузки содержит хеш мира:
`deserialize_workload` отвергает другой сейв, повреждённый payload, неизвестную версию,
невозможные размеры и неверные ссылки. Сгенерированные файлы храните в `out/`.

## Профили и параметры

| Профиль | Дата (юлианская) | Провинции | Персонажи | Роды | Армии | Схемы | Договоры | События |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| `year1` | 1703-01-01 | 400 | 1500 | 100 | 100 | 20 | 100 | 200 |
| `year60` (по умолчанию) | 1762-01-01 | 400 | 5000 | 100 | 300 | 100 | 400 | 500 |
| `year60x3` | 1762-01-01 | 1200 | 15000 | 300 | 900 | 300 | 1200 | 1500 |

`year60` — снимок 60-го года при старте в 1703-м; `x3` утраивает **все** счётчики
для запаса по нагрузке, не меняя игровых лимитов в ТЗ.

Параметры `--provinces`, `--characters`, `--dynasties`, `--armies`, `--schemes`,
`--contracts`, `--events` переопределяют профиль независимо от порядка аргументов.
`--characters` задаёт **общее** число персонажей, включая остаток при делении по родам.
Поддерживаются `--имя значение` и `--имя=значение`. `--seed` — unsigned 64-bit.
Отрицательные числа, переполнение, неизвестные параметры и невозможные сочетания
(например, схемы без двух персонажей) отвергаются, а не обрезаются молча.

Пределы инструмента: до 1 млн записей каждого типа, до 10 тыс. родов и
`dynasties × provinces ≤ 64 млн` для индекса владений. `--archived N` (E7-T04) добавляет N уже умерших
персонажей (дети основателей родов, умерли в день снимка, ids после живых): так получается архив из
ADR-0006 (≈ 5000 живых + 20000 умерших: `--characters 5000 --archived 20000`).
Каталог вывода должен существовать. В stdout — JSON с точными счётчиками,
`world_hash`, `dataset_hash`, `generation_ms` и размерами файлов.
Время генерации измеряется вокруг построения и проверки данных; сериализация и диск
в него не входят. Время не влияет на seed, состояние или хеши.

## Использование в бенчмарках

Библиотека `patriarch_stress` доступна при `PATRIARCH_BUILD_TOOLS=ON`; её заголовки —
`pat/stress/dataset.hpp`, `pat/stress/world_generator.hpp`. Зависит только от `sim`/`core`.
`generate(config)` создаёт `Dataset { world, workload }`; таблицы нагрузки имеют SoA-раскладку
и типизированные ссылки на сущности мира. Отдельные именованные PRNG-потоки дают
воспроизводимость и разделяют генерацию подсистем.

При чтении сначала загрузите PSV1 через `deserialize_save`, затем передайте полученный
`World` и байты PSL1 в `deserialize_workload`. `compute_hash(dataset)` охватывает мир и
все поля нагрузки. `serialize_workload` требует одинаковой длины колонок каждой таблицы;
для проверки значений полей и ссылок используйте `check_workload`.

Формат `PSL1`, версия 1: magic (4 байта), version/flags (u16/u16), world hash и
payload hash (u64/u64), затем четыре секции с u32 count и записями: армии — 20 байт,
схемы — 16, договоры — 20, события — 16. Все числа little-endian, без padding структур.
Новый формат нагрузки независим от версии игрового сейва E1.

## Проверки

`ctest --preset win-msvc-debug -L stressgen` запускает только две проверки этой задачи:
детерминизм/инварианты/round-trip профилей и CLI → обычный `simcli --load`.
Проверки не устанавливают порог времени на общих CI-раннерах. Критерий ≤ 2 с проверяется
одним Release-замером на целевом ПК для самого большого профиля `year60x3`.

Контрольный замер 2026-11-06: i5-12400F, MSVC 19.44, Release, "year60x3", seed 7 — **8.259 мс** на построение и проверку данных (один запуск, без сериализации и диска).
