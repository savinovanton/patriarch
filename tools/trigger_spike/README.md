# E2-T04 — спайк индекса триггеров

`trigger_spike` сравнивает три потребителя **одного и того же** потока изменений:

- `naive`: полный обход определений и всех сущностей их области;
- `indexed`: подписки `[scope][on-action]` + полный месячный пульс;
- `sampled`: тот же индекс on-actions + 10%-ная выборка области месячного пульса.

```powershell
cmake --build --preset win-msvc-release --target trigger_spike
python tools/trigger_spike/run_matrix.py --exe out/win-msvc/tools/trigger_spike/Release/trigger_spike.exe --output out/E2-T04-results.json
```

Матрица по умолчанию: 1000/5000/15000 персонажей × изменение 1/10/100% области за тик,
400 провинций, ровно 500 определений событий, 365 дней и 3 повтора. Порядок девяти
сочетаний перемешан фиксированным seed 20261106, seed мира — 7. Каждое сочетание в одном
процессе измеряет все три алгоритма, чередуя их порядок по дням/повторам. В JSON —
SHA-256 исходников, timings, RSD, количество просмотренных пар/предикатов/срабатываний
и аудит выборки. Скрипт не принимает Debug-сборки. Каталог вывода должен существовать.

Один вариант:

```powershell
.\out\win-msvc\tools\trigger_spike\Release\trigger_spike.exe --characters 5000 --changed-permille 10 --days 365 --repetitions 3
```

## Семантика сравнения

Используются 500 синтетических **определений**, а не 500 отложенных экземпляров из PSL1.
80% определений подписаны на on-actions, 20% — на месячный пульс; 80% имеют область
персонажа, 20% — провинции. У определения приоритет, маска одного/двух из 16 on-actions
и три предварительно декодированных целочисленных условия по разным атрибутам.
Восемь SoA-атрибутов области инициализируются из данных E1 и синтетических значений.
Это не парсер DSL, реальные игровые триггеры или баланс.

Общий producer меняет заданную долю сущностей в заранее перемешанном порядке и выдаёт
coalesced notification: одна сущность + маска её действий за тик. Часть уведомлений имеет
два бита. Индекс содержит списки EventId по области/on-action, отсортированные по
приоритету. Stamp-массив удаляет повтор кандидата, если определение подписано на оба
действия. Идентификаторы в списке — ранги в общем порядке priority/event.

Месячный пульс распределён по `id % 28`; 29–31-го повторов нет. Полный обход также
использует это условие, календарный день вычислен заранее, без повторного разбора даты
на каждую пару. `indexed` перебирает соответствующий слот напрямую. Для пульсов
`sampled` выбирает область хешем `(seed, month, scope, subject)` перед проверкой событий;
выбор общий для всех pulse-определений данной сущности. Это воспроизводимая 10%-ная
выборка, не реализация MTTH. `--sample-permille 1000` даёт полный пульс.

В каждом типе срабатываний результат сортируется по priority/event и subject.
`naive`/`indexed` обязаны выдавать **одинаковые векторы** action/pulse на каждом тике;
у `sampled` action-вектор тоже обязан совпасть, pulse-вектор должен быть подмножеством.
Расхождение немедленно останавливает эксперимент. Результирующие хеши повторов
также должны совпасть. Повторные отдельные occurrences одного on-action в течение дня,
применение эффектов и общая очередь игрового события здесь не моделируются.

## Что входит во время и аудит

Один процесс закреплён за первым разрешённым логическим CPU (Windows/Linux); глобальные
настройки компьютера не меняются. Перед каждым повтором — 31 день прогрева и сброс
fixture вне измеряемого интервала. Списки кандидатов/срабатываний резервируются заранее.
Измеряется wall time потребителя: routing, dedup, проверки условий и сортировка результата.
Создание входных изменений/уведомлений, построение индекса, сверка/хеширование результатов
и аудит выполняются **вне** времени. Продюсер должен надёжно сообщать все нужные действия;
цена его интеграции и распространение изменений по зависимостям не измерены.

JSON содержит mean/p50/p95/p99/max мкс/тик и нормировку общего времени на 1000 персонажей
при тех же 400 провинциях. RSD — по средним повторов; `stable=true` требует ≥ 3 повтора
и RSD ≤ 5%. Точные выводы об ускорении допустимы по стабильной паре `naive/indexed`.
Ускорение `sampled` не является ускорением эквивалентной семантики.

Аудит (первый повтор) записывает первый полный и первый найденный выборкой pulse-hit
для каждой пары (определение, сущность). Он сообщает долю обнаруженных различных пар,
число не обнаруженных за окно и задержку первого обнаружения в днях. Задержка считается
от первой полной квалификации; условие может исчезнуть и вновь появиться между пульсами.
Это не обещание доставки пропущенного события. Дополнительно сохранено общее число
pulse-hit: оно отличается от числа различных пар, поскольку пара может подходить много месяцев.

Целевые проверки: `ctest --preset win-msvc-debug -L trigger_spike` — полная эквивалентность,
scope/многоадресная подписка без дублей, порядок уведомлений, граница 28/29–31-го,
подмножество выборки, воспроизводимость и реальный CLI-отчёт. Порогов времени в CI нет.
